## §3 划分（尺寸、算法、冻结）

- **尺寸：test 170 局／train 512 局。** 地板核：test ≥150 ✓（170＝地板＋20 局损耗缓冲；170×198＝33,660 根储备，与试点根集 39,600 同量级，合修订 §2 的充足口径）；train ≥200 ✓（512＝试点量级 2.56 倍）。修订 §1「test 尽量大」按功能读法执行：test 的注册职能是 §6.4 仲裁测量根储备，其量级在 150–200 局即饱和；超出部分无已注册消费者，而 train 是换池的 operative 语料，故余量归 train。若按字面最大化（test 482／train 200）将把训练语料压至地板、与换池目的相悖，本件不采。划分在消费（标注／数据生成）开始前可由后续裁定调整，消费开始后冻结。
- **算法（钉死）**：池冻结于事实包快照——682 局以侦察兵五家 matches 清单（09:07–09:35 读数窗）为界，快照后新对局不自动入池。局 id 按字符串升序排序，以 Python `random.Random(20261117)` 洗牌，取前 170 为 test、其余 512 为 train，互斥完备。
- **落字**：DGX 在拉取补仓完成后入仓 v3 消费登记：并集清单、train 清单、test 清单（逐件 md5），并附**回放内容哈希口径**的零重叠报告（对旧 train／旧 test／试点登记／旧 Tier 2 切片／附卷两局／新划分彼此，字面 id 口径已由事实包验过、本报告补内容哈希一口）。策略组读回并以同算法复跑洗牌验合；**登记验合前不得开标**。
