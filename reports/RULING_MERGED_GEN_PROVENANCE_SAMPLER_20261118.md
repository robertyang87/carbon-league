# 裁定：合并代身份与 provenance 引用＋20% 混回采样器口径（策略组，2026-11-18）

- 凭据：工程组可行性确认件 reports/FEASIBILITY_CROSS_CONFIG_MIX_20261118.md（bd36c4fe）——现行链混编 die 于窗口容纳闸＋标量 config 身份闸；最小合规改法＝新增合并 publisher 于标注代层（仅 window 可不同、其余身份逐字段验、来源清单诚实封印），下游零改动。本件裁其待裁两项，随步段草案（04bce102＋修订 4d6627f5）定版一并钉死。

## §1 合并代身份与训练 provenance 引用

- 合并代是**新注册身份**：其 teacher_config_hash 按规范化来源清单计算，语义钉死＝「同标注器 code 身份＋同权重身份、仅窗口不同的源代并集」；不冒用任一源代 config 哈希。
- 训练 provenance 引用须两层齐全：(a) 直接引用合并代身份（合并 generation id＋其 teacher_config_hash）；(b) 展开引用来源清单（逐源代：段号、window、config 哈希、分片数／根数、抽样比与实抽根数）。缺任一层不合规——溯源链须「训练 → 合并代 → 源代」两跳完整。
- 下游身份闸口径随之登记：join_u／prescan／训练对合并代验「合并代注册身份与来源清单封印一致」，不要求与单一源代 config 全等。此非身份硬闸豁免：合并代是显式注册的并集身份（入册新身份），段内分片身份单一纪律不变。

## §2 20% 混回采样器口径

- 抽样单位为根；**按源代逐代独立抽**（每源代各抽其根数 20%，保各窗口占比恒定，不跨代混抽凑比）。
- 确定性硬要求：采样种子在合并代注册时钉死并写入来源清单，同输入＋同种子必同结果；抽样在源代根的稳定序（game, step, seat）上无放回均匀抽，不依赖文件系统顺序。
- 实抽根数＝floor(源代根数 × 0.2)，逐源代在来源清单记实抽数。本段新数据全量不抽（草案 §3.1 已定）。
