## 一、需求

所有者的需求，四条：

1. **击败天梯所有人，拿到第一。** 不是「进前十」或「做出一个强模型」，终点是榜首。
2. **登顶之后持续迭代、保持断层领先。** 第一不是一次性冲刺：对手会反制（M9XJ 线对 Master3s2 就是现成例子），产线必须能长期运转，让领先成为常态而不是运气。
3. **方案必须可落实。** 每一步有唯一执行人、有预注册验收数、有 kill/回退标准；不接受只有方向没有闸门的计划。
4. **约束（所有者既定）**：
   - 上榜提交永远归所有者本人拍板；同日提交不超站点「同作者只留 Top 2」的规则，不浪费名额。
   - 全流程自动化推进：索引/数据集修复、训练停开、自动接档、检查点先行定标、故障诊断恢复、优先级动态调整，由执行侧自行判断，只报里程碑和数字；只有需要所有者本人出手的事（扫码/验证码/机器旁操作/账号重登）和上榜提交等他确认。
   - 测量不许自欺：一切强度判断只认定标数字（固定考官、固定种子），`val` 不是强度；旧规则下测的锚点不得沿用到新规则。
   - 算力很贵：机器不许空转，队列非空＋机器空闲跨一轮即异常；每个大算力动作先有可证伪的验收。

### 2.3 对手是怎么做到的（已验事实）

- **Master3/3s/3s2（同一作者）**：KataGo 式路子——自博弈自造数据（不受现有棋谱上限锁死）、价值头预测终局分差（与天梯按分差计分的规则天然对齐，清算精度即源于此）、决策时搜索（价值叶评估）。Transformer 只是放大器：我们的注意力臂只比非注意力臂强几十到 ~200 分。
- **M9XJ-it260/it320**：不是全面超越 3s2，而是**定点反制**：it320 把局在前 200 步打死（首树第 9.6 步 vs 14.8、现金差 @100 +426 vs +122），绕开 3s2 最强的终局清算（它自己的清算反而更糙：残树 3.6、完美清算 16%）。能快的原因：目标单一、棋谱全公开、自博弈只打一个固定陪练、再加「训练→提交→拿天梯真实反馈→再改」的高转速循环。
- **结论**：单点最强不是护城河，**能持续迭代的循环才是**。3s2 作者现在面对的，正是他当初让全梯面对的问题——我们要建的就是这个循环，并让自己成为转速最快的一方。

## 三、目标

天梯第一；登顶后与第二名的分差保持在安全边际以上（以评分合并标准差计 > 2 SE），且每出现一个新挑战者，其复刻陪练进我方对手池的时延 ≤ 1 天。

## 四、行动方案

### 4.1 总策略：一主两辅

- **主线**：KataGo 式代际自博弈循环（设计见 `reports/katago_architecture_design.md`）：骨干保留现网混合结构，换三个错位点——① 价值头换终局分差分布头（83 分箱＋灭绝概率头＋归属/计数辅助头，目标只认修正后的原版终局分差）；② 搜索换候选臂 PUCT（臂＝解码器候选联合动作：贪心＋关键单位强制偏离＋温度采样；叶＝价值网批量评估；rollout 与手工叶公式删除）；③ 训练主线换代际循环（生成 → 按局存档缓冲 → 候选集蒸馏＋价值分布训练 → 预注册门控晋升 → 历史代际对手池）。
- **辅线一·定点狙击**：it320 三臂定标（spot-28 排队中）出数后，其臂进对手池作固定陪练，并按其行为画像（首树 9.6 步、前 100 步现金差 +426）做前盘速度定点反制训练——它怎么打 3s2，我们怎么打它。负责在主线成熟前抢身位，并给主线供最强陪练样本。
- **辅线二·测量基建**：固定考官对 {Master2 真身， Echo2}＋留出集终验；任何一代的晋升、上榜建议只认这套数。考官与留出集分离，防对着考官过拟合。

### 4.3 第 1 步：Stage 0 证伪（< 1 GPU 日）

- 在现权重上实现分差分布头＋候选臂 PUCT 叶搜索原型；热启动候选（m3s2r1、snipe 最新快照）同场摆擂台定 Stage 1 的 init。
- **验收**：对 E0 三方同场——裸网 −824（基线）→ 叶搜索 ≥ −330 且 ≥ rollout 搜索，worst_ms ≤ 200。
- **Kill**：叶搜索补训后仍输 rollout 搜索 → 设计作废、退回线 B 配方修订，不烧 Stage 1 算力。
- 执行人：作战室执行代理（DGX 或 L20 空窗，先到者）；机器占用与 snipe_n1 的关系按 4.7 默认值。

### 4.4 第 2 步：Stage 1 建产线（约 5 个 L20 日，估计）

- 自博弈基建上线：生成 worker、按局存档缓冲、代际对手池（snipe 池整体迁入作第 0 代）。
- **第一交付物是生成吞吐实测**（设计估 15–40 局/分，瓶颈在 Python 树操作＋引擎步进）：实测前不锁每代局数与代际节奏。
- 短跑一代：**验收**定标 > +412（新锚口径）且留出集同向；价值 MAE 两检查点不降 → kill/先根因。
- 冷启动探针并行：3 GPU 日封顶，只回答「随机初始化自博弈的可行性量级」，不占主线。
- snipe_n1 处置：跑到 it50 快照定标检查点后，按预注册对比决定停并（见 4.7 默认值）。

### 4.5 第 3 步：Stage 2 代际循环＋上榜纪律（常设）

- 每代固定流水：生成 → 训练 → 门控晋升（胜上一代＋考官不回退＋留出终验，三者全过才晋升）→ 定标入档。**连续两代不过门 → 停循环、先根因**，不许硬烧。
- 每代算力量级 3–6 个 L20 日（估计，随 Stage 1 吞吐实测修订）。
- **上榜纪律**：候选代对「现第一名复刻臂」的定标分差留足安全边际（> 2 合并 SE）才向所有者提提交建议；提交由所有者拍板；同日 ≤ 2 个。
- Stage 3（其后）：L 档宽网（≈12–14M 参数）＋部署包，1.5 核/512MiB 约束下计时全项（单步软限 1s/硬限 3s、慢步 ≤3 次且额外 ≤5s、整局 ≤1500s、初始化 ≤20s）为硬闸；不过且回落 S 档仍不过 → 只交裸网蒸馏版。

### 4.6 断层领先机制（登顶后常设运转）

1. **情报**：侦查兵持续收全梯前列新对局；新面孔入册不因名次跌出而移除，触发按历史最好战绩认定（现行规矩不变）。
2. **靶子滚动**：任何挑战者冒头，其语料当天入库、复刻臂排队训练，≤ 1 天进对手池——对手要反制的是一个一直在动的靶。
3. **代际不停**：主线循环常设运行，代际节奏由吞吐实测决定；每代留出集终验防自欺。
4. **反制储备**：每个主要对手保有一份行为画像（种树/残树/分差曲线，与本方案 2.3 同口径），反制训练随时可按画像开工。

### 4.7 三个默认值（所有者未否决即按此执行）

1. **L20 用量**：snipe_n1 跑到 it50 检查点后并入新线作第 0 代素材，L20 转主线为主；其间不双开大任务。
2. **部署形态**：先按带搜索版做 Stage 3 打包与计时验证，计时不过再回落蒸馏裸网版。
3. **DGX/Studio 征用**：两台家用机作自博弈生成 worker；传输走「Studio 从 DGX 拉」（DGX 直推 Studio 的凭据缺口未补，链路一律拉式设计）；文件传输永不走 ZeroTier（只做在线心跳）。

### 4.8 风险登记（设计文档前三）

1. 联合动作搜索可能只有浅层前瞻的命（候选臂质量封顶）——Stage 0 即为低成本证伪点，出数前整条线期望押此一假设。
2. 带搜索生成吞吐不确定性达一个数量级——Stage 1 第一交付物先测吞吐，代际规模随实测修订。
3. 分差分布头是单点故障（搜索叶/门控/重标三处共吃一个价值函数，且分差多峰重尾）——对冲：留出 MAE 逐代门控、灭绝头分离建模、门控集与留出集分离。
