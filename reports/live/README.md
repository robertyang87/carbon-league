# reports/live：进展和调整的直通通道

目的：云端会话能自己看到阶段性进展、及时给出调整，不用每一步都靠用户转发。

## Mac 这边：每 10 分钟推一次（自动）

把下面几个小文件覆盖写到 `reports/live/`，`git pull --rebase` 后提交、推送到 `main`（仓库只用主线 main，旧分支 `cnet2-search-v12` 已退休，勿再往它推）。只推这些文本文件，不推权重和回放。

| 文件 | 内容 |
|---|---|
| `status.md` | 当前时间；各机器在做什么；有没有空转；被触发的停手线；需要云端或用户定的事 |
| `snipe.jsonl` | 自我对弈 `train.jsonl` 的最近 40 行原文，加 `eval.jsonl` 的最近 10 行、`pool_changes` 全文 |
| `exams.md` | 最近 24 小时所有考试的汇总表：候选、对手、局数、分差 ± 标准误、账本各项。新结果加在最上面 |
| `train_bc.md` | DGX 上各个模仿训练的验证集曲线（每轮一行）和每轮用时 |
| `ladder.md` | 前十名的评分和局数；我们各条目的评分、战绩、最近 10 场输局（对手和分差）；回放盘点表 |

提交说明用 `live: <时间>`，方便过滤。没有新内容时不提交。

## 云端这边：定时每小时看一次，另外随叫随到

- 平台的定时唤醒最短一小时一次，云端不绕过这个限制。所以每小时自动看一次；任何时候 Mac 或用户发一句"看一下"，云端立刻拉最新的文件来判断。
- 两次之间的空档靠下面"Mac 可以自己当场执行的判定"顶上，不用等云端。
- 拉分支，读上面五个文件，对照 `plan_master.md` 的判定点。
- 把判断和要调整的地方写进 `reports/live/advice.md`（最新的在最上面，带时间），推送。
- 每条建议写明：依据哪个数、要改什么、怎么改、改完看什么。需要用户拍板的事单独列在最上面一节。
- 只是确认"照常继续"时，也写一行，表示看过了。

## Mac 这边读 `advice.md` 的规矩

- 每次推 `live` 之前先拉分支，看 `advice.md` 有没有新条目。
- 属于计划内的调整（改对手池、改温度、加考试、排队顺序）直接执行，执行后在 `status.md` 里记一行。
- 涉及上榜、删除条目、租机器或释放机器、花钱明显变多的，一律等用户决定。
- 对某条建议有不同看法或发现它和实际记录不符，写在 `status.md` 的"对建议的回应"一节，不要默默不做。

## Mac 可以自己当场执行的判定（不用等云端，做完在 `status.md` 记一行）

这些都是事先定好标准的事，结果一出来就按表做，云端事后复核。

**自我对弈（每一路）**
| 看到 | 立刻做 |
|---|---|
| `kl` 超过停手线（主路 0.20，快路 0.40），或 `clipfrac` 超过 0.25 | 停在最近的检查点，报云端 |
| 自带评测对 Master2 真身比第 0 轮低两百分以上 | 同上 |
| `vl` 连续三轮上升 | 同上 |
| 到了第 5 的倍数轮 | 另存检查点，排 600 对的考试（对 `opp_w3b` 和 Master2 真身），结果追加进 `exams.md` |
| 某个检查点对 `opp_w3b` 达到 +150 以上且超过两倍标准误，对真身不为负 | 立刻补考考官表里其余几类各 200 对，并报用户和云端：这是上榜候选 |
| 两路里一路连续三个检查点都比另一路低一百分以上 | 停掉弱的那一路，算力并给强的 |

**机器**
| 看到 | 立刻做 |
|---|---|
| 考试机空了 | 按垫底队列补活：最新检查点 → 给不显著的结论补到 600 对 → 新考官的定标 |

**仍然必须等用户的**：上榜、删除条目、加租 GPU 或明显多花钱、改总计划里的目标和判定标准。
