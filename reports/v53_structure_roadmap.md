## 1. 模块解剖

`Bot.act` 是一个约 1440 行的单体方法（L624–2061），子系统以内联段落 +
167 项 PARAMS 开关组织。逐模块：

| 模块 | 位置 | 算法本质 | 隐含假设 |
|---|---|---|---|
| 信念记账 Belief | L345–551 | 每格维护操作日志（再生/采集/树吸收/掉落/覆写），回放求当前值；未观测格用对称类初始值 v0∈[0,50] 网格反演（CLS=L313 镜像对称类，全图 63 类），学到一格即点亮全类；还能从**敌方采集员携带增量反推其脚下格碳量**（L437 起 update 尾段）与死亡掉落格重建 | 环境常数（REGEN 1.03 / COLLECT 0.3 / ABS 0.0375）精确已知；初始碳只落在对称类整数 v0 上；未知格只需点估计、无需不确定性表示 |
| 采集 DP | run_dp L793；逐员求解 L1733–1860 | 全图后向归纳：H=12 步、停留计数 S=5 态（pw=0.7^s 持续采集先验）、持货成本 lam=rho×携带、终端 = −lam×距基地距离；逐采集员独立求解，成本层叠加树税/规避/软风险 | 对手不进 DP 的世界模型——敌方只以静态 1–2 步可达性惩罚层出现；多员协调靠贪心近似（见下） |
| 多员协调 | claim L1936–1942；联合消解 L1945–1990 | 采集员按携带降序逐个规划，先行者沿自身 DP 策略路径把格子 claim×0.7 折扣，后行者 DP 看到打折后的收益图；最后按「让步损失」贪心解同格冲突（40 轮） | 顺序贪心 + 乘法折扣 ≈ 联合分配；冲突只需事后消解，不需要事前拍卖/指派 |
| 安全层 | minreach/cnt2 L755–768；惩罚 L1753–1757、L1925 | minreach = 每格「下步可达的最轻敌采集员携带」；携带 c 的我方员进入 minreach≤c 的格：DP 成本层 +0.5(c+30)（再下步 +0.15(c+30)），动作层致命格 −1e6；等重格扣 tie_cost+携带 | 敌人只要「能」打就按会打定价——不看该敌人历史上打不打；风险按最坏情形而非期望损失计价 |
| 树战 | TV L961–979；SV L981–989；任务分配 L1027–1150 | TV[q] = 在 q 种树的边际值：4 邻格当前碳量 × (1−(1−ABS)^L) 饱和吸收曲线（L=min(50,R−1)），按相邻树数分摊，+ steal_w×剥夺敌树份额项，× hold_p 0.8，门槛 TV−价≥12 且 TV≥1.6×价；SV = 存量树剩余寿命吸收值，抢树门槛 (1+steal_w)·SV−20≥8；种植员按 pdisc^距离 贪心领任务 | 用**当前快照** est 算全寿命价值：不建模碳再生流入、不建模敌方反抢/邻位竞种、不计树对敌方采集员的货税收入（也不计对我方员的货税成本，cell_loss_w 只扣种树格本身的碳） |
| 招募/姿态 | L1994–2060；want_p L2041 | 开局模板 open="CP"；种植员目标 early_planters=2，由 block_ok（封锁评估）/全图存量 stock_low/敌树数三个**地图状态量**门控；retire 条件 = 步≥85 且存量<2400 且敌树≤2 且 R≥50；R≤40 停招（岗哨型晚招除外，须预算≥150） | 姿态只需对地图状态反应，不需要对**对手类型**反应；编制配比全场近似恒定即可 |
| 封锁 camp | L1512–1650；flow L614–618 | ≤4 名空载员占敌基地对角格做碰撞封锁；每 eval_T=30 步用 flow()（敌方人均存碳速率 / 我方人均收割速率）评估，两次差评降档、ratio<0.45 判定生效（block_ok）；被撞死多了切 orbit 环绕模式 | 30 步评估窗 + 两次确认的慢回路足够；flow 比值能区分「封锁生效」与「对手自己收割变少」 |
| 猎杀 hunt | L1290–1510；预解表 L19–282 | 三段式：目标无安全格时用 fictitious play（240 轮）解覆盖博弈混合策略；未合围时查三人围猎预解表（半径 5、折扣 0.85、**假设目标 70% 选最优安全格**）；再不行用启发式落位。门槛：目标携带≥150、≥3 名更轻我方员在 R=5 内、耐心 8 步后冷却 15 步 | 猎杀几何只需 3 人/半径 5 的局部博弈；目标行为模型固定；战果统计 hs（eps/boxed/strikes/hits/hit_cargo…）**只写不读**（已 grep 核实：除初始化与自增外无任何读取点）——猎杀开/关、门槛不随战果调整 |
| 守家 siege/gate/run | L880–960、L1830–1920 | 敌空载员蹲我基地 → siege 计数；gate_out 预备冲门格；run 子系统按携带三档学敌方蹲守者的**实际出击率**（run_b 贝叶斯桶），派最轻满载员试探冲门——这是全基座唯一一处「按对手行为定价」的机制，但只用在冲门一件事上 | 蹲守者行为可学；该思想未推广到主安全层（见病灶 P2） |
| 影随 shadow / 岗哨 guard / 游骑 rover | L1650–1730 | ≤2 名空载员贴身跟敌种植员，迫其不敢停步种/抢树；guard 在 sbreak 时追赶蹲守者。注：mark、rovers、probe、p_extra 四个子系统在 base PARAMS 中默认关闭（mark=0、rovers=0、probe_n=0、p_extra=0，L282） | 贴身威慑的期望收益为正（无战果反馈验证） |
| 终局 | endgame L760、L1766–1780 | 硬相位开关：R≤14 时 lam=0、非基地格终端 −1e4、存入按全额携带计分；最后一动（R≤1）基地格豁免自家碰撞消解 | 终局只需最后 14 步切换；R∈[15,50] 区间不需要专门的收割姿态；切换不看比分差 |

**一句话总纲**：v53 是一个「信息层精确、规划层单体贪心、对手层无模型、
姿态层恒定」的系统。它赢 juzi 靠前两项（信念图 + DP，正对应 rl_stage1
§0 说的 juzi 两件武器它都有），输 2400+ 的原因在后两项。

## 2. 病灶清单

### P1 无对手原型识别、无宏观姿态切换（代码直证 + 家族样本）

- 代码：want_p（L2041）与 retire（L1023）的全部触发量是 step、
  block_ok、stock_low、n_en_trees——地图/自身状态，**没有任何对手
  行为特征**（敌编制轨迹、敌存碳速率、敌种/抢树强度）。rho、plant_ratio、
  camp 上限、hunt_min 全场恒定（相位项只有 early/endgame 两档）。
- 家族样本：4 局回放中 v53 家族对 Kailang、安生F9、DSH、无敌四种完全
  不同的对手，步 50–250 编制恒为 8C/2P，分毫不差——姿态是常数不是策略。
- 对照榜首：Alpha 会按对局滑动配比（对 v1 切 9C/1P 轻树模式，存碳
  8188 打平、靠树残差取胜，alpha_analysis §4）。且 Alpha 的三场败局
  恰好全是「对手变速、它没跟上」：6.1 对手步 100 切 10C/0P 纯收割，
  存碳 9360 vs 3992 碾压；6.3 对手步 150 切纯采集，终局 30 步存碳
  566 vs 1029。**变速打法是头部对局的决定变量，而 v53 连变速的
  传感器都没有**（它甚至观测不到「敌种植员归零」这一事件的意义——
  n_en_trees 是观测了，但只喂给 retire 的地图存量条件）。

### P2 安全层按最坏情形定价，不按对手行为定价（代码直证；对 NN 的损失量级为假设 H1）

- 代码：L1753–1757——只要 minreach[z] ≤ c（存在任一更轻或等重敌员
  下步可达 z），成本层无条件 +0.5(c+30)；动作层 L1925 致命格 −1e6。
  触发只看「可达性」，不看该敌员的历史出击倾向。与此同时，基座内部
  明明有现成的行为统计管道：pstay 上下文统计（L620）与 run_b 出击率
  桶（L282 参数 + L1830 起冲门 EV 公式 run_ev×出击率×(2c+30)）——
  **行为定价只被用在「我冲不冲门」，没被用在「我怕不怕这格」**。
- 对照榜首：Alpha 每局死约 34 个单位但死亡丢碳中位仅 57——它按期望
  价值付碰撞税（死的多是空载/轻载单位），不是回避一切碰撞。v53 对
  juzi 死亡丢碳 43 比 Alpha 还保守，这在 juzi 尺上是优点；但当对手是
  8–10 名采集员满图游走的 NN 时，minreach≤c 的格子覆盖全图富碳区，
  0.5(c+30) 的税无处不在——机制上必然表现为「要么让出富格、要么
  提前回存」，即收割吞吐被系统性压低。
- 天梯侧旁证：nocamp 近 30 局对 DeepSeek-NN-light 系列自身得分被压到
  6068–8544，而对规则型对手（gpt6chat-baseline、TJB、Kailang）能打
  9885–13224；对 RL-policy-1 得分 8544（对方 11590，−3046）、对
  RL-light-1 得分 7513（对方 10906，−3393）。
- **H1（待测）**：对 NN 型对手，规避税的期望值损失 ≥300/局。
  验证法见案 C 第一步（惩罚量插桩）。若实测 <150/局，本病灶降级，
  案 C 让位于案 D。

### P3 采集规划是单体分解 + 顺序贪心，非联合优化（代码直证）

- 代码：corder 按携带降序（L1733）逐员跑独立 DP；协调只有 claim×0.7
  折扣（L1936–1942，先行者按**自身** DP 策略路径预扣）与事后冲突
  消解。种植员任务分配同病：按位置排序逐个贪心领任务、taken 集合
  硬排斥（L1027–1150），无指派优化（无拍卖、无匈牙利、无边际重算）。
- 后果（机制推论）：高携带者先占优路，后行者的 DP 在已被折扣的图上
  规划，系统性地把次优员派往次优区；claim 折扣是 0.7 的拍脑袋常数，
  与真实边际重叠损失无关。NN 对手的联合协调是端到端学出来的，这
  正是 rl_stage1 §0 所说 NN 在池内学到、却过不了 juzi 悬崖的东西——
  反过来说，在 v53 这一侧，它是纯规则架构里**可被结构升级直接
  攻击**的一块。
- 量级：未测。验证法见案 E（镜像自博弈测协调税）。

### P4 树战估值是静态边际短视，非战役级（代码直证）

- 代码：TV/SV（L961–989）由当前 est 快照一次性算出：吸收用
  (1−(1−ABS)^L) 饱和曲线作用在**当前格值**上——不含 L 步内的再生
  流入（格子以 1.03/步再生与吸收对冲，真实终值与快照饱和值系统性
  偏差，方向随格值/邻树数变化，未标定）；不含敌方反抢的期望折损
  （只有敌种植员已到 3 格内才生成 guard 任务，L1000–1004）；不含
  树对过往敌采集员的货税收入（树从 8 邻格敌员携带抽 10%/步，这是
  可观的选址价值，TV 完全不计），也不含对我方员的货税成本。
- 对照证据：Alpha 唯一一场「树效率败局」6.2 输在步 50–100 的树
  经济（残差 1331 vs 1919）——头部对局的树战分水岭就在中盘效率
  窗口，而静态边际估值最弱的正是中盘（树多、抢夺频繁、再生流入
  占比最大）。
- 缓解事实：v53 对 juzi 树收入 5819 vs 3197 是碾压级，说明该模块
  对 2000 分以下对手不是短板；病灶只对 2400+ 成立。

### P5 猎杀：预解表的目标模型固定 + 战果统计只写不读（代码直证）

- 预解表假设（L19–20 注释）：3 名猎手、半径 5、目标「70% 选最优
  安全格」、折扣 0.85。猎手数实际可达 5（hs[:5]），几何超出表
  的只有启发式兜底；目标若是 NN（行为分布与 70% 假设无关）或正
  在返航/扎营，表值系统性失真。
- hs 战果账（命中数、缴获碳、放弃数）全程只增不用：hunt_min=150、
  hunt_vmin=0.25、耐心 8 步全是出厂常数。若猎杀对某类对手净亏
  （猎手脱离收割的机会成本 vs 缴获），系统永远学不会关小它。
- 猎物稀缺性：Alpha 死亡丢碳中位 57、单位「死得穷」——对头部 NN，
  携带 ≥150 且落入半径 5 包围圈的目标本就罕见；猎杀更像对中段
  对手的武器。优先级据此排在 A/B/C 之后（见 §3 次级候选）。

### P6 终局与中后盘无比分/相位姿态（代码直证 + 家族样本提示）

- 代码：endgame 是 R≤14 的硬开关（L760）；R∈[15,40] 已停招
  （岗哨晚招须预算 ≥150 且 camp 缺岗，L2010–2016）；R∈[15,50]
  的采集仍用中盘 lam=rho×c 与终端 −lam×距离——没有「收割冲刺」
  相位，也没有按比分差调整风险偏好（落后时不搏、领先时不锁）。
- 对照榜首：Alpha 最后招募中位步 270（R≈30，基地旁短途收割）、
  最后种树步 275.5、最后 30 步存碳 +997——它的 R∈[15,50] 是
  独立经营的一个战场（alpha_analysis §5、§8.4）。
- 家族样本（变体口径，仅作提示）：nocamp 负安生F9 一局，步 200
  时 5931:5896  仍持平，步 250–299 现金增量 +1850 vs 对手 +2458，
  终局滞留 258 vs 0——输点集中在最后 50 步的吞吐差。base 本体对
  juzi 滞留仅 36，说明 base 的终局对 juzi 级对手没问题；对顶级
  收割手是否重演 F9 剧本，属未测假设 H2（验证法并入案 A 的
  相位触发评估）。

### P7 封锁子系统：自适应回路慢、传感器混杂，而家族最优解是直接关掉它（旁证）

- camp 评估窗 eval_T=30、需两次差评才降档——最坏 60+ 步才开始
  缩编；flow() 比值把「敌方被封锁」与「敌方自己转入低收割姿态」
  混在一起（P1 的对手切换会直接污染这个传感器）。
- 市场证据（标注为旁证）：家族天梯最好成绩恰恰是 **nocamp** 变体
  （2030 分）——作者本人在迭代中选择整段关掉 camp，而不是让自家
  评估回路把它调到最优。这提示 camp 的期望价值在头部对局接近
  零或为负，4 个单位槽的机会成本是真金白银。此条不单独成案：
  案 A 的姿态层应把 camp 上限作为按原型可调的一项（对 NN 型
  对手默认 0–2，对基地依赖型对手 4）。

### P8 算力闲置：结构升级的预算不是问题（代码直证）

- base 决策 29–42 ms/步，只用站点预算（1000 ms/步均值、单步
  3 s 上限）的约 3–4%。对照：Godslayer 用 347 ms/步的搜索把
  Alpha 逼到 8234:8159（alpha_analysis §1），其作者证明了深
  搜索在头部对局可换分。H=12 的 DP、半径 5 的猎杀表、30 步的
  camp 评估窗，全都是在「省算力」假设下定的尺寸——这个假设
  在本站不成立。以下各案的算力成本都按此预算评估，不构成约束。

## 3. 结构改动方案

### 案 A：对手原型识别 + 姿态切换层

- **改哪个模块**：新增 Posture 层，插在 act 开头与 PARAMS 之间；
  改动点是招募（L2041 want_p/retire）、树门槛、rho、camp 上限、
  hunt 门槛这五组量的取值来源——从常数改为「基线 + 原型覆盖」。
- **机制**：
  1. 特征（全部来自已有观测/账本，每步更新）：敌编制轨迹
     （C/P 数）、敌种树/抢树累计、敌存碳速率（现成 deliv_hist/
     ec_hist）、敌平均携带（现成 ecar）、敌树存量、敌 camp 在场
     （现成 siege_cnt）、我方/敌方分差估计（cash + 在途 + 树残差）。
  2. 原型集（先四类，步 40–60 起判，置信不足不判）：养树型
     （敌 P≥2 且敌树存量高）、纯收割型（敌 P→0 且 C→10，或敌
     存碳速率陡升 + 敌树存量跌）、封锁型（siege 持续）、均衡型
     （默认/判不出）。
  3. 姿态覆盖表（每类一组增量，幅度刻意保守）：如对纯收割型——
     提前 retire 种植员（不等 stock<2400）、rho 上调（抢先落袋）、
     seize 权重上调（趁其无种植员护树）、hunt_min 下调（其满载
     员更多）；对养树型——plant_ratio 下调抢树口、guard 权重
     上调、camp 上限维持；对封锁型——camp 上限归零换 guard/
     sweeper 优先。
  4. 相位触发（与原型并行）：R≤50 且分差在 ±800 内或落后时
     进「收割冲刺」子姿态（停种、短途招募延至 R≈25、rho 上调），
     回应病灶 P6/H2。
  5. 防抖：最小驻留 20 步、切换需特征连续 5 步同向、每局切换
     次数上限 3。
- **为什么预期有效**：直接对着 Alpha 三场败局的共性机理（变速
  克制静态配比，alpha_analysis §6 共性段）与 P1 的代码事实；
  Alpha 自己的胜势来源之一就是配比滑动（§4）。v53 缺的不是
  执行模块，是把执行模块按对手重新配比的调度层。
- **本地验证设计**：陪练池按原型各备一个——养树型 = shadow_alpha_v2
  （NN 养树）；纯收割型 = 用 base 的参数日程做一个「步 100 全裁
  种植员」脚本变体（switcher，仅作陪练，不动 base 文件）；均衡型
  = juzi + v0.5；封锁型 = base 本体（camp 全开）。每原型对 base
  与对姿态版各打配对 8 局（同 seed 换边），看总分差与分原型
  分差。成功标准：姿态版总分差 ≥ base，且纯收割型对位由负转
  ≥0、养树型对位不回退超过 200。
- **成本与风险**：实现中（分类器 + 覆盖表 + 防抖约 1–2 天，含
  switcher 陪练制作）。风险：误判导致姿态抖动（防抖 + 覆盖
  幅度保守对冲）；本地原型与天梯 NN 的真实原型分布不一致
  （用 m_v53nc 的对手构成校准原型先验；上线后以天梯 10 次
  提交额度内的定位局复核）。

### 案 B：v53 蒸馏 + RL 微调（NN 仲裁层，与 RL 阶段二合流）

- **改哪个模块**：不动 v53 本体；新增 NN 策略，其教师从
  「Alpha 回放影子」换成 **v53 本人**。v53 退居三职：规则盾
  （camp/hunt/siege/endgame 等子系统继续以规则运行，NN 输出
  过盾）、陪练池核心、自博弈语料发生器。
- **机制**：
  1. 蒸馏：v53 自博弈（双边 v53 + 参数扰动版 v53 制造多样性）
     批量产 (信念特征， v53 动作） 对——信念特征直接复用 Belief
     类的 estimate + 对手统计量（这正是 RL 阶段二在建的信念
     通道），BC 训 NN 至能复现 v53 的决策分布。
  2. 微调：PPO，陪练池 = v53 本体 + v53 参数变体群 + shadow_v2
     + 案 A 的 switcher；奖励沿用阶段一的基线归因（已验证管线：
     rollout 约 2800 局/小时、12 轮 45 分钟，rl_stage1 §1）。
  3. 仲裁边界：NN 管采集员移动、种植任务选择、招募三类高频
     决策；camp 岗哨、hunt 出击、gate/run、endgame 相位由规则
     盾以掩码/否决形式约束（Alpha v2 的形态就是「NN + 终局
     一条规则」，我们把盾做厚）。
- **为什么预期有效**：2400+ 的配方就是 BC+自博弈 RL（Alpha
  自述与成绩双证）。阶段一失败的根源不是 RL 本身，而是教师
  与池子太弱：影子对 juzi −14308，池内进步无法迁移（rl_stage1
  §0）。换成 v53 当教师，起点直接站在 +5575（对 juzi）的策略
  上：数据无限（自产）、信息口径与部署完全一致（无回放标签
  错位问题）、且 v53 的信念图解决了阶段一的信息层缺失。NN 要
  学的只剩 v53 学不会的两件事——联合协调（P3）与对手建模
  （P1/P6），这正是梯度法相对规则的比较优势。
- **本地验证设计**：两道闸——蒸馏闸：NN 纯 BC 版对 juzi 配对
  8 局 ≥ +4000（即至少保住教师八成实力）才准进 PPO；提升闸：
  PPO 版对 base_v53 配对 16 局场均 ≥ +500，且对 shadow_v2 /
  switcher / juzi 三把尺不出现单尺 < −1000。检查点选择沿用
  阶段一教训：探针集 ≥8 局配对、禁止 2 局噪声选点。
- **成本与风险**：最高（NN 线主工程，以天计；与 RL 阶段二共用
  基建，不重复造轮子）。风险：PPO 再次出现「池内进步不迁移」
  （以教师强度 + 探针协议对冲；若 PPO 版始终过不了提升闸，
  蒸馏版 NN 本身也可作为「可微调的 v53 等价物」交差，不至于
  全损）；NN 推理须 ≤ 约 25 ms/步（Alpha 实测 9–25 ms 可行，
  P8 预算充足）。

### 案 C：安全层风险定价化（本路线图的首选第一刀）

- **改哪个模块**：安全层（L1753–1757 的 DP 成本层 + L1925 的
  动作层致命罚），以及 pred_next 的消费方（目前只喂 sweeper/
  guard，不喂主 DP）。
- **机制**：
  1. 把 minreach 的「可达即罚」换成**期望损失定价**：对每格 z，
     风险价 = P（敌员真的进 z 出击 | 上下文） × 损失（c + 30 +
     货归敌的摆动项）。P 由在线统计估计——基座已有两套现成
     管道：pstay 上下文统计（扩一个「敌采集员在可击杀情境下
     的实际出击率」键集）与 run_b 的出击率桶（按敌员携带档 /
     我方携带档分桶）。样本不足时先验回退到当前 0.5 的保守价
     （冷启动不冒险）。
  2. 致命 −1e6 只保留给「P 高且 c 大」的格；其余降为期望价。
     终局 R≤6 的现有放宽逻辑保留。
  3. pred_next 的周期预测分布并入 C0/C1 成本层（已知周期 mover
     的下格是确定性信息，现在主 DP 完全不用）。
- **为什么预期有效**：对着 P2 的机制——基座已经在 run 子系统
  里证明了「学出击率再按 EV 冲门」这套打法（run_mode=3 是
  出厂默认），只是没把它推广到每一步的采集决策。Alpha 的
  碰撞经济学（死 34 人/丢碳 57）是期望定价的结果；v53 对
  juzi 的 43 是回避定价的结果。回避在对手稀疏时免费，在
  对手满图时是全图税。风险定价在两种情形下都退化到正确
  的一端（P 高时自动回避、P 低时自动放行）。
- **本地验证设计**：两步——
  1. 插桩测量（在 base 的**副本**上加只读统计，不改决策）：
     每局累计「规避税」= Σ 选中动作上被 avoid 层扣掉的 DP
     值 + 因 −1e6 改道的机会损失近似。对 juzi / shadow_v2 /
     switcher 各 4 局配对，先量出 H1 的真值再决定投入。
  2. 消融评测：avoid 定价三版（原版 0.5 / 半价 0.25 / 风险
     定价版）对 shadow_v2 配对 8 局 + 对 juzi 配对 8 局；
     成功标准：对 shadow_v2 分差改善 ≥ +300 且对 juzi 的
     death_cargo 回退 ≤ +150（守住老本行）。
- **成本与风险**：插桩半天、实现 1–2 天（统计管道现成）。
  风险：NN 对手会**条件性出击**——专挑我方携带峰值时下手，
  历史出击率会低估峰值风险。对冲：P 按我方携带档分桶 +
  高携带档保留硬层下限；这正是 run_b 已按携带分三档的原因，
  照抄即可。

### 次级候选（机制成立、排序靠后）

- **案 D：树战役级估值**。改 TV/SV：吸收项换成含再生流入的
  L 步模拟（est 已有全图，成本可控）、TV 加货税收入项（树位
  × 邻域敌员流量，流量用 ehist 估计）、SV 乘反抢折损（敌种植
  员时距 vs 树回收期）。验证：对 juzi + shadow_v2 配对各 8 局
  看 tree_income 与树残差（终局 cash − 存款 + 成本还原），
  成功线：树残差 +200 且存款不回退。对着 P4 与 Alpha 6.2 的
  步 50–100 窗口。排序在 A 之后：它优化的是 v53 已经最强的
  模块，边际收益不如补短板。
- **案 E：联合指派**。采集员改拍卖式指派（每员对候选富区出
  价 = 自身 DP 边际值，胜者先行且 claim 按真实边际递减而非
  0.7 常数）；种植员任务同理。验证：镜像局（对 base 本体配对）
  最干净——协调税在镜像局里是对称暴露的，看 deposits 与
  claim 重叠率。排序最后：结构收益真实但量级未知，且案 B
  的 NN 一旦成立会内生解决大半。

## 4. 排序与组合路线

**我的排序：C → A → B（执行序）；天花板：B > A > C。**

- 案 C 第一刀：成本最低、第一步是纯测量（半天出 H1 真值，
  证伪也便宜）、且产物（对手出击率统计）同时是案 A 的原型
  特征与案 B 的 NN 输入——三案共用一块地基。
- 案 A 第二：对着已实证的变速克制机理，覆盖表增量与案 C
  正交（C 改「怕不怕」，A 改「打不打树、回不回存」），可并行
  开发、串行验收。
- 案 B 是唯一通往 2400+ 的路（家族 fork 天花板 2080 是
  反证），但它应该**吃 C、A 的成果再开训**：教师换成
  C+A 改进后的 base（更强的教师 = 更高的蒸馏起点），原型
  特征与出击率统计作为 NN 的现成输入通道，姿态覆盖表作为
  RL 的动作空间先验/盾。先 B 后 C/A 等于让 NN 去重新发现
  这两块已知结构，浪费阶段一已经付过的学费。
- 若资源只够一条线：选 B，但把案 C 的插桩测量并进 B 的
  第 0 步——无论走哪条路，先知道规避税有多大。

|---|---|---|

**一句话收尾**：v53 输给 2400+ 不是输在某个参数，而是输在
「没有对手模型、姿态恒定、风险按最坏情形定价」这三件结构
事上。参数线把 2000 分段的地板抬满了；要上 2400，先补
案 C 的地基，再上案 A 的调度层，最后用案 B 把整套结构
蒸馏进 NN——那是榜首自己的来路。
