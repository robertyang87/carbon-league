# S4 camp 裁决报告（2026-11-03）

结构线 S4：复现家族最优的 nocamp 变体、做 camp 回路改造版，与基座三方对位，
回答 camp 到底是**关、修、还是留**。路线图病灶 P7 的本地裁决。

**裁决先行：修。** 以 fork-s4-campfix 为 camp 子系统的集成基线；「关」被本地
配对口径证伪；「原样留」被回路证据否决。边界：本裁决只覆盖 v53 家族内对局，
camp 对 NN 型对手的价值未测（见 §6）。

## 1. camp 在代码里到底是什么

进攻性封锁（base_v53.py，Bot.act 的 campers 段，约 L1540–1680 及联动点）：

- **岗哨**：最多 `campers=4` 名采集员被派驻到两个敌方基地的**对角格**
  （每基地一对对角，按脚下碳少的一对优先——蹲守员必须保持空载）。带碳
  超过 `camp_keep=100` 的蹲守员被释放回正常采集。
- **收益路径三条**：① 截击——敌满载采集员回基地时踏上/贴近岗哨格发生
  碰撞，空载蹲守员（最轻）胜出并缴获全部带碳；② 威慑绕行——敌方 DP
  规划时刻意避开岗哨格，归途变长、存入变慢；③ 蹲守员自身在岗哨格的
  零星采集，及 lone/mark 逻辑下对落单敌采集员的短追。
- **成本**：最多 4/10 个单位槽不事生产；蹲守员会被敌方撞杀/猎杀
  （camp_lost / camp_deaths 记账，补员 30/名）；岗哨格的敌树税与终局
  滞留风险由蹲守员自担。
- **评估回路（病灶所在）**：岗哨就位后每 `eval_T=30` 步评一次，连续两次
  差评（eval_bad≥2）才把 camp_level 降 2 档；判定量本应是窗口专用比值
  `got/expect`（窗口内敌存入 ÷ eff_rate×敌采集员步），但下一行把它
  **覆盖成全局 flow()**——flow 的分母是我方自己的收割速率。被撞杀时的
  放弃判定（kill path）犯了同款错误：算好了 got/expect，又改测 flow()。
  另有 siege_hold 覆盖：敌方蹲我基地达标时强制 camp_level 回满档。

## 4. camp 亏在哪：四条证据

1. **回路慢（代码+实测）**：eval_T=30 × 两次差评 × 「计数器只在岗哨
   就位时前进」，base 降档步实测 68–298（中位 117），对 campfix 时
   8 局**从未降档**。等回路反应过来，局势早已定型。
2. **传感器混杂（代码直证）**：两处判定都把窗口专用比值算好又弃用，
   改测 flow()（见 §1）。实测后果：双边 camp 时双方存入都被压到
   ~4000（互耗均衡），base 的 flow 读数反而「良好」，camp 永远开着；
   而对 nocamp 时 flow 被对方 7532 的强存入流抬高，6/8 局被迫降档——
   flow 实际在测「对手经济强弱」，不是「我的封锁有没有效」。
3. **对自由对手，截击收益趋近于零**：对 nocamp 的 8 局里 base 截击
   仅 5 次共 354 碳（44/局），岗哨格收益 145/局；同期成本是 29.1%
   的采集员步 + 3.6 名蹲守员死亡/局。不设 camp 的对手用 DP 绕开岗哨，
   几乎不白送。camp 的对 nocamp 价值主要剩威慑绕行（其存入 7532
   仍低于 base 的 8160，但树收入也同步低 190，是全经济被岗哨几何
   扭曲的结果，不是单一截击通道）。
4. **截击的肥肉在互蹲局**：双边 camp 时截击跳到 1.9 次、795–997
   碳/局——双方基地口交通拥堵、满载员被堵在岗哨附近才是截击的真实
   来源。camp 本质是**互蹲武器**，不是单边收费站。

## 5. 三维记分卡（作战纲领口径）

- **稳**：campfix 对 base 逐 seed 对合计 {0, −562, +2186, 0}，最差单局
  −1106；nocamp {−2292, −2817, −3760, +1964}，最差单局 −4585。
  campfix 的尾部风险显著小于关 camp 与原版回路。
- **准**：camp 判定量的对账——eff_rate=2.3 与轨迹实测的敌存入率
  2.14–2.40/采集员步吻合（got/expect 本身是标定正确的传感器，是被
  flow() 覆盖才失效）；campfix 修复后判定行为可复核：对 nocamp
  4/4 局在 68–91 步退出 camp（当截击期望只有 ~37/局时退出是对的），
  对 base 8/8 降档但 7/8 在终局前回满（窗口比值随封锁生效而回落，
  自洽）。残余误差源如实标注：got/expect 仍把「对手经济强弱」与
  「封锁效果」部分混杂（双边 camp 时对方存入低有一半是对方自己也
  在蹲），彻底分离需要「无 camp 反事实基线」，属案 A 姿态层课题。
- **狠**：转化数——campfix 截击 15 次/6358 碳（8 局，对 base），
  与 base 同期 15 次/7977 碳同级，修复回路没有削掉 camp 的牙齿；
  抢树/树收入与 base 持平（3938 vs 3865），终局滞留同级（767 vs 868）。

## 6. 裁决与可叠加性

**裁决：修——fork-s4-campfix 进集成线，作为 camp 子系统基线。**

- 「关」（nocamp）本地证伪：对 base −863 且是全经济面的输（存入
  −628、树 −190），不是噪声单点。天梯上 nocamp 变体 2030 分的信号
  与本地结果矛盾，最可能的解释是它的 Edge 来自非家族对手（NN 策略
  会撞岗、终局会被基地口拥堵卡住），**该对手面本轮未测**——若集成线
  之后要对影子 Alpha/DeepSeek 复验 camp，应以 campfix 与 nocamp
  两个版本各打一轮再定 camp 的最终去留，本报告不预判。
- 「留」（base 原回路）否决：慢 + 混杂均已实证；它唯一的意外优点
  （flow 对对手存入流敏感，歪打正着像个粗糙姿态传感器）在 campfix
  的存入比值里保留了信号源，且不再被我方收割速率污染。
- campfix 的均值优势（+203）本身在噪声内，不单独作裁决依据；裁决
  依据是三条合流：不输均值、尾部风险更小、传感器诚实且退出及时。

**可叠加性**：campfix 的改动全部落在 camp 评估块与 eval_T 一个参数，
与 S1（树估值）、S3（终局/猎杀）、案 C（安全定价）无代码交叠；
与 S2/案 A 是接口关系——姿态层应把 `campers` 上限与 r2 阈值组作为
按对手原型可调的旋钮架在 campfix 之上（对 NN 型默认待测、对封锁型
维持、对纯收割型可关），campfix 的降档/回满机器正是姿态层需要的
执行器。nocamp 文件保留作姿态层的「camp=0 档位」实现与对照基线。

## 7. 方法与纪律

- 对位：同 seed 同图换边配对（seeds 1000–1003），RNG 协议与 eval_v53
  一致（random.seed(7919·seed + 104729·side + 31)）；同时在跑对局
  ≤2；两批评测均在 .eval_lock 内执行（计时为共抢参考口径，分差与
  账本不受影响，模拟器对同 seed 确定性）。
- 留痕：20/20 局已录 traces/ 并登记 INDEX「S4 camp 裁决」节，重跑
  终分与评测记录逐局核对 **20/20 = 0.00**。
- 插桩说明：评测期 camp 内部量读自策略模块 _BOT（只读，不改文件）；
  首版截击检测器（按敌方死前格判定）给出假零，已用轨迹动作落点
  口径重测并在本报告中以重测值为准，插桩原值仅在 §3 表注中保留
  对照意义（表中截击行即为重测值）。
- 交付文件：fork_s4_nocamp.py（campers=0，余与 base 逐字一致）、
  fork_s4_campfix.py（eval_T 30→12、两处判定改用 got/expect、
