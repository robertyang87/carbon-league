# 宏观决策训练方案：让模型自己学会"何时招、招什么、何时种"（2026-11-10）

不靠加深搜索。把"每个决定最后赚了多少"直接当训练信号，训练对象只限基地招募和种树这两类决定。

## 0. 起点：量出来的账

工具：`data/unit_ledger.py`（已入库）。从回放逐个单位、逐棵树记实际回报，不做任何估计。

```bash
python3 data/unit_ledger.py ladder DIR NAME          # DIR/rows.json + DIR/rep/
python3 data/unit_ledger.py corpus DIR NAME_PREFIX   # index.json 快照格式，awr_gen 产出的语料也是这个格式
python3 data/unit_ledger.py ladder DIR NAME --json units.jsonl   # 同时导出逐单位、逐棵树的标签
```

Grove1 天梯 142 局（2026-11-10）：

| 每局 | Grove1 全部 | Grove1 对榜首三类 | Master2s | Master2 | M 类 |
|---|---|---|---|---|---|
| **树的生意净值**（树收入 − 树价 − 种植员招募费） | **−607** | **−300** | **+304** | +147 | −111 |
| 种植员数 | 42 | 36 | 29 | 30 | 36 |
| 零产出种植员 | 48% | 45% | 38% | 38% | 39% |
| 每棵种的树：价格 / 吸回 | 49 / 72 | 50 / 76 | 41 / 85 | 50 / 84 | 53 / 80 |

逐单位：

- 车在任何时段招都是净赚：0–50 步 +690，100–150 步 +423，200–240 步 +188，256–276 步 +65，276 步后 +4。
- 种植员在任何时段招，平均都不赚：0–50 步 +1，之后每个 −11 到 −22，75–83% 亏本。
- 种的树按价格：35 以下每棵 +50 以上；35–50 是 +30；50–80 只有 +7；80 以上 −31。我们 42% 的树在价格 50 以上种的，Master2s 只有 20%。
- 250 步以后种的树占我们的 18–21%，每棵只赚 6–18；Master2s 是 9%。

对 Master2s，这一项每局差 600，比开局落后（300–420）和收尾剩货（180–350）都大。

**本方案的总目标**：对榜首三类，树的生意净值从 −300 提到 0 以上；零产出种植员降到 40% 以下；同时入库不降、对方树·步不暴涨。

## 0.1 更正（2026-11-10 晚）：我方的"树的生意净值"不能单独当目标

两套独立实现（上游 TG / RG，本方案的 `MACRO`）、两批对手，结果一致：

| 做法 | 我方树的生意 | 种植员 | 入库 | 配对分差 |
|---|---|---|---|---|
| 限种植员数（中盘 2、终局 1，改招车），云端 60 局 × 2 对手 | +89±51 / +101±42 | −5.9 | +232 / +7 | **−81±105 / −171±125** |
| 限价（中盘 65、终局 35），云端 60 局 × 2 对手 | −5±45 / −11±43 | +1.7 | +114 / +242 | **−139±73 / −53±106** |
| 上游 A 价格闸（八号机 81 局） | −19±48 | | | **−157±62** |
| 上游 B 名额（八号机） | 约 +90 | | | −27±68 |

- 限种植员数确实把我方的账提上去了，入库也没降，分差却不涨。差的那部分在对方身上：我方树少了，对方的树·步多 7–10%，
  对方的车也少被吸。第 5 节写的风险（"对方的损失没有进账"）是实际发生的，量级和我方账面的改善相当。
- 限价没有省下钱：一局拦 11–13 次，只少种 3 棵（24 棵里），其余只是晚种，树收入少 150–200。
- 所以第 0 节的"−300 对 +304"不能直接读成"每局漏 600 分"。Master2s 的树账好，不等于我们少招种植员就能拿到同样的分。

对本方案的影响：
1. 验收一律以配对分差为准。树的账、零产出比例只当诊断，不当目标（A3 第 2 条、B5 第 2 条按此理解）。
2. 阶段 B 的回报用整局最终分差（零和，自带对方的损失）。按我方单位账面逐个改标的做法（B3 表）暂缓；
   要做的话，回报里必须先加上对方的损失。
3. 阶段 A 的旋钮大概率过不了验收第 1 条，按第 5 节止损处理，不叠进探针。

## 1. 原理

现在的网络是模仿出来的：招募和种树一局只有几十次，在训练里几乎没有分量；学到的是"老师通常怎么做"，不是"这么做赚不赚"。搜索只看 3 步，管不到几十步后才兑现的决定。

改法分两步：先用自动搜索找到好的决策规律（阶段 A），再把它连同实际回报一起训进网络（阶段 B）。上榜的模型里不留规则，每步只多一次前向，不增加思考时间。

## 2. 阶段 A：旋钮加自动搜索（今晚，不训练）

### A1. 旋钮

接在 `cnet2_search.py` 的规则层，和 `PLANTER_CASH` 同一位置，用 `base_fix` 登记（搜索和破产保护已经会尊重它）。配置项 `MACRO`，默认关闭，关闭时对局必须和现在逐步相同。

| 旋钮 | 含义 | 搜索范围 |
|---|---|---|
| `PL_CAP_E / _M / _L` | 开局、中盘、终局允许同时在场的种植员数；达到就把"招种植员"改成"招车"，名额满则不招 | 1–5 |
| `PL_T1`、`PL_T2` | 三段的分界步 | 40–80、220–260 |
| `PRICE_M`、`PRICE_L` | 中盘、终局的种树价格上限；高于它，种植员不在空格上停下种树（抢树不受限，固定 20） | 40–100、25–70 |
| `REC_STOP_P` | 之后不再招种植员 | 240–290 |
| `REACT_T` | 种植员上限 += `REACT_T` ×（对方树数 − 我方树数），取整，下限 0 | 0–0.6 |
| `REACT_S` | 价格上限 −= `REACT_S` × 最近 50 步我方被抢的树数 | 0–8 |

后两个是"随对手变化"的部分。没用的话搜索会把它们压到零。

"不在空格上停下种树"的实现：种植员的默认动作是停、脚下可种、价格超限时，改成网络给出的概率最高的移动动作。

### A2. 搜索

新脚本 `data/knob_search.py`：

- **纯网络，不开搜索**（旋钮的效果基本不依赖搜索，这样一局很快）。
- **对手池**，至少三个风格不同的：Master2s 替身、1C-v9、Grove1 自己（纯网络版）。
- **同一批种子**，每组配置和基准（旋钮全关）逐局相减。
- **目标函数**：三个对手里最差的那个配对分差。只在一个对手身上有效的配置会被淘汰。
- **逐级淘汰**：120 组随机配置各 40 局 → 留前 30 组各 120 局 → 留前 6 组各 400 局。
- 每局结果落盘即同步回 Mac（抢占机随时会被回收）。
- 所有对局存成 `awr_gen` 那种语料目录，阶段 B 直接用。

### A3. 验收

1. 前 6 名对三个对手的配对分差都不为负，最差对手上过 2 倍标准误。
2. 对胜出配置跑 `unit_ledger.py corpus`：树的生意净值上升，零产出种植员比例下降。分差涨而账不动，判为噪声。
3. 对方树·步相对基准的增幅不超过 15%（防"省了种植员、放任对方种树"）。
4. 最好的一组加上搜索，按固定预算对 Grove1 头对头 200 局，过 2 倍标准误；对 1C-v9 不为负。
5. 过了就作为探针上榜。上榜后用 `unit_ledger.py ladder` 重算对榜首三类的账。

## 3. 阶段 B：训进模型（1–2 天）

### B1. 数据

- 来源一：阶段 A 的全部对局（上百种旋钮配置，天然带着各种招募和种树方式）。
- 来源二：`awr_gen.py` 扩到整局 300 步，只对基地槽位和"种植员停不停"采样，车走贪心。对手池同 A2。每轮 6000–10000 局。
- 网络输入里已经有随对手变化所需的量，不用改结构：双方车数、种植员数、树数（`sc[5]`–`sc[10]`），种树价格（`sc[11]`），全场树数（`sc[18]`），双方现金。

### B2. 标签

`unit_ledger.py --json` 给出每个招募、每棵树的实际回报。新脚本 `code/macro_labels.py` 把它对回数据集的行：

- 招募：单位出现的前一步、对应基地槽位的那个决定；
- 种树：树出现的前一步、那个种植员"停下"的决定。

### B3. 改标和加权

现有训练器已支持按单位加权（`uw`）和只训解码器（`BC_TRAIN_PREFIX`），不用新写反向传播。

| 决定 | 实际回报 | 处理 |
|---|---|---|
| 招种植员 | 高于同时段均值 | 保留，权重 exp((R − b)/β) |
| 招种植员 | 为负 | 改标：名额未满且同时段招车均值为正 → "招车"；否则 "不招" |
| 招车 | 为正 | 保留，加权 |
| 招车 | 为负（多在 276 步后） | 改标为"不招" |
| 停下种树 | 树的净值为正 | 保留，加权 |
| 停下种树 | 树的净值为负 | 改标为该步网络概率最高的移动动作 |
| 其余所有行 | — | 权重 1，另混入 17 万行原训练集做锚，防止车和其他风格漂移 |

b 取同对手、同 50 步时段的均值；β 按有效样本量不低于 20% 设定（`awr_weights.py` 里已有这套逻辑）。

### B4. 训练

- 从 Grove1 的策略网（`cnet2_b128m2t3`）出发，只训解码器和当前主风格那一行，主干冻结。
- 2 个 epoch，学习率 1e-4，DGX 的 GPU，约 40 分钟。
- 训完按槽核对遗忘：车的一致率相对训练前下降不超过 0.3 个点。

### B5. 验收（每一轮都做）

1. 纯网络对三个对手，同种子减训练前：最差对手不为负。
2. `unit_ledger.py`：树的生意净值、零产出比例、50 以上价格种树的占比，三项都往目标方向走。
3. 对方树·步增幅不超过 15%；我方入库不降。
4. 加搜索，固定预算对 Grove1 头对头 400 局过 2 倍标准误，对 1C-v9 不为负。
5. 限时包量最慢一步，上榜。上榜后重算天梯上的账。

### B6. 迭代

模型变了，它遇到的局面也变了。用新模型重新生成对局、重新打标签、再训，共 2–3 轮。每轮半天。连续两轮账不再动就停。

## 5. 风险和止损

- **对方的损失没有进账。** 种植员压制对方树收入的价值只通过"对方树·步增幅不超过 15%"这条约束间接把关。如果某轮这条被突破，回报里要加一项：抢来的树按对方损失再记一次，对撞掉的对方种植员记 30。
- **本地没有真的 M 类和 Master2s。** 每一轮都要上探针，以天梯上的账为准。
- **止损**：阶段 A 的前 6 名没有一组过验收第 1 条，说明这些旋钮表达不了差距，方案停在这里，不进阶段 B。阶段 B 连续两轮账不动，也停。
