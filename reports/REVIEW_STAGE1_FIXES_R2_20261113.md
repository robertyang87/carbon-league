## 2. R21 / P1：q 锚点报告按局统计，最终 PASS 仍用逐根均值

位置：`code/stage1_teacher_gate.py:646–660`，特别是 **659–660**。代码计算了 hard/soft 的 `game_mean`、局级 t CI 和 cluster bootstrap，但 PASS 读取的仍是 `hard_c["root_mean"]` 与 `soft_c["root_mean"]`。v1.1 §8 声称锚点的点估计与 CI 一律按 game 聚合，未在裁决入口贯彻。

真实 `main` 默认锚点采样器从 50 局、150 根里抽30根，实际来自21局，每局1–3根不等。给多根来源局构造正收益、单根来源局构造负收益，逐根与逐局均值可以异号。本轮执行实际 `_q_scene`、`_anchor_task`、统计函数及 main；仅 teacher/终局回报使用确定性表。所有候选终局 U 均在正常胜局范围内。

| 锚点指标 | 按 root 均值 | 按 game 均值 |
|---|---:|---:|
| 硬动作收益 | +.0506667 | **−.0133333** |
| 软 q 收益 | +.0315339 | **−.0082984** |

软锚点局级 t 区间 `[−.0520901,+.0354933]`，cluster bootstrap `[−.0462340,+.0296372]`。主 Q 指标为正；驱动仍输出 **formal=true、PASS、exit0**。按规范选定的局级估计对象，连锚点点估计大于0都没满足，不应 PASS；本例局级锚点均值≤0、软区间上界≥0，按既定逻辑应为 INDETERMINATE；这不新增 CI 下界>0 的要求，不能仅因区间跨0就否定其他点估计为正的筛查结果。

原 du 的 50局×3根反例已经正确判 FAIL，不能因此推定 q 入口也已修完。修复应让判定使用与协议/报告相同的 game 统计单位，并加上述不等每局根数、均值异号反例；保留正向例，避免把门全部改成拒绝。

## 3. R22 / P2：pilot 文件有 hash，不等于来自合格且匹配的 Stage A

位置：`code/stage1_teacher_gate.py:482–510`、`681–708`、`711–725`。Stage B 对工件的 hash、部分模型/配置身份及局表作了检查；但 Stage A 在自身为诊断运行、缺训练隔离或样本极少时仍会发工件，Stage B 未检查这些来源资格。另有零方差时不更新 sidecar 导致新旧结果配对不完整的问题。

以下三条均执行真实 main、sampler、工件写入及读取流程，**未手改或伪造 artifact**，只替换耗时 workers 为明确结果：

1. **诊断 pilot 升格。** `--max-scenes` 实际截成2根，header 的 `formal=false`；仍生成有效 pilot 工件。后续50局的 Stage B 读取它并正式 **PASS**。少量诊断样本被用于锁正式 N。
2. **未隔离的 pilot 可来自训练集。** Stage A 不提供 ds 清单，用 p0…p9 生成工件。Stage B 提供权威 ds 清单，恰包含 p0…p9；B 自身局表不重叠，仍正式 **PASS**。pilot 的10局实际全在训练清单中，检查没有跨到工件来源。工件也未绑定训练 manifest/version；改变训练身份未被识别为来源变化。
3. **同输出路径复用旧 pilot。** 先以 p0…p9（10局33根）的非零方差写出 `<out>.pilot.json`；再以 p10…p19（另10局33根）的零方差成功结束新 pilot，因 `if cs["sigma_game"]` 不进入工件生成分支，sidecar 原样保留。新主结果有新 run_id、没有新 artifact；sidecar 没有 run_id。随后读取该路径的 B 含 p10…p19 加40个其他局，仍 **PASS**，因为它只与旧 p0…p9 比较。若调用方严格确认新主结果存在并匹配 artifact_id 可避免误用，但当前命令接口没有强制该配对，单靠输出路径不能保证。

这不表示文件完整性 hash 没用，也不是要求密码学防伪。缺口是**完整性、实验资格、来源身份、当前运行配对四件事没有一起核验**。Stage A 的 sha256 是内容自校验，不宜称密码学签名。

修复要求：

- 明确可签发正式 pilot 工件的条件：合格样本量/独立单位、非诊断裁剪、训练隔离已完成、预注册配置。未满足时只出诊断工件，Stage B 拒绝升格。
- 工件绑定 run_id、源结果、完整数据/代码/协议身份与 pilot 局表；Stage B 校验资格，并把 pilot 局表与适用训练 manifest 交叉核对。需要更换训练版本时走明确的重新定标或兼容规则。
- σ=0 应有明确处理：发布本次有效且锁定下限的工件，或发布本次无资格结果并让下游拒绝；不得让旧 sidecar 被当成本次产物。保留旧文件可以，但消费端必须绑定本次预期身份。
- 原因码应说明实际降级原因；当前 N 不足时 `pilot_check` 与追加的诊断字符串可能不一致，也应统一。

证据：[真实 CLI 探针](review_evidence/20261113_stage1_r2/inputs/probe_inputs.py)、[精简结果](review_evidence/20261113_stage1_r2/inputs/results.compact.json)。缺清单、重复 ID、缺 artifact 等已经拒绝的路径也在同一证据中。

## 4. R23 / P2：τ≠1 时只认证行为分布，不能扩大为原训练 q 已获认证

位置：`code/stage1_teacher_gate.py:373–390`、`414–432`、`651–660`。原 q 的 soft gain 仍仅报告；裁决和全臂软锚点使用归一化的 `q**τ`。默认 τ=1 时两者相同，旧反例已关闭；τ≠1 时是两个不同对象。

沿用前轮16臂反例，实际公式产生的原 q 软收益为 **−.01857149**；设 `--behavior-temp 2` 后，行为分布软收益为 **+.00430850**。实际全候选锚点累计执行30×16次续弈，对变温分布得到相同正收益；驱动正式 **PASS**。这证明全臂锚点接线真实存在，也证明它覆盖的是变温后的分布。

**如果实际训练标签也改为 q² 归一化，这个正结果本身没有错。** 当前文档与接口仍区分训练 q、生成行为温度，却没有把最终训练 target 的身份绑定到认证结果，不能将后者的 PASS 转述为“原 q 可用于蒸馏且收益已验证”。这不是默认配置继续触发旧 P1，而是可选配置的目标契约缺口。

修复可二选一：训练原 q 时同时验证原 q 的主收益和真实锚点，行为分布另外认证；或显式冻结训练 target 就是 q^τ，输出/数据/建集消费共同绑定其变换及版本。无论选择哪种，报告结论只覆盖实测的分布。

证据：[method 结果 `raw_training_q_negative_tau2_behavior_positive`](review_evidence/20261113_stage1_r2/method/results.json)。同文件包含 τ=1 原例 FAIL、正向例 PASS、负真实锚点 FAIL，避免只测拒绝路径。

## 5. P3 与准确记账

### 到时 root 的入口契约尚未补齐

`stage0_teacher.py:218–220` 只拒绝灭绝，未拒绝 `step_count>=299`。双席 root299 仍推进300。控制例我方 cash20、对手50，错误额外推进允许对手招募到20，teacher Q=.5，已结束局面的真实 U=.2462502812。docstring209和规范§8“已终局根均抛 ValueError”过宽。正常 gate 应只传0–298，未证明它实际传入此输入，所以保留 P3，**不否定 S01 的合法 root 路由修复**。入口可复用 `_is_terminal`。

### 验收 finite 门仅补到 guard-off

`test_s12_a3_teacher.py:78–81` 已拒绝原来的全 NaN 反例；但90–119行 guard-on 冒烟没有同样的检查。原 main 的受控输出中，guard-off 正常、guard-on 50根全 NaN，仍打印 `50 roots OK` 和 `A3 teacher PASS`。应对所有返回检查 finite、形状、非负和归一化，不仅 guard-off。

A3 空数组及两边相同 errors>0 已拒绝；但1条记录、63条重复记录仍通过，A3_teacher单根也通过。固定 fixture 的数量/唯一身份未锁。上述是验收断言覆盖，不表示 Studio 真实结果含 NaN 或重复样本。

### 功效字段需说明含义

新增 `power_at_locked_for_0.02` 报告的是正收益显著性检验的近似功效，仍未包含样本均值≥.02这道业务门。σ=.1、N=196 时字段约 .7995，真效应恰好 .02 时整个合取条件的放行率近似 .5；σ=.36、N封顶200时约 .1201，确实如实显示不足。建议改名并同时标注复合通过条件的功效和近似假设，不能把 .7995 解读为整道门80%通过率。这属于解释口径，不为其另开 P1。

### 接受用户明确说明的取舍

`--max-scenes` 只有实际截断才降级，help 已对应；未截断不削弱证据。FAIL 退出码1通过；worker 异常非零、原输出保留，成功结果带 run_id并原子发布；空场景指标转null，严格 JSON通过。**保留旧文件本身不算缺陷**，消费者必须核对预期的新身份。R22 指的是 pilot sidecar 没有建立这种强制配对，不能与一般 `--out` 保留混为一谈。

本轮未独立取得作者新一轮 canonical `heads_v2`、20局 fixture 与原始 Studio 输出；仓内 S1 目录仍为 README+4脚本。本轮是自己的确定性探针，不声称作者未运行，也不把其口头结果直接升级为独立复跑。各机已更新的主张仍以作战室实际回执为准，本轮未远程验机。
