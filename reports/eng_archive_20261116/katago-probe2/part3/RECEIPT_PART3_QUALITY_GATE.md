## §3 机制：叶为何从未被调用（源码亲读＋实测）

机制源：重建臂 A′ 内嵌搜索（`part3/work/refit/A/cnet2_search.py`，与包内嵌源逐字节同；B′ 同构，仅叶块不同）。

- `agent()` 入口取 `t0`（第 665 行），`_search(obs, x, y, acts, xo, left, t0, tw)` 接收该 `t0`（第 877 行）。**首层门从 agent 入口计时**，不是从 `_search` 入口计时。
- `left = 299 - step`（第 844 行）；`H = min(cfg["H"]=5, left+1)`（第 1445 行）；哨兵 `if depth < min(cfg["MIN_DEPTH"]=3, H): shallow += 1; return acts`——叶不调用：

| 步 | left | H | sentinel min(3,H) | 叶调用所需 depth |
|---:|---:|---:|---:|---:|
| 298 | 1 | 2 | 2 | ≥2 |
| 297 | 2 | 3 | 3 | ≥3 |
| ≤296 | ≥3 | ≥4 | 3 | ≥3 |

- 深度循环首层门（第 1451 行）：`if last_dt is None and now - t0 > 0.45 * cfg["BUDGET"]: break`。BUDGET=0.7 → **阈值 0.315 秒**。门前的工作：phase-1（Feat 冷观察、pol.act、规则层）＋ `_search` 环前工作（key_units、候选生成 decode_b、对手续招、FastCarbon 分支模拟 load_observation＋step）。门一断即 `depth=1`，哨兵拦住，返回默认动作——叶从未评估。
- 实测逐 call wall（≈入口→首层门时间；门断后仅剩返回动作的微量工作）：**最小 0.4752 秒（A′）/ 0.4839 秒（B′）**，均值约 1.5 秒。**最快的一根也已超过 0.315 秒阈值 1.5 倍**，均值约 5 倍。这不是争用伪影：pilot 串行、无配额、单进程；DGX load 约 20/20 核，单线程进程基本独占一核；即使把全部争用都算掉，最小值仍过线。
- 后层门同样锁死：`now - t0 + PROJ×last_dt > BUDGET`（0.7）与 HARD 墙钟门（0.85）——即使首层侥幸通过，单层耗时量级亦使投影门在 depth 2 前断开（部署持久形态实测即止于 depth 2，见 §4）。
- 翻子规则（第 1490 行后）：`sc = [leaf(...) ...]` 后 `if j != 0 and sc[j] > sc[0] + cfg["MARGIN"]`（MARGIN=825.4）才改子。叶既未调用，MARGIN′ 再宽再严都与 changed 无关——**本关的 changed＝0 与 MARGIN′=825.4 的大小无关**，是首层门的结构性结果。

## §5 为何没有合法喂法能救这关

- **改预算**（抬 BUDGET/HARD）：唯一能让叶跑起来的旋钮（abig 已证），但 BUDGET=0.7 是冻结包 CONF 的一部分；改之即改主体，任务书明禁。
- **持久 agent 喂法**（部署形态）：不在本关注册设计内（本关是 Part 2 口径的新鲜逐根屏）；且闸二 v2 已实测该形态 changed 0/443、depth 恰为 2——叶仅在步 298 根可调用，全集 6,336 根中仅 64 根（约 1%），在 MARGIN=20 下 5 根步 298 亦 0 改子；换 MARGIN′=825.4 只会更严。换喂法不救关，只换失败形态。
- **并行/ pinned / 更安静的机器**：pilot 已是串行无配额的最有利喂法；最小 wall 0.4752 秒仍过 0.315 秒线 1.5 倍——安静机器闭合不了这个缺口。
- **换根集/换步段**：根集是注册的 rootset32；步 298 是 sentinel 最低处，pilot 含 8 根步 298，depth 最高 1——连最低门都过不去。
- **改臂/改底座/改 MARGIN′**：明禁，且与机制无关（§3 末）。

结论：**注册设计内不存在能让叶可证地干预的合法喂法。关无法构造。**
