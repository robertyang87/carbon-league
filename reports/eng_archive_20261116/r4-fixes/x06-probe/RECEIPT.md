# X06 补充探针回执 — join (game, step, seat) 连接在「局表反序＋双席不对称」口径下复验

**结论：PASS。** 现行 `code/k0_join.py`（md5 `78363299a7da04e09724c7327f0d1c86`，与 main 逐字一致的运行副本）在此前验收未覆盖的 r4 X06 严格口径下逐根内容全对：三案（对照／局表反序／sides=[1,0]）各 12/12 根的特征行与单席 oracle 逐字节同哈希、输出 bundle 的 (game, step, seat) 与标注根逐项一致、特征 gid 改写为标注 gid、消费者全门通过。未发现串席/串局，无需开修复单。

## 为什么需要这趟（机制定位）

r4 X06 打的是补件规格本身：builder 同一 (gid, step) 双席共享键、无 seat 列。现行 join 的 seat 归属不靠内容、只靠两条结构假设（`_seat_row_map`）：按 step 序列重置点切段，段序 ↔ build meta 的 `sides` 序；局间靠 games 表**按名**映射。此前验收的 gi 互换实验证明了名字映射，但没有在「标注侧与 build 侧局表互逆」与「段序翻转」下逐根验过内容。本趟即补此验。

## 独立 oracle（不经 join 任何推断）

`build_oracle.py`：对两局各以 `cnet2_build.build_game(sides=[s])` 单席直跑（builder 自家按玩家 p 构造 `Feat(p)`、取 `st[t][p]` 自家观测与动作标号），取 step 206/207/208 的行，按 15 个特征字段拼接计 sha256。seat 身份由 builder 的玩家参数直接给出，不经段切分。

**双席不对称（判别力）**：同 (局， 步) 两席行大幅不同（maps 差 1213–1358 元、hist 系列各差 ~100–170 元、carbon 差 106–138 元；scal 的视角相对通道成对交换、符号通道 ±0.21/±0.03 反号——终局分差 994000 局 ±762、994001 局 ±320）。6 个 (局， 步） 的两席 oracle 哈希互不相同——串席不可能蒙混过关（负对照已实证）。

## 范围与如实注记

- 本趟为只读验证：未改任何仓内文件；三案产物与证据全在本目录（`results.json`、`oracle_index.json`、`roots_table.md`、`build_oracle.py`、`make_build_rev.py`、`make_build_sides10.py`、`run_cases.py`、三套 joined_* 与两套构造 build 代）。
