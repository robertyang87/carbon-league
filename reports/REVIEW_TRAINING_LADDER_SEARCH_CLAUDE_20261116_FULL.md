# 主臂训练、Echo4/Echo5 线上问题、搜索线：review 与进训练的建议（2026-11-16）

> 基准：main@1ec8331a（11-16 12:51）。数据：`reports/ppou2_archive_20261116/`（train.jsonl 至 it=52、league.json）、
> `analysis/echo4|echo5/`（侦查兵 parse2 产物）、`reports/search_dossier/`、各检查点裁决与闭环评估件。
> 标「推断」的没有实测；本机没有 L20 环境，两处代码改动只做了功能与等价性测试，**没有测过提速或强度效果**。

## 0. 结论

1. **主臂是合理的，继续跑。** 锚前移的做法已经连续三段拿到增益；对 Echo4 的候选场 U：it=40 0.5441 → it=45 0.5481 → it=50 0.5739。
2. **线上暴露的头号问题，我读出来的和闭环评估不完全一样。** 评估定的是「产能」。从同一批数据看，产能低是结果；
   分开胜负的是**对抗强度**：工人死亡多的局我们大幅落败，而那 12 个从没赢过的对手在产出上并不比别的对手高，是把我们的产出打下去了。
   这直接影响 adj1 支线按什么属性选压力对手。
3. **搜索线**两轮全筛都是显著负读，且伤害与改子数成正比。整局改子这条路我建议只留一个有明确判据的出口，另给两个更窄的用法。
4. 写了两处可选的训练代码（默认关闭、默认路径逐字不变）：让分对手 `@C<金额>`、每轮对手子集 `--round-opps`。

## 1. 主臂训练：现状与优化

### 1.1 现状读数（train.jsonl it=1–52）

| 段 | 锚 | 系数 | 离锚 kl | 备注 |
|---|---|---|---|---|
| it=4–20 | m3s2r1 | 0.05 | 0.021 → 0.129 | it=20 合并 ΔU +0.047 |
| it=21–25 | m3s2r1 | 0.15 | 0.113 → 0.088 | 被拉回，it=25 +0.049 |
| it=26–37 | m3s2r1 | 0.05 | 0.099 → 0.154 | it=30 +0.089、it=37 +0.092（确认） |
| it=38–52 | ckpt_37 | 0.05 | 0.020 → 0.107 | it=40 对 Echo4 +0.114、it=50 U 0.5739 |

损失项平稳（vl 0.013、gnorm 约 10、clipfrac 0.22、adv_std 0.11），没有发散迹象。对池胜率 0.56 → 0.65。

### 1.2 建议的优化（按我估的性价比排序）

**(1) 采样吞吐被推理 server 的小批次卡住。**
- 实测：server 每 60 秒窗口约 6,200 次前向、`pos_per_fwd` 约 10，`t_fwd` 满窗（两个 server 都在满负荷做 10 个局面一批的前向）。
  server 按（模型，teacher）分组，每步每个模型一次前向；联赛现在 13–20 个模型，所以批次被切碎。
- 「重启后首轮 217–221 gpm、随后掉到 155、再慢慢到 138」不是泄漏：首轮没有并行的更新阶段抢 GPU，之后每轮采样都与上一轮更新重叠。稳态就是 140–155。
- 可做的：
  - `--round-opps K`（本次新增，见 §4）：每轮只从 K 个非 SELF 对手里采样，每步前向次数随之下降、批次变大。长期各对手的局数占比基本不变。
  - 继续加 `RL2_SERVERS` 到 3–4（你们已有「逐级加」的口径）。
  - 清掉不再提供信号的成员（见下一条），模型数少一个就少一类前向。

**(2) 池权重里还有大块「已经赢穿」的对局。** league.json（it=52）：

| 成员 | 先验 | 候选胜率 | it=52 当轮局数 |
|---|---|---|---|
| m3s2r1L（起点） | 1.10 | 0.851 | 475 |
| caragor1_ep19 | 0.275 | 0.861 | 54 |
| m7bsv2g1 | 0.30 | 0.802 | 138 |
| m9xj260wr1 | 0.50 | **0.490** | 304 |
| snap_40 | 1.0 | 0.537 | 724 |
| SELF | 0.5 | 0.499 | 672 |

m3s2r1L 的先验 1.10 是开线时「起点留锚」定的，现在它每轮仍占约 11% 的局、候选对它 85%。建议把它降到与同族一致（0.55 或更低），
并把 `--pfsp` 从 1 提到 2，让份额更向仍有阻力的成员（m9xj260wr1、近期自快照）集中。这是池表改动，按你们的规矩在边界做并备案。

**(3) 考官只剩 Echo4 一个，而且是自家上一代。** 这有两个问题：
- 它量的是「比祖先强多少」。Echo5（it=40）内考对 Echo4 是 +0.114，天梯定版 2482±44 对 Echo4 的 2522±20——差在噪声内，但方向相反，直打 0 局。
  现在没有任何外部读数证明 it=40 之后的增益能转到天梯全场。
- 建议加一个**非本家**考官并用让分去饱和：Master2 真身已退役出考官位，对它 96% 胜率读不出东西，但 `EVAL_OPP_CASH` 可以给它加起始现金，
  调到基线 U 约 0.5 再当尺子。它是规则/搜索型、不是我们这一系的网络，能提供一条独立的可比线。
- Echo5 的天梯样本只有 29 局，值得让它多打，或者下一个候选上榜后专门盯直打。

**(4) 锚前移可以例行化。** 现在离 ckpt_37 的距离 15 轮走了 0.107，按这个斜率 it=58–60 会碰 0.15 上限。
既然每个已确认检查点都有锚资格，不必等碰线：每次 5 轮考确认后就在下一个边界把 `--ref` 切过去（你们已经在对 ckpt_45 这么做）。

**(5) 每轮数据只用了四分之一。** `--dec-frac 0.25 --epochs 1`，更新阶段约 650 秒里有约 300 秒是前置的价值/参考前向。
把 dec-frac 提到 0.5 大约每轮多花 5 分钟、梯度样本翻倍。它会改变每轮步幅，应作为单独一臂对照，不要直接改主臂。

**(6) 两个监视项。** 策略熵从 0.668 升到 0.750，而部署是取最大概率动作；`dlogp` 约 −0.033、clipfrac 0.22 来自「用上一轮策略采的数据」。
两者目前都没造成问题，建议检查点考顺带报一下「采样打」与「贪心打」的差，免得训练目标和部署形态慢慢分叉。

## 2. Echo4／Echo5 线上问题：我读到的和评估的差别

### 2.1 数据事实（`tools/ladder_conflict_split.py`，本次新增；纯描述）

**A. 损失集中在一堵「墙」上。** Echo4 243 局、77 个对手：
- 有 12 个对手（各 ≥3 局）**一局没赢过**：0/63，平均分差 −1563。它们占全部 106 场负局的 59%。
  名单：Master3s、Master3s2、Master3s3z、Master4s、M9XJ-600、M9XJ-630、小肥鱼v5、哈基米 v3pro、K4TacSearch-v6、Fable-BC-v2/v3、Fable-Sym8-v4。
- 对其余对手 180 局，胜率 68%。

**B. 这堵墙的产出并不更高，是我们的产出被打低了。**

| 指标（均值） | 对墙：我方 / 对手 | 对其余：我方 / 对手 |
|---|---|---|
| 第 50 步现金 | 121 / 215 | 196 / 216 |
| 第 100 步现金 | 1130 / 1679 | 1573 / 1587 |
| 终局现金 | 7060 / 8623 | 9359 / 8721 |
| 树步 | 1085 / 1596 | 1402 / 1101 |
| 工人死亡 | **53.9** / 52.8 | **35.2** / 35.9 |
| 招募 | 60.4 / 58.9 | 41.9 / 42.1 |

墙对手自己的现金曲线和普通对手几乎一样（终局 8623 对 8721）；变的是我们这一侧：第 50 步现金就少了 38%，树步少 23%，
工人死亡多 53%。双方死亡数相当，说明是互换式的对抗，而我们为每次互换付的代价更大。

**C. 按我方工人死亡数三等分，胜率差得非常大，两个版本一致。**

| 死亡三分位 | Echo4：死亡 / 胜率 / 分差 | Echo5：死亡 / 胜率 / 分差 |
|---|---|---|
| 低 | 24.9 / 88% / +995 | 25.7 / 89% / +674 |
| 中 | 38.3 / 51% / −5 | 41.0 / 67% / +116 |
| 高 | 55.9 / 32% / −729 | 52.2 / 27% / −228 |

Echo4 逐局相关：我方死亡数与分差 −0.61，第 50 步现金与分差 +0.36。

### 2.2 与闭环评估的关系

- 评估把「模式 2 产能」定为第一病灶，并注意到「负局招募显著高于胜局」，命名为追赶型招募。
  按上表，多出来的招募和多出来的死亡是一一对应的（对墙 60.4 招募 / 53.9 死亡，对其余 41.9 / 35.2）——更像是**补死掉的工人**，不是为追产能而多招。
- 所以我的读法是：高对抗局里我们输；产能低、招募多、货物周转差是它的下游表现。
- **限定**：这是天梯数据的描述，对手身份和对抗强度混在一起，不能证明因果（也可能是强对手恰好都打得凶）。但 Echo5 在完全不同的对手带上复现了同一条梯度。
- 搜索线的定位报告是一个旁证：改子把单位送进会被对手收割的遭遇，`lost_enemy` 是 10 倍通道。我们这一系的策略在「遭遇」上的定价本来就弱。

### 2.3 进训练的建议

**(1) adj1 支线的压力对手，按「对抗强度」选，不只按产出选。**
修正案现在的属性验真是「树步产出 ≥ 候选 ×1.15」和「现金/树步 ≥ 候选 ×1.20」。按 §2.1-B，墙对手在这两项上未必达标，
而它们的共同点是把对局拖进高死亡。建议在签名测量里加两列并作为入选依据之一：**每局造成的对方工人死亡数**、**前 100 步的死亡数**。
这只需要在 `signature_measure.py` 的读数里加字段。

**(2) 先量一个数：训练对局里的死亡分布。** 天梯上低/中/高三档是 25/38/56。如果训练采样里对池成员的对局基本都落在 25 一带，
那就坐实了「池里没人这么打」。这个数我没有，sidecar 加一列就能出。

**(3) 可以进池的非本家对手现在有两个。** Master2 真身和 Echo2 都已退出考官位，「一员一职」不再拦它们入池。
Master2 真身是规则/搜索型，终局清算也干净（作对手时残树约 2–2.7），rollout 本来就支持 bot 文件作对手。
它对候选已经很弱，所以要配合下一条的让分才有压力。

**(4) 让分对手（本次新增 `@C<金额>`，见 §4）。** 对墙的局里我们第 50 步就落后约 95 现金、第 100 步落后约 550。
池里的替身给不出这种「开局被压」的局面。让分是一个代理：让对手带起始现金优势开局，候选就会经常处在落后状态。
- 建议起步：给 2–3 个仍有阻力的成员（m9xj260wr1、最新自快照）和 Master2 真身各挂一个 `@C60`–`@C120` 变体，合计份额 15–20%。
- 变体是独立的联赛成员，有自己的先验和胜率记录，`--pool-authoritative` 下可直接写进备案池表；它与基底成员共用同一个模型，不占 server 槽位。
- **它只模拟「落后」，不模拟「被攻击」**。能不能改善对墙的表现，要靠 adj1 的阶梯去验，我没有证据。

**(5) 下一版上榜后盯三个数**：对墙 12 家的胜场（现在是 0/63）、高死亡档胜率（32%）、第 50 步现金差。这三个比总分更早反映病灶有没有动。

## 3. 搜索线

### 3.1 现状

| 轮 | 对 Echo4 配对 ΔU | 改子率 | 每改一子 |
|---|---|---|---|
| 第一轮全筛 | −0.836 | 46.7% | −19.0 分 |
| 第二轮全筛（后继内核） | −0.459 | 37.7% | −6.5 分 |

两轮里不改子的局分差恰为 0，伤害与改子数成正比、过原点。也就是说**每一次改子的期望是负的**，
比较器的排序信息量低于策略先验本身。微筛三变体（TAU=150、H=2）是往「少改、只改把握大的」方向走，方向对。

### 3.2 建议

**(1) 给整局改子定一个能关线的判据。** S3 的逐根反事实续局可以直接回答：按比较器优势分档，改子后真实 ΔU 为正的比例是多少。
- 如果存在一个优势阈值，其上正确率明显高于一半（比如 ≥65%）且这样的根不太稀少，就用这个阈值作 TAU，再进全筛。
- 如果任何阈值上正确率都在 50% 上下，整局改子关线，不再调参。
- 这比再跑几轮 200 种子微筛更省：微筛的分辨率约 0.06，只能分出「灾难 / 近零 / 正」。

**(2) 只在终局用精确搜索。** 最后十来步，展开可以一直算到终局，叶子就是真实现金，不需要任何估值。
- 对应的线上现象是稳定的：终局未卖载货我方 88–90、对手 48–51，对墙对其余都一样。
- 量级要说清楚：每局约 40 分，折成 U 很小；它的价值主要在小分差局（评估里货物形态决定性的 8 场都在 237 分以内）。
- 这是风险最低的一个搜索用法，也最容易单独验证（只看最后 N 步的改子，对照臂完全相同）。

**(3) 把搜索用在训练侧，只蒸馏验证过的根。** S3 会产出一批「改子后真实续局确实更好」的根。
把这些（局面，更优动作）作为辅助监督加进训练，是 KataGo 式改进算子的最小可用形态，而且不承担部署时改错的风险。
它依赖 (1) 的结果：如果找不到高正确率的区间，这条也不成立。

**(4) 时间预算不是约束。** 部署单步约 51 ms，上限 1 秒。如果 (1) 找到了可用区间，可以放心把预算花在「同一个根多采几组对手动作、取置信下界」上，
而不是加深度。

## 4. 本次代码改动（本地，未提交）

两处都是**默认关闭、关闭时行为逐字不变**；trainer 的 md5 会变（2c8262fb → 78b047f1），rollout 的也会变（f91b13c3 → f83c3fb2），
按你们的钉版流程，采用前需要验收和重新备案。

### 4.1 让分对手 `@C<金额>`（`code/rl2_ppo_rollout.py`）

- 池成员写成 `<原 spec>@C90`，该对手开局多 90 现金（机制同考试用的 `EVAL_OPP_CASH`）。
- 后缀在建对手前剥掉，所以与基底成员共用模型；完整 spec 仍是联赛键，有独立的先验和 n/胜率/分差记录。
- 回传的 `margin` 是真实终局分差（Terminal-U 奖励照此算）；逐步分差从 −金额 起算，不把让分记成第一步的损失；每局记录多一个 `handicap` 字段。
- `SELF@C..`、零或负金额、空基底都拒绝；路径里恰好含 `@C` 的不受影响。
- 测试：`code/test_rollout_handicap.py` 25/25（含真实 `play_batch` 对局、双席）；另验了不带后缀时的分差、逐步分差、步数与改动前逐项相同。

### 4.2 每轮对手子集 `--round-opps K`（`code/rl2_ppo_train.py`）

- 每轮从非 SELF 成员里按原采样权重不放回抽 K 个，本轮对局只在它们和 SELF 之间分配；SELF 保持全池时的占比，抽中的 K 个平分其余。
- 长期占比：测试里 8 个成员、K=3、4,000 轮，各成员份额与全池份额相差都在 2.5 个百分点内。
- K=0（默认）时走原路径，随机数消耗序列与改动前逐字相同。
- 测试：`code/test_round_opps.py` 12/12；另跑了一次两轮的真实小训练（`--round-opps 1` 加一个 `@C90` 成员），每轮确实只出现一个非 SELF 对手，让分变体作为独立成员进了 league.json。
- **没测过的**：在 L20 上到底能提多少速。批次变大是结构上确定的，提速幅度要看 server 的固定开销占比，需要实测。
