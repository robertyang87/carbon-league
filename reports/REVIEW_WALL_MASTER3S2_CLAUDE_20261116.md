# 墙的成因与提胜率方案：用 Master3s2 源码做的本地消融（2026-11-16）

> 基准 main@ba7c6a5c。对象：`sources/master3s2/master3s2.py`（md5 57f9a594）、`code/packs/echo4_int8.py`、`code/packs/ppou2_m_it50.py`、
> Echo4 天梯语料 243 局。全部对局在本机（i5 四核笔记本、2 进程并行）跑，**每格只有 4–12 局，是方向读数，不是考试级**；
> Master3s2 的搜索按墙钟 0.58 秒/步规划，本机负载下它拿到的搜索量可能少于天梯。

## 1. 结论

1. **墙就是对手的每步搜索。** 关掉 Master3s2 的搜索，Echo4 与它打平略优；开着搜索，Echo4 四局全负、平均 −1433，与天梯上的 0/4、−1612 对得上。
2. **我们的网络不比它的网络弱。** 对「只用策略网」的 Master3s2：Echo4 8/12 胜、it50 6/8 胜。差距不在训练出来的策略上。
3. **把它那种搜索接在我们的策略上，局面立刻反过来。** Echo4 的动作作为受保护的首选、由 Master3s2 的搜索裁决：对 Echo4 本体 3/4 胜（+705），
   对完整的 Master3s2 2/4 胜（+294）——同样 4 个种子上 Echo4 本体是 0/4、−1433。
4. **我上一份报告里「对抗强度是第一病灶」的读法要收回一半。** 死亡多是真的，但它不是可以单独修的行为：见 §3。

所以提胜率的主路是**搜索**，而且是「整步候选＋前推若干步＋学出来的评论家」这种形态；继续调训练池（adj2）解决不了墙。

  再加它自己策略的温度采样和单工人偏离，前推最多 8 步，评论家打分，严格更优才换。

## 3. 关于「死亡」：它是同风格对撞的结果，单独修不动

- 逐次死亡取证（`tools/ladder_death_forensics.py`，243 局）：我方 92% 的死亡是一换一的同归于尽——种植员撞种植员、空载捕碳员撞空载捕碳员；
  被对方「猎杀」的只有 1.9 次/局。对墙 49.6 次/局，对其余 32.2 次/局，双方数字几乎相同。
- 同谱系对打本来就这么多：Echo4 对 Echo3 51 次、it50 对 Echo4 50 次、Echo4 完全镜像 116 次。墙里多数是 Master3s 系、它的 BC 复刻和 M9XJ 系，
  与我们同风格、抢同样的格子。
- 两个规则补丁都试了，都更差：
  - 「不走进会同归于尽的格子」（`code/exp/opp_collision_guard.py`）：死亡从 50 降到 12，但对 Echo4／Echo3／it50 全负，平均 −1,700 到 −2,300。让格子等于让地盘。
  - 「主动去撞」（`code/exp/opp_attrition.py`）：对 Echo4 同样全负（−970 到 −3,700）。
- 所以这些对撞是争地盘的正常代价，什么时候撞、什么时候让，要靠前推几步去算——这正是搜索在做的事。
  按死亡数分档的胜率梯度是真的，但它反映的是「遇到了会算的同风格对手」。
- adj2 里按「造成死亡数」选压力对手，量到的主要是风格相似度；我建议这一轴只留作描述，不要指望它修墙。

## 4. 方案

### 4.1 主路：给我们的包配一个 Master3s2 式的搜索（训练不停）

我们现有搜索线两轮全筛都是负的，与它的差别是结构性的：

| | 我们的比较器 | Master3s2 的搜索 |
|---|---|---|
| 候选 | 逐单位改子 | 整步联合动作：策略自己的采样＋单工人偏离，策略原步永远保留 |
| 评估 | 浅层展开＋手写/仿射叶 | 双方按策略前推到 8 步，分阶段淘汰（1 步留一半、4 步留四分之一） |
| 叶值 | 现金量纲的启发式 | 小评论家网：现金差为底＋学出来的修正；越过终局用真实分差 |
| 降方差 | 无 | 对手根步动作在所有候选间共享 |
| 硬规则 | 被搜索推翻 | 返航步在候选里固定 |
| 换子门槛 | TAU 调参 | 0（因为估计量本身稳） |

要做的三件东西和各自的现成来源：

1. **前推用的小策略网**。它用一个蒸馏的 64×4 小网做 rollout。我们有 `cnet2_s64`，但那是旧网；需要把 it50（或届时最强检查点）蒸馏成同量级小网。
   这是标准 BC，数据用现成的自博弈局。
2. **评论家**。PPO 的 vnet 就是在自博弈终局上训出来的（价值诊断里对终局 U 的相关 0.987），但它和主网一样大。
   按它的做法蒸馏成「现金差＋小修正」的小网，输入可以复用小策略网的骨干。
3. **搜索引擎本身**：候选生成、分阶段淘汰、共享对手根步、时间规划。我们有 fastsim 作前推引擎，`cnet2_search.py` 里的分支展开可以复用。

验收顺序（每步都便宜，且前一步不过就停）：

- **第 0 步（今天就能做，考试机上）**：把 §2 的六格各放大到 200–400 局，确认「关搜索打平、开搜索 −1,400、混合体转正」三个读数。
  这一步不需要写任何新代码，`code/exp/opp_m3s2.py` 和 `hybrid_m3s2search.py` 直接可用；要在 1.5 核配额下跑，否则 Master3s2 的搜索量不对。
- **第 1 步**：混合体里把「候选来自它的策略」换成「候选来自我们的策略采样」，评论家仍用它的。读数不掉，说明候选侧可以完全自有。
- **第 2 步**：换上我们自己的小 rollout 网和小评论家。读数不掉，就是一个完全自有的搜索包。
- **第 3 步**：1.5 核计时认证（它的预算是 0.58 秒/步，我们的主网单步 51 ms，合计在 1 秒线内）＋对 Echo4、对 Master3s2 的正式场。

### 4.2 关于直接用混合体

混合体本身已经是一个可以打的东西：包体约 4.6＋2.9＝7.5 MB（上限 10 MB），单步约 0.65 秒。
但它内嵌了别人公开的策略文件（网络、信念跟踪器、搜索），**要不要这样上榜是所有者的决定**，我只把它当诊断工具。
即使不上榜，它也给了一个明确的上限参照：我们的策略配上这一档搜索，大致在 Master3s2 之上。

### 4.3 训练侧（次要，但值得顺手做）

- **把 Master3s2 完整体放进考官位和训练池都要小心计时**：0.58 秒/步，一局约 3 分钟，是替身的几十倍。作考官可以（你们已注册）；
  作训练对手只适合小份额，或只用它的「关搜索」形态（那就和我们的网差不多强，压力有限）。
- **更值的是把搜索结果蒸馏回策略**：混合体每步都会给出「搜索后换了哪一步」。它在本地约改动（待量）比例的步；
  这些（局面，更优整步动作）就是现成的策略改进标签，比 K0 的根候选教师便宜，因为每步只花 0.6 秒而不是 45 秒。
  这就是 KataGo 式闭环缺的那个改进算子。
- **信念跟踪器**：Master3s2 从第 0 步起就推断全图碳值，我们的网看到的是带未知的观测。这解释了一部分「第 50 步现金落后」。
  它是写死的推断机，不需要训练；把它的估计图作为我们特征的输入是一个独立的小实验（要重训特征层，放在搜索之后）。

### 4.4 该停或降级的

- adj2 的「对抗型」选人轴：降为描述（§3）。
- 让分对手 `@C`：它模拟的是「开局落后」，而开局落后的原因是对方有搜索和信念。保留为工具，不作为修墙手段。
- 现有比较器线的 TAU 微调：按 §4.1 的对照，问题在估计量而不在门槛。回炉确认场可以跑完，但不建议再开新的调参批次。
