## 结论先行

1. **这不是「一个 BC 网络」，而是四层复合体**：手工 54 平面特征＋碳图信念跟踪器（写死的地图推断机）→ 策略网络（BC＋自博弈 RL，约 111 万参数，按对手身份 sid 条件化）→ 每步联合动作搜索（内嵌完整规则模拟器＋独立评论家网络，0.58 秒硬预算）→ 写死规则层（终局返航 go_home、落点仲裁、招募门控）。四层中只有第二层的「怎么走」是学出来的，其余三层是工程。
2. **搜索是整局联合动作搜索，不是逐单位改子**：候选＝策略自身在多个温度下的整步采样（≤32 个）＋单工人偏离；分阶段加深（1 步留 50% → 4 步留 25% → 8 步终局评估），双方都按策略采样推进，对手根步动作跨候选共享（CRN 式降方差）；切换门槛 `_S_EPS = 0.0`——敢用零门槛，是因为估计量是 8 步模拟均值而非单叶差。
3. **墙的三个表型各有明确出处**：开局现金强势＝信念跟踪的信息优势（第 0 步起近全图碳值推断）＋第 0 步起搜索；死亡压力＝危险平面（逐动作致命性写进特征）＋模拟器对碰撞/树税的精确计价（轻载捕碳员碰撞胜出并夺货，`next_state` 碰撞段）；残树 2.1–2.3＝终局机器群（终局平面 37/38、go_home 硬规则、搜索候选强制保留返航步 _S_HOMEFIX、margin 形终局值）。
4. **作考官的饱和风险是数量级问题**：墙面平均分差 −1563 对应 U≈0.09；@C60–@C120 的让分尺度（训练压力刻度）对这个量级只是零头（估计可动分差低百量级），把 U 拉回 0.5 需要 @C800–1500 量级（估计），那时游戏已被让分改形。3s2 的合适位置是 margin 尺读数／D-wall 式诊断对手，不是 U 基线考官；且其单步成本（搜索至 0.58s/步）使任何考场必须先过计时认证。
5. **m3s2r1 复刻缺的不是权重精度，是三个不存在的子系统**：搜索、信念状态、写死规则——回放里只留得下它们的输出动作，留不下产生动作的反事实计算；复刻残树 5.6–6.8 对真身 2.1 的差距正是终局机器群不可见的指纹。
6. **对 Echo4 搜索线回炉的可借鉴点**：估计量降方差（模拟推进的均值）优先于门槛调节；候选生成保持在策略分布内且策略原步永远受保护；硬规则步在候选内固定、搜索不得推翻；时间按实测成本规划候选数。这四条与四源终裁的带表读数（30–100 分差带改善 9/9、6/6）同向：信号是小而真的，要的是分辨率，不是更大的 TAU。

**agent() 每步流程**（629 入口，perf_counter 计时 t0；任何异常吞掉返回 `{}`＝全员不动，571 `_act`）：

1. 步 0 或状态缺失时初始化 BeliefTracker 与 rng（`_SEED=None`，553：每局新鲜随机）；
2. 信念更新：`tr.step(players, step, obs['carbon'])` → 碳图估计 est＋known 掩码；
3. `encode` 出 54 平面（输入是**信念估计图**而非原始碳图），量化到 0.01 网格（`clip(rint(x*100),0,255)*0.01`，与搜索侧 `_quant` 1149 同式）；
4. numpy 策略前向（sid 固定，见 §2）得每格工人 logits lw、基地 logits lb；
5. 动作**采样**（非 argmax，见 §2）：基地先抽招募动作（现金 ≥30 且工人数 <10 才执行）；工人逐个抽动作，载货捕碳员先过 go_home 检查（命中者以优先级 2.0 置顶）；
6. 落点仲裁：按概率降序逐个工人定落点，自家碰撞默认禁止（`_RETIRE=0`），采样动作优先、不可行时按概率次序替补；最后 12 步允许捕碳员叠在自家基地上（`_BANK=12`，551）；
7. `configuration` 非空时进 `_search`，可整步替换上述联合动作（异常吞掉、保留原动作）；
8. 把最终动作记回跟踪器（`set_actions`，供信念的碰撞归因）、存 prev 观测，返回。

## §2 策略网络

**架构**（`_Policy.forward` 514–531；权重形状静态解包）：

- 输入 54 通道（stem.w 形状 (96, 54, 3, 3)）；stem 3×3 卷积（wrap 填充＝环面）＋ **sid 嵌入**（emb (121, 96)，按名字查表广播相加）→ ReLU；
- **6 个残差块**（meta[0]=6）：3×3 卷积 → ReLU → 全局均值池化的 SE 式线性支路（g.w (96,96)）→ 3×3 卷积 → 残差相加 → ReLU；
- 双头 1×1 卷积：hw (5,96) 工人头（每格 5 个动作 logits）、hb (3,96) 基地头（每格 3 个招募 logits）；
- **无注意力、无循环**；历史只经特征里的上一步位置平面（14–17）与信念状态进入；
- 参数量：策略网 **1,111,617**（float16 存储；stem 46,656＋emb 11,616＋6 块各 175,296＋双头 776），评论家另 12,193（见 §3）。

**sid 条件化**：权重内 `snames` 共 **120 个名字**——作者自家谱系（AgyCarbon-*、claude-opus-v*、TJB-o18-*）与天梯他人策略名（Carbon_*、Challenger、Shugang_*、DS-Evo-1 等）混编，即该网在训练时按「对手/人格身份」条件化；部署钉死 `_SID = sid('TJB-o18-rush-v41')`（549）。搜索里给对手建模时用的也是同一个 sid（1252 起 root 对手视角 `net(xo, _SID)`）——**它把对手建模成「戴着 rush 人格的自己」**。

**观测特征：全手工 54 平面**（`encode` 76–203，输入含信念估计）：

- v1（0–24）：估计碳图/100（80）、known 掩码、双方捕碳员位置＋log 载货（2–7）、双方树位置＋树龄/50（8–11）、双方基地（12–13）、上一步双方单位位置（14–17）、步数/300（104）、双方 log 现金（19–20）、双方单位数/树数（21–24）；
- v3 终局（37–38，113–114）：`2.4·max(0, 1−left/16)` 与 `2.4·max(0, 1−left/6)` 两条终局斜坡（注释：其余时段为零、不扰动中盘）；
- v2 危险（25–36，约 117–140）：逐己方单位逐动作——落点是否致命（有更轻的敌方捕碳员能到／对种植员是任意敌方单位能到）与是否平局（同载货），外加全图最近敌方捕碳员载货面（35–36）；
- v4（39–53，142–190）：到最近自家/敌方基距离（147）、「终局前到不了自家基地」布尔面（149，X[41]）、两步内敌方捕碳员计数与最轻载货（42–43）、己方下步可达捕碳员计数与最轻载货（44–45，注释：满编时自家碰撞允许、最轻者全得）、双方种植员可达面（46–47）、夺树面（48–49：己方种植员旁的敌树按剩余寿命、反之亦然，181）、分差 ahead/behind 面（50–51：现金差/2000 截断 2.5，185）、双方在板载货 log（52–53）。

**信念跟踪器**（205–501）：对每格维护碳值估计。可见集＝自家捕碳员所在格＋种植员邻域（BeliefTracker.step）。不可见格靠三件写死的机制推断：① 游戏动力学正向推演（REGEN=1.03、CAP=100、ABS=0.0375、COLLECT=0.3，267–270——即碳再生/吸收/采集率的逆向标定值）；② 对称类推断（CLS 按到边距离分 63 类，同类格共享初始碳 v0，观测到一格即可反推整类，`_infer_v0` 在 0–50 内搜最合的 v0、容差 5%）；③ 事件归因（树枯萎/新生、工人死亡的碰撞归因——结合我方上一步去向 `last_dest` 推断谁在哪格赢了碰撞、碳落谁手，含从敌方捕碳员载货变化反推其采集格碳值）。先验：未见类期望碳 22.0（`prior()`，按已发现非零类比例缩放）。**这是把游戏隐藏信息机制整台逆向出来的推断机，不是学出来的。**

**价值头形态**：策略网本身**没有价值头**（只有双策略头）。评论家是独立小网（`_VALUE`，`_TorchNet` 1016–1019 装配、__call__ 末段计算）：骨干特征每格 1×1 卷积 96→32 → ReLU → 全图 mean＋amax 池化（64 维）拼 5 个标量（`_scalars` 1153：现金差/3000、在板载货差/3000、步数/300、树数差/10、工人数差/10）→ 69→128 → 1；**输出＝当前现金差/3000 ＋ MLP 修正项**（线性输出，**非 tanh**）。终局值 `_terminal(m) = clip(m/3000, −2.5, 2.5) + 0.5·sign(m)`（999）——与 U 的结构同族（分差项＋胜负项 0.5），但分差项是线性截断而非 sigmoid。

**部署采样还是 argmax**：**采样**。`_probs`（562）＝softmax(logits/_TEMP)，`_TEMP=1.0`（548）；`_TEMP<=0` 才是 argmax 分支，部署不用。基地与工人都用 rng.choice 按概率抽（571 起）；搜索候选与 rollout 内的双方动作同样是采样。即部署形态＝「采样策略＋搜索在候选间裁决」，且 `_SEED=None` 使其逐局不可复现（仅分布可复现）——作考官时这是读数方差的内生来源，配对种子设计配不上它的内部随机。

## §3 每步短搜索

**存在且每步触发**：`_S_START=0`（975），步 0 起每步都搜；门条件：`configuration` 非空（571 起的调用点）、torch 可用且引擎可用（`_SEARCH_OK`；内嵌 `next_state` 优先，真实 Board 兜底；torch 缺失则整段关闭、纯策略照常打）。任何异常回退策略原动作。

**候选生成**（`_search` 1279–1300；常数 976–979）：

- 候选 0 ＝策略原步 act0，永远在集内且在分阶段剪枝中永远保留；
- 温度采样整步联合动作：`_S_GEN = ((2.5, 8), (1.0, 3), (3.5, 8), (0.0, 6), (5.0, 8))`（977）——依次在温度 2.5/1.0/3.5/5.0 下用 `_sample` 抽整步动作（上限 8/3/8/8 个），动作字典去重，同一温度连续 8 个重复即停（`_S_DUPS=8`）；
- 温度 0.0 档＝**单工人偏离**（`_deviations` 1206）：把 act0 里至多 6 个工人的动作换成其次优动作（跳过 go_home 固定者与落点冲突者）；
- 总上限 `_S_K=32`（976），再被时间规划下调（见 §6）：`most` ＝整个搜索计划能塞进剩余时间的最多候选数（`_plan` 1234 按行数/步数/趟数算总成本）。

**评估：分阶段加深＋双方推进**（1385–1438）：

- 每个候选配一条 rollout（`_S_M=1`，980；`_S_MMAX=1`，981——最后两名加测的回路在本配置下不触发，即**每候选恰一条路径**）；
- 对手根步动作先按对手视角采样一次（同网同 sid），**同一 rollout 号 m 的对手根步动作被所有候选共享**（`begin` 内 opp[m] 缓存——CRN 式对照降方差）；
- 逐深推进：深度 t 时用评论家给所有存活盘面打分（批量 ≤32 行/趟，`_S_ROWS` 985）；阶段剪枝 `_S_STAGES = ((1, 0.5), (4, 0.25))`（982）：t=1 后按均值留前 50%（至少 2 个、含候选 0），t=4 后留 25%；存活者继续到 **`_S_D2=8` 步深**（983）；
