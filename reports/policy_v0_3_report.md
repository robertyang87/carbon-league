生成：2026-11-03。评估在 FastCarbon（与原版 36/36 对拍一致）上进行，口径与前轮相同：**同 seed 同图、交换先后手配对**，绝对分跨局不可比。本轮全部 14 局对测（8 局对 juzi + 4 局对 example + 2 局消融）均已用 `record_trace.py` 留痕至 `traces/`（清单见 `traces/INDEX.md` 的 v0.3 补录节），重跑终分与本报告记录逐局核对差 **+0.00 / +0.00（14/14 精确一致）**。

## 本轮改动（policy_v0_3.py，以 v0.2 为底）

1. **树战资源模型重做**：
   - 种植员编制 2 → 3，分阶段解锁：第 3 名仅当我方树 ≥ 4 棵时才招（`planter3_min_trees`），不饿早期采集经济。
   - **守树站格拦截退役**（`tree_def_on` 默认 0，代码保留作消融对照），改为**反抢竞速**（`tree_reseize_on`）：策略逐歩记忆自家树（pos → tid），树被夺（同 tid、主人翻转）且剩余寿命收入积分（`tree_income_estimate`）≥ 150 时登记为竞速目标，最近的空闲种植员优先赶往；目标格仍被敌方种植员占据时在邻格悬停（不进格自杀），格子一空当步进格夺回。目标有 40 步 TTL 与价值衰减下限（< 100 掉表）。
   - **反抢质量门槛**：普通抢树在原「> 20 + 3×路程」之上再加 `rob_value ≥ 150`（竞速折扣之后）；Phase A 站格夺树同用 150 门槛（反抢竞速目标豁免，登记时已过门槛）。尾值树不再追。
   - **种树选址避敌方活动热区**（`plant_hot_avoid_on`）：敌方工人位置热度图（每步 ×0.97 衰减，本格 +1、4 邻 +0.4）；候选格距敌方种植员 ≤ 2 时得分 ×0.25，其余按 1/(1+0.5×热度) 折扣；种植员已站格时，若敌方种植员贴身（≤1）则不种（种下即被抢）。
2. **死亡丢碳专项**：先离线统计（下节），再针对性改护货（`cargo_guard_on` / `planter_guard_on`）：
   - 危险图（hard/soft 集）的咨询门槛从货 ≥ 60 降到 **≥ 15**（Phase A 停留判定与 Phase B 移动同口径）；与我方**同货**的敌方采集员，其可达圈进 soft 集（并列最少是同归于尽）。
   - `_choose_dest` 对 hard 危险格在**两个池子**里都 +500 成本——v0.2 的回退逻辑里硬危险格只是「禁行」，全禁区时与自家预留格同价竞争（seed 1002 步 99 的 213 货 converging 猎杀即如此发生）。
   - **肥货气泡**：货 ≥ 180 且有更轻的敌方采集员在 2 格内 → 立即返航，不再就地采集。
   - **种植员自保**：种植员移动把**所有**敌方采集员的可达圈（本格 + 4 邻）当 hard 危险（任何采集员接触都杀种植员）；种植员停留种树时若敌方采集员贴身（≤1）取消停留（对方进格可在 Phase 2 先杀种植员、种树不成立）。
3. 保留 v0.2 全部冻结修复与 R 配置阈值组（450+距离折扣+剩余步数硬规则）、对手模型 400 校准；规划器不回归。

## 死亡丢碳离线统计（施工单第 2 步的前置，diag_deaths_v03.py）

对象：`traces/` 里 v0.2 对 juzi 的 8 局全程轨迹。逐局与 eval 账本 `death_cargo` 核对差 ≤ 0.3（轨迹取整），总计 236 死、账面丢碳 5814（727/局），与账本一致。分类经最贵几起「其他」死亡的逐帧探针验证后定型（分类器 v2）：

**核心发现：账面 727/局高估真实损失。** 其中 **264/局（36%）是基地口碰撞整合**——终局采集员踩上己方基地格与同伴碰撞，胜者当步把合并货量存入（探针实证：胜者站在基地格、我方现金当步跳升 ≥ 被撞者货量，如 seed 1003 步 278 现金 +266 ≥ 245）。这类「死亡」货没丢。

| 真实丢碳 463/局的构成 | 数值 |
|---|---|
| hunt_kill（被敌方采集员赢下碰撞格） | 102 次、3558（**96%**） |
| 其他真丢（踩敌基地等） | ~103（3%） |
| 按货量段：150–300 段 | 仅 **2 起**（216@步268、213@步99）共 429（12%） |
| 按货量段：< 60 段 | 198 次、3205（87%）——低货决斗死的海洋 |
| 按步段：51–250 步 | 占真丢 **88%**（251–300 只占 16%，且多为整合） |
| 按地形：敌树吸血圈内 | 仅 **8%**（开阔地 92%） |
| 杀手起始距离（帧 t）：≤ 1 格 | 占真丢货 **77%** |

**施工单的初始假设（满载者在敌树圈/猎杀圈暴露）被数据否决**：大货真丢只有 2 起，真问题是**低货采集员（均货 ~35）被更空的敌方采集员贴身决斗批量猎杀**——我方采集员采到几十货停着不动，对方空载采集员进格即赢、连货带格一起拿走。v0.2 的危险图只在货 ≥ 60 时才咨询，15–60 段完全裸奔。

**种植员是另一条失血线**：112 次阵亡（14/局、0 货），**76% 死在距己方基地 ≥ 5 格的野外**（远征 churn：抢树远征 + 深区种树），每次烧 30 招募重招。对照：同 8 局 juzi 全局只死 100 个单位（我方 236），丢碳 2297（我方 5814）。

原始量（我方 / juzi）：存入 4649 / 6856；树收入 **643 / 3763**；种树 18.4 / 25.1 棵；抢树 **0.4 / 12.2 次**；招募 16.4 / 16.9 人；死亡 **12.4 / 11.4**，死亡丢碳 **393 / 319**；终局滞留 18.3 / 23.0。

读法：
- **死亡专项是决定性胜利**（账本口径、与分类器无关）：我方死亡 29.5 → **12.4**/局（juzi 11.4，**首次持平**），死亡丢碳 727 → **393**，招募 33.4 → **16.4** 人（juzi 16.9，持平）。用同分类器复测 v0.3 轨迹：账面 393 里 **358（91%）是基地口整合回收**，hunt_kill 真实丢碳从 v0.2 的 ~445/局崩到 **~13/局**——低货决斗死这条失血线基本被掐断。存款缺口随之收窄 284。
- **树战重做在其自定指标上失败**：抢树 4.1 → **0.4**/局（150 门槛 + 竞速合计产出 ≈ 0；轨迹翻转计数同为 0.4，互证）；树收入 720 → **643** 不升反降；juzi 树收入反而 3418 → **3763**、抢我方树 12.2 次/局如故。**树缺口 −3120 占总缺口 66%**（v1 时 54%）——不是树变得更差，是其他洞都补小了，只剩它。
- 第 3 名种植员机制本身工作：6/8 局成功在场（≥3 种植员帧数场均 43、最长 94），种树量也涨到 18.4 棵——但多种的树照样被成批夺走并喂 juzi 的 3763。
- 反抢竞速为何 ≈ 0（轨迹只能定性、不能拆分到单个机制，政策内部状态未留痕）：juzi 夺我方树的翻转 12.2 次/局真实发生，但我方翻回仅 0.4。候选机制（按可能性）：① 夺树时点我方树邻格已被 juzi 吸空，登记门槛（剩余积分 ≥ 150）就没通过；② 竞速目标登记了，但 juzi 种植员在树上停留期间我方只能悬停，其离开时目标已过 TTL/价值下限被掉表；③ 150 的 rob 门槛把普通抢树也一并关死（v0.2 无门槛时抢 4.1 次、虽多为尾值但非零）。下一轮动树之前必须先给门槛/登记/到达三段加计数插桩，不再盲调。

## 结论与下一步建议

1. **当前最佳版本 = v0.3（−4737）**。骨架的防守半边已与 juzi 持平（死亡 12.4 vs 11.4、招募 16.4 vs 16.9、真实猎杀丢碳 ~13/局）；冻结不复发；速度达标。**剩下的仗 66% 在树、47% 在存款**（两项有重叠：树被夺 → 对方存入端也涨）。
2. **树战下一轮先插桩、后动刀**：给三个关口（竞速登记数、rob 门槛拒绝数、种植员到达时目标状态）加计数，用一局轨迹 + 计数定位 12.2 次被夺里到底卡在哪一段，再决定是降门槛、分段门槛（反抢用剩余积分、普通抢用 rob_value 不混用）、还是改打法（例如放弃夺回、改为在 juzi 树旁贴身采集抽血——用采集端对抗树经济，而非种植员对耗）。
3. **存款缺口 −2207 成为第二正面战场**：生存持平后，缺口来源只剩编制构成与路线效率两个候选（3 种植员局里采集员少 1 名的代价、肥货气泡让返航更频）。下一轮可从轨迹统计双方分阶段在场采集员数与单采集员产出，直接量出来。
4. 护货参数（门槛 15、气泡 180/2 格）本轮未见副作用证据（存款不降反升、滞留正常），保留。
