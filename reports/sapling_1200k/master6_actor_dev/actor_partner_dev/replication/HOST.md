# 新图八场的主机计时证据

本机 cgroup 的 CPU 配额为每 100,000 微秒可用 400,000 微秒，允许使用逻辑核 0–4。每一对同时开跑的父代与候选进程各绑定一核，按地图和物理席交换 0、1 核。每场收据记录实际亲和掩码。棋力对照用原版的逐场计时、返回类型、候选数、完成深度及真实改令数。[八场运行统计](CLOCK.md)

从 10:45:27 至 10:47:42 UTC，对剩余赛程补采 28 个 cgroup 快照，覆盖 135.02 秒。内核在其间记录 1,339 个调度周期，其中 5 个周期发生配额节流，计数增加 171,744 微秒。这是整个共享 cgroup 的增量，无法归到某个考官调用。前六场没有同期主机采样。原版的外部调用最大耗时 724 ms；0.58 秒控制是否再启动一批搜索，与完整调用的硬超时口径不同。[原始主机样本](clock_host.json.gz) · [原版预算判断](../../../../../sources/master3s2/master3s2.py#L1393)

补采器最初通过 Linux 的进程子节点文件查工作线程，本机内核未暴露该文件，所以 28 份样本的 worker 列均为空。现版通过父 PID 发现工作进程，已在本环境验证能看到由非主线程启动的子进程及其亲和掩码。先前缺失的逐线程 CPU 用时保留缺测。[可复用采样器](clock_host.py)
