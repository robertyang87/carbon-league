# 晚段同工资换招采集工

在冻结的 Sapling v1 准备招种植工时，候选仅在晚段、同工资、真实可招且存在安全回款路线时改招一次采集工。显著的近端夺树或造林机会让父代继续招种植工。决策读取本席公开的当前工人、树、指令和最多六步的可见地碳记忆。招募后所有工人由冻结双网正常行动。回款估计本身无法保证新工会走所估的路线。[冻结筛选与适用范围](protocol.json)

58 个招种工步中，33 次找不到可见回本地点，11 次保留近端夺树机会，6 次保留有价值的新树位置，5 次现金、工位或现存种工条件不符，1 次有基地交通风险。两次改令都是基地旁一格、两步前本席确实见过地碳，预估能交 40.79 与 36.25，等价工资均为 30。预测值只用于筛选。在公开地碳未知的格子，模型保留未知状态。[分席和拒绝原因](screen.json) · [全部58条原招工指令](recruit_orders.json.gz)

部署候选逐步重解码原 v1 选择的分支。从选中基地起按替换后的角色推进真实 Prefix，若同轮其余单位的命令也变动则回到 v1。两场各 299 步，父代的历史命令全部复现，两个改令均只有一个基地指令不同。这两场出现专家与 Sapling 意见分歧时，冻结的解码在采集类分别 69 和 68 次选中 Sapling 输出。候选水平应以真实对抗验证。[实物包](agent.py) · [来源与 SHA-256](manifest.json) · [整局复演](package_replay.json)

两根均通过权威环境和 FastCarbon 的同根招聘检查，实体工号、实际职业和等价工资记录在协议中。两条臂共用原版对手的根动作及原始随机流的配对初态。随后原版 Master3s2 从实际可见历史恢复，自行搜索、按原温度应对直至官方终局。两边各只有一次续弈，一部分终分差异可来自限时搜索与后续轨迹分叉。[配对原版实验登记](native/protocol.json)

    python -m unittest -q test_late_workforce.py
    python build.py
    python screen.py
    python screen.py replay
    python native.py prepare
    python native.py schedule

最后一条命令遵循同机已登记的实验先后与互斥锁，已完成的分支先核验原签名。该研究的局部比较使用两个已采集过的训练局面。正式地图和天梯提交另有独立流程。

两根实际回款均覆盖工资，官方净分变化为 −127.22 和 +16.97。按事前条件保留 v1。[四条真实续弈结果](native/RESULTS.md)
