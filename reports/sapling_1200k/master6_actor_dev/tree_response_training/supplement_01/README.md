# 追加训练地图与真实付款对照

第三批签收时，六张训练图上已有 24 个配对终局，其中 15 个实际付款。旧队列余下两批即使每个条件根都实付，总数也只到 31。此次单独预登记至多三个新批次，每批两张训练图、每图双席、每席至多两根。开局前已固定棋盘指纹、席位、挑选窗口、分层和考官随机状态；两张原有保护开发图继续封存。[登记清单](registration.json) · [生成登记的源码](register.py)

每批都是完整的八根上限，保留未选中、未成功付款、败局，以及所有官方终局。只有原队列第五批完成并通过全部命令哈希、地图和官方终局的复核才允许启动补批。每批签收后复核累计地图数和实付配对数；达到八图与三十二实付即停。正负收益各覆盖两张地图另用于判断能否拟合。补量只由地图与实际付款数量触发。

从本目录运行 `python run.py status` 查看第一处断点，`python run.py drain` 可接管或恢复。独立监督器会等待原队列与开发预约释放原版考位。已经运行的监督器持有进程锁，第二个调用会让位。每批选根实际执行赛前冻结代码，每个终局标签保留原版对手再响应、官方逐帧计分、真实扣款及双边现金事件。最后一个已登记批次结束后输出 `completion.json`，含累计实付、地图、正负效应所在地图、空窗及仍缺数量。[接续入口](run.py) · [地图与历史回放隔离](clearance.py) · [顺序及停止条件回归](test_supplement.py)
