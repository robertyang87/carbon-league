# 为 Sapling 收集种植决策的原版终局标签

该训练批次用冻结 v1 在两张新图上对完整原版 Master3s2 交换席位，从四条实际源局中每局最多取两个决策。每个选定根比较同一名种植工的两条合法指令：原地付款，与移动后保留现金。双方随后根据新局面真实应答到官方终局。标签为两次干预下的**本方官方得分变化减去对手官方得分变化**。另存树本身的首次持有收入，以区分一笔买卖和全局得失。[冻结协议](protocol.json) · [地图与既有训练数据的隔离核验](clearance.json)

源局使用训练图 621471120、621471121，两张地图各打两席。621471220、621471221 登记为开发图。上一批两张旧开发图及其两条经营反例不进入本批训练数据。当前预算提供两张独立训练地图，不拟合可推广的控制头，不调用开发或正式考试地图。[源局采集及官方核账](source_games.py)

机会档案保留每步每名本方种植工的全部五个方向、真实的已有解码前缀、公开支付能力、占格和威胁，以及这个工人前三、五、十步的路线。选根提前按对手靠近基地的重货、己方有收益潜力的树区面积和附近敌种植工分层。只使用动前公开观察和 v1 当时的原始行动，按冻结的排序挑选；最终还要用实际 v1 两个网络沿替代前缀重解码，其他单位和基地指令必须逐项不变。因此可区分“没有走到有价地块”“站在地块上仍走开”“实际买入”。[全量公开机会导出](opportunities.py) · [两臂真实合法性与确定性选根](select_roots.py)

## 接续方法

使用项目现有比赛 Python 环境，从本目录依次运行以下入口。各阶段保留输入哈希与已完成游戏。重复调用会重新核验已保存的工件，避免重新抽取一条随机流。源局使用核 0/1。四条源局完成后，两个独立响应对可分别使用核 0/1 与 2/3，前提是其他原版场空闲。[响应资源冻结补充](response_resources.json)

```bash
python source_games.py play
python opportunities.py
python select_roots.py
python pair_games.py schedule
python label.py
```

每条训练标签引用条件根的公开输入、已记录历史和完整双边命令。付款意图遭碰撞或未实现时仍保留该样本。双方官方终分、真实支付、树的首次持有收入、后续双方收支及考官搜索次数可独立核对。两臂对齐起始随机状态和时间估计表，裁决仍会受到原版墙钟预算影响。完整数据出齐后汇总不同地图与不同暴露层的覆盖。[对局响应](pair_games.py) · [官方双引擎与逐树现金标签](label.py)

[首批八个配对终局及正负训练标签](RESULTS.md) 已签收。下一组的两个新训练图已按独立清单登记，源局、机会索引、干预与结果按批次单独存放。用 `python next_queue.py --status` 可只读查看第一个缺项，已启动的组可用 `python batch_cli.py intake_02 run` 检查身份并从缺项恢复。[跨批次清单](next_intake.json) · [第二批赛前登记](batches/intake_02/protocol.json) · [批次驱动](batch_cli.py)

已登记的后续训练可用 `python continue_intakes.py drain` 顺序接续，运行中可用 `python continue_intakes.py status` 查进度。监督器使用目录下的操作系统文件锁，重复启动会直接返回。各批另有注册锁与运行锁，恢复时按已保存的协议、源局命令、地图指纹、同根动作、原版随机流、官方计分及逐臂命令哈希核对。退出后再次运行同一入口可恢复。监督器只处理清单中的训练批次；补量批仅在八张训练图或三十二个实付配对仍有缺口时启动。完成后，跨地图支持和正负效果各自覆盖的地图数见最新一批的 `aggregate.json`。双席保护开发图另外封存。[顺序监督器](continue_intakes.py) · [训练任务与资金门槛](next_intake.json)
