# 从己席观察预测对方运货工的走向、回库与碰撞

Sapling 在原版 Master3s2 的六张留图上能提前识别一部分回款。用工人实际轨迹、可达返程线路、周围轻重工和公开现金预测五步内入库，Brier 分数从只看距基地的 0.0881 降到 0.0712。对 14 张未用于拟合或校准的天梯图，分数从 0.0941 降到 0.0856。拦截还需知道对方下一拍进哪一格，五向单选的准确率仅为 49% 左右。回库概率、碰撞后货物所有权和整局终分分别留账。

## 数据与推理身份

- 原版研究固定到 3d02c08f78e4a2efe954d882c3b8e8648aed2411 的 v1_phase_census/latest_games.json，54 条完整实战母带，27 张地图各换席。清单 SHA-256 为 90a6d8fb8962503db05b22162fa0e4921f104c7a43f778c5c47b7243a18903a3。每条母带核父包、原版考官与字节身份，重演核终局现金。训练 17 图、单列校准 4 图、留评 4 图，再单列较近 2 图。训练仅有一个考官注册名。
- 天梯固定到 all_top5/appendix_4a4677c9，取该批有双边分数可完整复算的 14 场，双方各作一次观察者。敌方涉及 15 个报名名，均未进该项头的训练或校准。Master6 出现在其中 11 场。两席共用物理地图，报告按地图等权。原版各组和天梯的地图种子及初始物理地形不交。这些均为已公开或已用的研究图。
- 每条记录对应一名此刻可见且携货大于零的对方采集工。特征包括当拍货量、双方工人与基地位置、我方轻工能否在最短路径上封格、同伴接应、当前可见碳，以及过去 1/3/5/10 步该 ID 的位移、载量和距库变化。输入最多 11 帧己席观察。对方真实命令取作下一步五向观察标签。其后实际对局用于核收入与碰撞。input_audit.py 在双方席位 24 个实根上逐工比对归档特征和公开 API，67 个携货工吻合。改写全部不可见碳并添加虚假全图、敌令和将来标签，输出逐值相同。72 项乱序、跨席或缺帧输入校验均拒绝。
- 既有 reports/master_family/tactical_rules/opponent_intent 只在旧 policy_v0_5 示范上训练。保留它的角色五向权重，仅在四校准图上按过去三步是否在接近仓库分两组调温。十步 freight_horizon 已有同 ID 的公开返程特征，直接复用。旧 return_denial_training 拦截器的输入含己方拟执行的联合命令，应用条件不同。reports/opponent_predictor_report.md 的方向桶与历史方向预测亦作为既有工作。新增训练参数来自公开局面及对手响应标签，未使用考官网络参数。
- Forecast.predict(history) 按工 ID 返回五向概率及三步、五步入库与接触概率。CollisionRisk.predict(history) 补报实物货款转移风险。两份新头各小于 4 KiB，模型需同时使用仓内原有方向权重和特征代码。四个目标分别采用按地图等权的正则化逻辑回归及独立校准，对 H5 概率施加不低于 H3 的约束。

## 概率证据

表内 Brier 越小越好，单位是整张地形等权的工人时点。H3/H5 的真实支付要求同一名工人在相应时窗内确实获得基地现金；工人进库时可含中途新收货物。时间窗在正式终局处截断。区间按物理地图重抽，同一时点和同图换席产生的重复机会没有当作独立地图。

| 观察 | 原版留评 6 图，14,121 个工人时点 | 天梯留评 14 图，29,803 个工人时点 |
|---|---:|---:|
| 下一步五向准确率，旧头调温 / 沿上一方向 | 49.0% / 42.4% | 49.1% / 40.6% |
| 五向交叉熵，调温 / 未调温 / 沿上一方向 | 1.274 / 1.287 / 1.820 | 1.286 / 1.302 / 1.869 |
| 三步入库 Brier，本头 / 距离 / 常数 | .0473 / .0577 / .1429 | .0542 / .0617 / .1477 |
| 五步入库 Brier，本头 / 距离 / 常数 | .0712 / .0881 / .1974 | .0856 / .0941 / .2013 |
| 五步入库平均预测 / 实际 | 27.9% / 27.0% | 31.3% / 27.8% |
| 五步与另方带货工争同格，平均预测 / 实际 | 0.40% / 0.28% | 0.51% / 0.24% |

五步入库相对距离头的 Brier 差在原版为 −0.0169，95% 地图自举区间 [−0.0188, −0.0153]。天梯为 −0.0085 [−0.0122, −0.0039]。三步入库分别为 −0.0104 [−0.0119, −0.0090]、−0.0075 [−0.0097, −0.0050]。训练有 42,333 个工人时点，校准有 9,782 个。原版旧四图及较近二图在 evaluation.json 分列。天梯按对手名、席位分列。观察 Master6 的 11 图共 11,521 个工人时点，五步入库 Brier 为 0.0952，距离基线为 0.1054。外部对局上五步回款概率平均高报了 3.5 个百分点。

**回溯同一地形上的正反例。** 用固定顺序分别取首次出现的「当前货值至少 100、五步入库预测至少 80%」的成功和失败例，规则与逐根收据见 input_audit.json。在 621477120 图观察席 0，第 55 步对方工 8 载货 170.35，距库 3 格，最近 3 步向库靠近 2 格，有一个不被轻工立即封堵的最短下一格，预测 93.5%，五步内实收 170.35。第 167 步对方工 28 载货 296.19，同样距库 3 格，最近 3 步向库靠近 3 格，同样只有一个安全最短下一格，预测 81.3%，五步实收 0。回程证据能缩小关注范围，单凭走近仓库依然会误判窗口。其余离散程度见逐图和全部分箱的记录。

## 真正发生的抢货

主协议统计同格另一方也带货的采集工，碰撞可导致失货或双方同灭。空手轻工能击败携货重工，故在查看这批跨队实款明细前另行冻结 collision_extension_protocol.json。补充统计实际在碰撞中从带货采集工转给敌方存活采集工的正额货物。每个真实受损工人的货款转移计一次，同一事件前连续几个预警时点不会重复增加事件数。存活工人取得的货值与之后回库所得可分别检索。

| 面板 | 真实正额夺货事件 | 胜方碰撞前空手 | 从带货工转给对手 |
|---|---:|---:|---:|
| 原版训练 17 图 | 24 | 18 | 1,676.24 |
| 原版校准 4 图 | 6 | 3 | 643.20 |
| 原版留评 6 图 | 7 | 5 | 320.35 |
| 天梯留评 14 图 | 35 | 26 | 1,474.03 |

补充头预测那名对方工人未来五步成为夺货受害者，原版 Brier 为 0.002469，距离基线为 0.002513。天梯两者分别为 0.005907 和 0.005912。预测携货工主动或被动取得对方货物的五步项在天梯还略逊距离基线。低事件数、相邻时点重复覆盖同一次碰撞、缺少尝试后撤退的标签，都限制了对抢货收益的推断。可据实观察的是攻防时应跟踪空载威胁，尤其在大货回款路上。这些记录本身无法回答换走一步是否更赚。

## 观察什么样的回款窗口

限定货量至少 50、距库 2–4 格、能回看三步的所有携货工时点。在此前三步向库靠近的子组中，若至少一个最短下一格没有我方更轻或等轻采集工能立即到达，原版 2,461 个时点的五步实收率为 60.9%，工均实入 106.5。所有最短下一格都受威胁时，83 个时点实收率为 39.6%，工均实入 60.7。天梯跨对手相应为 4,819 个与 229 个时点、59.8% 与 36.7%、工均实入 100.7 与 62.5。这给出了比「看见大货就抢」具体的观测对象，实际出生位置、双方其余人员与目标选择仍可能解释差异。尚未向库靠近且所有短路受威胁的原版子组仅 36 个时点，反而有 50.5% 入库。完整四格与根货值见 return_context.json。每个时点可能观测同一笔未来回款，工均值不可逐行相加，也不能冒充我方封路的边际收入。

## 从概率走到我方收入

在 108 个原版同根双臂、18 张地形上，分别实盘复算两套完整己方命令。选择器只能在原父代整套动作与已签的另一整套动作中选一套。两臂共用当时己席的敌工走向预测。若己方有队友移动或招工占目标格、敌方有未建模或多个可能到格者、编辑了非采集工或无法归属碰撞影响，保留父令。无竞争而直接回库的本方运费和可能放弃的货款也计入选令。比较器对五向均匀概率使用完全相同的局面、动作和机会成本。三步/五步的随后行为随己方动作可能变化；它们只记为描述，未拿来给改令强加反事实收益。

| 已签面板 | 来源地图 / 全根 / 改令 | 相对父令己方正常存入 | 对方正常存入 | 官方终局分差变化 |

各列按图等权，保留全部未改令根。训练、校准、原四张留评图在该双臂集中分别有 66、14、28 根。较近两图和天梯均无实际同根双臂，故无对应的干预收益估计。留图有 16 根涉及非采集工改令、10 根没有可归属的接触差。其余 2 根两种概率选择了完全相同的整队动作。

## 复现与原件

在本目录用同一 Python 环境和单线程 BLAS 执行，依次为：

1. 执行 python verify_sources.py 校验冻结来源与地图隔离。两份 features.npz 可直接使用。重建时分别执行 python data.py native 与 python data.py ladder。天梯原件优先读本地回放缓存，缓存不存在时按 Git blob 的固定身份读取仓内归档。
2. 执行 python fit.py 训练主头，python collision_extension.py 重建跨队支付及其补充头。evaluation.json 和 map_metrics.json.gz 收录预测、常数与距离对照及分席、分地图和分报名名结果。collision_audit.json.gz 留有真实受损工人、赢家、格子及金额。
3. 执行 python input_audit.py 和 python return_context.py 重算时序隔离、公开方法等价性、逐根例子和回库条件表。
4. 执行 python commercial.py 重算保留整队动作的比较。商业根原始的两方命令、收益与零干预项见 commercial.json.gz。商业协议与其纯读带修订均保留。复算使用官方己席观察，避免 100.0/100 的字节表示差异，并先冻结母带前缀、隔离官方解释器共享工号序列，防止干预改变下一个根的身份。
