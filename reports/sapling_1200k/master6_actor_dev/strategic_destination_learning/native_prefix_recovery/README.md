## 重建方法

1. 正常加载并初始化固定字节的原版。用训练源的官方裁判、双方实际历史动作、每步双方真实时间余额复现盘面，逐拍核对公开输入摘要。第零步走原版公开入口，取得该次自然生成的 MT19937 状态，将行动意图和四个成本值修回归档记录。导入时照常构建并暖好两个后端。首用配置和几何缓存可用同一配置的原版单步模拟预热一次。
2. 此后每过一个历史步骤，把该席公开观察交给原版 BeliefTracker，推进己方根决策随机流，再用该席真实发出的命令更新工人预计目的地，保存上拍完整 players。温度 1 的原版对每个己方基地和每个己方活工各调用一次带概率的 RandomState.choice，调用发生在资金、占位和 go_home 规则处理之前。使用同一 MT19937 连续取相同个数的均匀值会将内部状态推进到同一位置。真实源码的搜索情景另按步号、席位、模拟序号建立局部随机流。测试覆盖了零概率、概率完全集中、无工人、不同基地数及带缓存的高斯状态，960 个合成步骤、5,200 次加权选择均精确复现完整 MT19937 状态。[恢复函数](recover.py) · [随机流对照程序](check_rng.py) · [对照结果](rng_contract.json)
3. 逐拍使用归档的四项实测成本（两项平滑值及两项最近值）。在双方第一次真实分歧处保存同一份恢复后的状态，此后让两臂在各自的新局面上走完整原版公开入口。真实历史比赛的私有初始熵未归档；这里恢复的是一次新配对续弈共用的随机历史。不知道的历史分支不能从动作日志倒推。缺少成本、实发令或公开观察哈希时，该路径缺少等价依据。[既有慢速回放的历史修正](../midgame_economic_policy/native_response/run.py)

两种恢复在六个比对点都核了 Belief 全部字段（含每格历史、可见性、上步树及工人、last_dest）、上一步 players、完整本方随机状态、四项成本、几何与规则缓存、Python／NumPy／Torch 环境 RNG 及静态推理权重身份。两个步骤中自然影子命令与实际归档命令不同，均以实际命令对齐。原来只重放 Belief 与 prev 的做法没有推进根随机状态；原有末步研究从单独登记好的根随机流出发，处理的是另一种实验条件。[历史 Belief 回放](../../own_search_bridge_dev/teacher_window_dev/run.py) · [末步随机流与成对恢复](../../endgame_queue_dev/native_last.py)

考场计数器、模拟器最后一次模拟的税收诊断和被跳过的 CPU 计时无法借此重造。它们在这版源码中用于报告；新分支单独记录计数增量，历史引用原始收据。分支采样与深度受真实墙钟影响。中盘根两臂虽然都搜索 19 个候选、深度 2 且返回同令，但耗时分别为 0.648、0.449 秒，下一步测量成本因此已分化。完整强度评估继续从开局逐拍调用原版。这里没有更改在跑的四根试验、原版代码、正式考场或任何已登记的比较口径。[原版状态与时钟边界](../../cargo_tree_action_learning_dev/native_actor_corpus/league_policy/native_return_intake/live_curriculum/inprocess_snapshot/original_state.py)
