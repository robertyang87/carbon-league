# Sapling 在 513 的胜局和败局，究竟改了哪些命令？

对地图 621758513 已结束的两场 BC 对原版 Master3s2，把同一拍的完整公开请求分别交给四个独立持久入口。原 BC 在双席 **598/598 拍**都原样重现考场联合令。实验逐拍校验公开观察的 SHA，包含真实剩余时间；两台模拟器按原票据的双方实际命令推进，每拍现金与官方终分均吻合。以下两场在结果公布后选取。[官方整场结算](../hosted/settlement.json) · [比较口径](protocol.json) · [实现](compare.py)

## 胜局的交仓命令相同，三步前的路线不同

席 0 终分为 **10,441.92 比 10,423.86，赢 18.06**。第 291 步开始前落后 38.08 分。44 号工人在 175 格携货 352.2765，向上进 160 仓；47 号在 49 格携货 126.8943，向下进 64 仓，共到账 479.1708。原 BC、父代和两种去 Sapling 权重对照，在这两名工人的交仓指令上完全一致。本方当拍另有树收入和夺树支出，净涨 467.22，对手涨 0.74，推进后领先 428.40。

**真正可区分模型的动作在第 288 步。** 47 号工人当时在 20 格携货 126.8943，BC 选左，父代和两种消融都选下。同一拍 48 号种植工在 86 格空载，BC 选右，另外三者均选下。两套整队命令恰有这两处差别。真实轨迹中 47 号经 19、34、49 格后进 64 仓。其他路线后续能否按时交货，须由响应对手的独立分支判断。第 291 步原 BC 与父代在**整队**上也相同；去掉 Sapling 权重后另有四个单位改令，均不是 44 和 47 号。在此之前十步，本方和对手的全队在途货分别为 773.23 和 724.05，距交仓三步时分别为 1,160.63 和 599.79。[胜局逐拍对照](seat0.json.gz) · [实名命令和窗口](pivots.json)

## 败局在对方进仓前已失掉一步封堵的距离

席 1 终分为 **7,991.70 比 9,112.90，输 1,121.20**。第 239 步，BC、父代和两种消融的**本方整支队命令均相同**。原版 43 号从 145 格向下进 160 仓，到账 256.434，连同地租使对方现金增加 278.22。本方只有地租收入 8.76，分差从 +29.31 变为 −240.15，此后再未领先。出令时本方离 160 格最近的采集工是 172 格的 51 号，仍有四格路程。

此前 10/5/3 步，本方和对方在途货分别为 348.46/769.43、253.24/635.16、271.16/791.53。第 230、233 步本方 45 号采集工在 BC 分别左移、下移，父代两次都停留。这些是更早出现的策略分歧；原轨迹本身不能证明任何一个改法能拦下 43 号或改变胜负。[败局逐拍对照](seat1.json.gz) · [双方现金、货与实际行动](key_events.json)

## 两套神经网对整局产生的动作差异

| 同局面整队比较 | 胜席 0，不同拍 / 299 | 败席 1，不同拍 / 299 | 不同单位令，采集 / 种植 / 基地 |
|---|---:|---:|---:|
| BC 对原父代 8da4 | 109 | 107 | 174 / 78 / 7 |
| BC 对伙伴 1.00、Sapling 0 | 94 | 94 | 146 / 84 / 7 |
| BC 对伙伴 0.75、Sapling 0 | 92 | 96 | 147 / 84 / 7 |
| 1.00/0 对 0.75/0 | 12 | 8 | 21 / 0 / 0 |

原权重比为自有 it50 0.75、Sapling 0.25。1.00/0 重用以前的消融定义，0.75/0 仅拿掉 Sapling 的加数，固定 it50 和返航修正的尺度。两种消融始终计算原 Sapling 前向，其加数乘零。每个版本都在自己的自由前缀上重解码全部单位，保留原有整队仲裁。一个单位的命令变化可以来自前面单位先选了另一条令，并不代表该单位的独立神经评分翻转。

胜席 BC 与父代的五个基地令分歧，其中有四次 BC 实际成功招种植工，合计支付 **120**。败席两次此类招工实付 **60**，一个不同令的种植工当拍支付 **53.42**，两个不同令的采集工当拍共交入 **114.45**。这些是改令单位在原轨迹上的实际现金科目；替代令的收入与成本未作结算。完整分类亦给出两种消融比较的实际到账与支出。[全量角色与现金分类](result.json)

两张原始票的 BC 公开请求 P95 为 32.68 / 32.08 ms，最慢 85.67 / 83.70 ms，双方各场 BC 均为零慢步、零超时。本地复演为单 CPU 的顺序公开入口调用，各版本的负载与时钟单独存储；这里的整场胜负仅指原始两张票。
