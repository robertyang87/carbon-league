# Sapling 修改网络权重后，历史实发队令还有多少概率？

原版 Master3s2 对阵中采集的 **24 条训练轨迹，在已量化的 Sapling 子包下整条概率均为零**。这组原始轨迹不能用整局重要性加权估计子包的胜率或分差。共有六张训练图，每图两席、每席两次自然采样。这些局只在父包上实打过，本次只在本地重放已有档案。

| 实算项目 | 结果 |
|---|---:|
| 历史父包 → 更新骨干后的子包（SHA-256 前缀） | `851c901a` → `da9919ad` |
| 首个实发队令在子包概率为零的步号（step 0 起） | 最早 4，中位 22，最晚 38 |
| 首次归零发生于普通确定性拍 / 预定抽样拍 | 23 局 / 1 局 |
| 实算公共局面 / 历史档案总局面 | 556 / 7,176 |
| 实算前缀中预定抽样拍数 / 父包与历史 logp 最大绝对误差 | 23 / 0 |
| 前缀上出现子包给父包零概率命令分配正概率的局数 | 24/24 |

**为什么大量普通步也要验？** 历史采样器只在 12 个预定拍给两条队令抽样的机会，普通拍自由解码后执行唯一命令。换网络权重会改变普通拍的唯一命令。例如训练图 621758464 席 0、draw_a 的第 4 步，父包让 worker-0 原地停留，子包令其向左。该局历史实发队令的条件概率当拍从 1 变成 0。另一个例子是图 621758465 席 1、draw_a 的第 12 步，两名工人同时向右的历史实发令在父包中有 43.52% 概率，子包只会发「上、右」或「上、上」。两个包在物理动作上的选择已经改变。

**如何计算。** 程序校验训练清单、两个单文件包、ZIP、注册、逐拍档案和收据的 SHA-256。逐步恢复官方环境并核对该席行动前公开观测哈希。程序调用两个最终包的自由解码路径，在各自部署抽样点枚举真实分布，按单位身份和最终物理命令归并概率（省略与显式 NONE 等价）。环境推进使用原始双方实发命令。每张地图的两个席位和两趟自然采样全部保留。

这里的轨迹权重是考生在所录历史上的条件动作概率乘积。考官、平台墙钟与环境没有重新采样。对每个历史实发命令计算 `q_new(a_t|h_t) / p_old(a_t|h_t)`。在首次出现分子为零时，完整乘积已确定为零，余下各拍不再复算。24 条整局权重之和为零，自归一化估计及其 ESS 的分母均为零。24 条前缀还都直接观察到子包支持集中存在历史父包不会选择的队令。现有数据可用于识别部署分歧或训练模仿策略，进一步比较子包对手响应和胜负需要在其真实行为分布上取得证据。普通 PPO 使用逐步比值，不能把此处的整路径结论直接解释成每一个局部更新都无效。固定同一候选菜单只调抽样概率的对照另见 [order_reranker](../../cargo_tree_action_learning_dev/native_actor_corpus/league_policy/native_return_intake/order_reranker/)。

**复算。** 本次使用 Python 3.12.14、NumPy 1.26.4 和 zlib 1.3.2。安装仓内官方游戏环境后，在本目录执行以下命令。缓存逐局绑定程序、档案和两个包的哈希。若作为整局重加权的前置检查，追加 `--require-recorded-overlap`。对这批实测数据该开关在写完证据后按预期以状态码 1 退出。

```bash
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 \
  python likelihood.py --work /tmp/sapling-physical-likelihood
```

[result.json](result.json) 给出总表及全部首零步号。[prefixes.json.gz](prefixes.json.gz) 保留每条检验前缀的旧/新实发 logp、首次零概率和首次新支持的完整队令及概率，JSON 的 null 表示 log(0) 或未定义的 ESS。历史实战与训练身份见 [训练清单](../../cargo_tree_action_learning_dev/native_actor_corpus/league_policy/native_return_intake/hosted/training_manifest.json)。
