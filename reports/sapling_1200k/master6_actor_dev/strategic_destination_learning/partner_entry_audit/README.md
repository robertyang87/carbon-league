# 自有 it50 的守卫与 Sapling 的实际改令

在已曝光的开发地图 **621758346** 上逐步复演双方换席，得到 598 个真实行动前局面。完整 it50 入口仅关闭破产守卫，两席都产生了完全相同的整队物理指令。该图不支持另开一条守卫修复线。旧 8da4 的行为差异可以追到 Sapling 混合评分和已有的返航加分两项。[预先固定的对照](protocol.json) · [逐步实令](commands.json.gz)

| 在同一个己席公开局面比较整队令 | 席 0 不同拍数 / 299 | 席 1 不同拍数 / 299 |
|---|---:|---:|
| 原生产 it50 与只关闭破产守卫的生产入口 | 0 | 0 |
| 原生产 it50 与在同一前缀实际计算 Sapling、系数为零的生产入口 | 0 | 0 |
| 原生产 it50 与归档 8da4 | 118 | 137 |
| 8da4 与把其中的策略混合从 75/25 改为 100/0、保留返航加分 | 104 | 136 |
| 在旧 100/0 入口上，再把返航加分归零 | 36 | 35 |
| 关闭守卫的生产 it50 与旧 100/0 且返航加分归零 | 0 | 0 |

有些局面同时受两项干预影响，归因行不能相加。在 240 个 Sapling 混合评分实际改令的局面里，两席合计 305 个工人指令及 5 个基地指令发生变化。在纯伙伴下关闭返航加分影响了 75 个工人指令。零系数入口真实运行了 598 次 Sapling 前向和 6,569 个活跃槽，学生独立最高分动作在 2,342 个槽与伙伴不同；乘零后不改变生产入口的命令。诊断使用独立的前缀对象承接实际生效的前序动作，以免多次调用有状态的特征函数改变本来要测的策略。[源码及 SHA](replay.py)

真实比赛中 8da4 的席 0 终分为 7,145.72 对 8,806.26，席 1 为 8,034.77 对 7,541.14。归档考生平均每步分别 46.10 ms 和 46.56 ms，最大 120.25 ms 和 133.98 ms；原版考官累计公开调用分别 128.43 秒和 129.78 秒，完成八层搜索 241 和 232 拍。这是历史开发环境下的读数。所有对照共用该席历史，正式环境每步只推进原先实际发出的两方命令，双席最终分数均与原始记录相同。其他入口的反事实终分没有采集。[完整计数与时钟绑定](summary.json)
