# 末段采集工同根原版续弈

本目录保存局面级行动差。每组使用同一开发局的同一真实局面、同一焦点工人和两个完整联动指令。根步对手命令采用原局已同时发出的动作。从下一步起，两臂各自调用完整 Master3s2，再以同一个冻结的 Sapling 双网 v1 逐步响应，直到官方环境终局。

* 训练来源冻结于上级 `protocol.json` 的四张地图，每图双席。另四张地图为隔离筛选。每个登记图席只取 t286–296 的首个合法收货或回库替代，保留没有机会的图席。双方局面、成本估计和原版后续局面条件随机流在同根两臂起点一致。每步有 0.58 秒的原版搜索时间设置，真实测时随后可能让模拟深度分化。新流也可能产生与原存档不同的终局。
* `selection_<seed>_<seat>.json` 固定焦点工人、原令和替代令、行动前本席特征、双方可见根状态摘要、根步对手命令和随机流。筛选先重建父策略的完整历史特征和单位前缀，复核根步父令，随后复核全队合法性、基地费用和碰撞保护。
* `{train,held}_<seed>_<seat>/{base,alt}.json.gz` 包含两臂真实后续指令、逐步原版调用、计时、双方行动前可见状态摘要和官方终局计分。`*_account.json.gz` 独立核对时间尚未耗尽时的灭绝、计分、现金变动和交付归属。每笔本金只按该根的实际存量记一次。新开采、运输过程中抢到的货、树税和在终局还未交入基地的货分开算。
* `train_labels.json` 和 `held_labels.json` 逐图席列出两臂及差值，方向统一为替代减父令。每一列是同一行动的不同结果，不能把分差、交付和本金加总。留出运行先锁权重，对保留父令的图席赋零差值。小图样本中的同根收益也不能直接转为整局胜率。

复算环境沿用项目提供的官方规则依赖，原版搜索、NumPy 和 BLAS 在单个原版工位运行。设置 `CARBON_DEBUG=1`，让原版内部异常直接中断。执行顺序为 `python native/run.py train`、`python native/labels.py train`、上层冻结权重、`python native/run.py held`、`python native/labels.py held`。原版驱动要求单线程 BLAS 与绑定 CPU 1，并遵守全局原版续弈锁。
