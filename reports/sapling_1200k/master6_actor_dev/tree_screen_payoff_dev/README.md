# 提前护树是否值得让运货工改道

在已有原版 Master3s2 对局的 21 个合法护树位置上，用同一个 16 拍窗口估计改道的利弊。公开特征包含双方最近采集工、守树距离、敌方现金和上一拍敌种树工动向。分别把亲本命令和护树命令代入相同的失树威胁头，得到两个失树概率；两者之差是模型预测，受原策略出手偏差影响。预期守树收益计为“失树概率下降 ×（双方可能转移的树款 − 对手本会支付的夺树费）”。对护树工另拟合 16 步真实交付金额，根据原令、改令分别估算回库距离、敌方树区、受威胁程度与载货，收益端扣除预计少交付的金额。下一步原令会交货、己方冲突、敌方轻工能到等旧条件继续生效。[估价函数](payoff.py) · [训练代码](fit.py) · [权重](weights.json)

以五张早期地图的 19,469 个采集工时点、12,897 个树时点拟合。另两张已曝光地图上，16 步运货实收的平均绝对误差分别为 41.41、36.85，训练均值对照是 69.53、66.08；单树总吸收金额分别为 5.97、5.54，对照是 17.88、15.68。这些是实际走法的金额预测误差，替换动作的增量误差需要靠响应分支验证。对手夺树后未必一直持有，因此把整段树款视为全部转移也是近似。[按地图误差](metrics.json)

6/21 个位置估计净值为正，3 个来自当前精确父包。以该父包公开入口在对应两份历史上完整运行 598 次，实际改变 t39、t186、t193 三个命令，与离线行动预测逐拍一致。其余 595 拍完整命令等同父包。预测净收益为正的 6 个根中有 1 个只有 +0.02，不能据此当作可实收收益。[全部分数及源包](probe.json) · [候选包及入口核验](parity.json)

已有三对真原版续局均被新规则跳过，其中两次实际直接收益为正。地图 621758328 席 0 的 t148，新闸预测 −16.98；原版两臂在根后 16 拍实收的双边树款净增 69.28，但本方调动工交付少 21.97，合计 +47.31。621758322 的 t246 预测 −17.08，实收 +33.29；621758327 的 t174 预测 −30.00，直接实收差约为零。这些已知反例表明，模型在未改令历史上预测得准，仍可能错误放弃赚钱的动作。[实测收据重建](probe.py)

新响应在两个不同已曝光地图，以固定源顺序取当前父包各自第一条改令。席 1 第 39 步、席 0 第 193 步均让空载采集工靠近目标树。根步沿用原版同时提交的敌令，从下一步恢复双方自然响应。新地图 621758331 的准入条件在这两组续局开跑前登记：两处都提高目标树双边收入、夺树支出及调动工回款的 **16 步合计**，同时两根官方终局分差的增量合计为正，才用候选和父包分别双席开一张开发地图。[预先记录的门槛](protocol.json) · [选根与墙钟](trial.py)

另将确实在两步内失树的观察按“来源轨迹、时点、树号”去重，追到 16 步窗口末尾。训练图 114 个时点中有 14 个随后在窗口内夺回，实际树款合计 89.65% 归对手；另外两张图 116 个时点中有 7 个夺回，90.42% 归对手。后者包含同图重复轨迹和相邻时点，不能解释为独立的 116 次试验。在这些已经失树的时点上，按整段树款 100% 转移来给保树定价一般偏高。[按树逐笔收款与夺回](seized_tree_tenures.json.gz)
