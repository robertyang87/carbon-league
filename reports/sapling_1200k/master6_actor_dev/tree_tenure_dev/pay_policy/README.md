## 实际出令

保留 Sapling 原父包及其共同解码。第 45–125、150–235 步各取**第一个**同时满足下列条件的根，同拍有多个种植工时按其公开 ID 升序。当前格允许新种或夺树，己方同时计划的招工和其他种植工树款预留后仍买得起，没有友军或本拍招工会落在该格，而且真实自回归前缀能给出合法付款和延后两个联合动作。两个动作只允许该种植工不同位。命令选付款，父代本来就要付也用掉本窗名额。全局最多两次，其他时刻沿用原父包。单文件候选 SHA-256 前缀 dd1690c1，包含原父包完整字节。[冻结协议](protocol.json) · [可读规则](overlay.py) · [候选包](candidate.py)

在已完成的 16 张父代开发图两席各复盘一次，64 个窗口均找到机会。早窗 32 个机会中 25 次会改令，触发步介于 45–51；晚窗 32 个机会中 31 次会改令，均在第 150 步。全体 56 个变令分布在 16 张图。每个窗口都在父代事实轨迹上衡量，早窗改令后的真实后继局面没有拿来计算这里的晚窗机会。[全部窗口及共同预算](opportunities.json.gz)

## 当拍会不会真的付钱

同根取实际同时提交的敌令，将父代联合动作与候选动作各推进一次。对 56 次父代本来要走的局面，父代指令让种植工 56 次全部活到下一步。改为原地等待后，16 次付成、种植工存活，树款合计 1,085.03；其余 40 次种植工当拍消失，树款实扣全部为 0。双方都亡的根有 0 个。40 次内，35 次是敌采集工来到目标格，5 次是敌种植工。8 个父代本来就要付的根原样支付，全部兑现。在场上省下树款与丢失种植工是两笔账。[逐个根的父代与付款两臂存活、工种及现金](clearance.json.gz)

在这一批特选时点上，行动前有敌工一步可及对应了这 40 个额外死亡，其余 16 个改令时敌工均不可及。这条后验解释使用的是事后对照，未修改候选。观察到的 40/40 不能当作普遍的到达概率。在新的完整开发对局中，继续按冻结出令、双方换席、全部结果一并计算。[原版调度与断点恢复](native_run.py) · [双支生存及实际树款账目复算](audit_native.py)
