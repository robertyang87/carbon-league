# 载货工遇险时提前一拍回库，能赢 Master3s2 吗？

开发实验只改一条采集工命令。Sapling 与原有搭档先实际推理出联合动作。如果采集工持货至少 80、原定落点三格内有不重于己的敌采集工，而且相邻有队友和招工均未占用的己方基地，就让它立即进库。在同一步多个工满足条件时选择货量最大的一个。地图 621758325、两个席位、候选和父代的四局名单及候选权重先行入仓。考官使用原版 Master3s2 公开入口、温度 1、自然采样和 0.58 秒自适应搜索。[冻结方案](protocol.json) · [单文件候选](candidate.py) · [开发地图核查](clearance.json)

## 哪些货实际上需要抢救

在三张已用开发图上，对包含双方换席的六局原版动作逐拍重放。15 个可改令时点，父代全都由原工把货送进了自己的基地，距原决定的中位数仅一拍。取每个席位最晚出现的一个机会，固定双方根步的考官动作，然后让原版自由响应到正式终局。席 0 提前交付 228.54，父代下一拍交 248.15。席 1 提前交 89.68，父代下一拍交 107.42。两次提前入库后的整局分差分别改善 54.21、43.86，四条续弈全部落败。后续有自然采样与墙钟波动，每个根仅一个配对，无法据此估计平均收益。[全机会追踪](historical_settlement.json) · [四条原版续弈](ledger.json)

另有两起确实把至少 80 货物转给敌方采集工的碰撞。第一起 t297 被抢 117.22，原工从 t287 到 t294 连续八拍距库四格。第二起 t296 被抢 148.81，t292 开始返航，t293 又折回。逐拍记录保留了碰撞前十步双方的工号、货量、地块、现金与真实指令。前一类样本适合检查过早回库的机会成本，后一类适合检查护货启动得是否太晚。[实际失货前十步](loss_trails.json.gz)

## 分差在哪一段拉开

此前六局父代在 t100 的平均现金分差约为 +55。t100–149 平均丢 473 分，其中交付差 −310、树收入差 −325，较少的种植支出抵消了部分差距。t250–298 六局分差全部恶化，平均又丢 630 分，其中交付差 −596，树收入差 +83。t285 时本方采集工平均在途 452，考官 632；从此到终局本方平均交付 678，考官 1,033。交付包含后续新采的货。这六局只覆盖三张图，不能把这些均值推广为天梯参数。[分段现金账](development_periods.json) · [在途库存与随后真实交付](historical_endgame.json.gz)

Master5s 索引补录三场，其中一场已在旧索引并集中，其他索引另增一场前五选手出场。已按对局身份去重并校验地图与本次开发图不相交。Master5s 输给 it910 的一局尤其值得保留。截止 t274 的十步内，Master5s 自己交付 1,177，对手交付 330，现金分差向它移动 970，最后仍以 6,133.59 对 6,304.25 落败。单次交付高峰不能替代整局取胜证据。四场的两席现金流水每一步都与回放核对，并保存了最大转折前 3、5、10 步的双方动作与收入归因。[索引去重](intake_check.json) · [逐拍流水与指令](ladder_cash.json.gz)
