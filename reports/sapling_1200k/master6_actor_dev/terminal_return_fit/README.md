# 用原版 Master3s2 的终局回报更新采集策略

父代是 `416cc31b…`，推理使用原有两套网络和 75/25 logit 混合。在每个采集工的当前合法动作上，加一个四参数分数。参数起点为零。学习器只从训练图的四个官方终局分数取信号，Master6 示范、本方中途存入和额外交战奖励都不进入更新。[冻结方案](protocol.json) · [初始检查点与可重建包哈希](initial_checkpoint.json)

每个候选动作的四项输入均在本席出令时可得。第一项取决于携货、当前命令是否到库、靠近基地的步数和离终局的时间。第二项度量下一格遭更轻敌工碰撞、被围及树耗对当前货物的风险。第三项评估可能截住的更重敌货，按己货、安全格、队友占位和剩余回程折减。第四项估计能安全采集且还来得及回库的机会，扣除树耗。原继续解码及反事实继续解码各自用完整前缀，双方编码器在每步只算一次。若改动连带改变种植工或招工，或新引入友军碰撞与招工冲突，则恢复整套父代动作。[采集特征和联合决策](runtime.py) · [单文件组装](build.py)

## 两张地图分别回答什么

训练图 621461120 上，以已冻结方向 `[1, -1, 1, 1]` 向两边各扰动 0.65，正负两臂各换席打两局。官方分差和由分差、胜负组成的 U 共同构成终局奖励 J。两个席位等权，沿同一方向做一次有限差分更新并保存参数。四局只能估计这个参数组合沿一个方向的效果；各个因素的单独贡献无法识别。原版搜索与温度 1 采样保留，地图和席位配对，考官随机流未受控。退步、零更新及灭绝局均纳入记录。[训练入口与目标公式](trial.py)

候选形成并冻结后，在另一张开发图 621461220 上独立跑父子各两席；届时分别列原始胜负、分差、U 和席位配对差。若零更新，记账并跳过两个相同臂的重复对局。判据为平均配对分差提高且两席 U 均提高。两张地图都排除在以后正式考试范围。即使这张开发图两席获胜，跨地图九成胜率与平均分差 +500 仍需新图正式考试验证。[地图注册](map_allocation.json) · [地形及既有训练历史核查](map_clearance.json)

## 开赛前验证和成本

在既有开发图 621458920 两席复播时，零残差 598/598 步所有动作逐项吻合父代实录。每 25 步取一次事先固定的根，双席共 24 根。正扰动在 4 根、负扰动在 2 根发出不同采集命令，均保持其他角色原指令、更新后各槽合法且不新增己方冲突。经构造验证，调转两臂回报会调转更新方向，两臂回报相等得到严格零更新。单网和双网的参数均没有在本试验中改写。[真实根机制收据](mechanism.json) · [学习器构造验证](test_trial.py)

原双网在最近一张原版开发图的两个完整对局分别用时 161.3 和 162.0 秒。此次机制复验里，零残差完整 agent 均值 48.1 毫秒，扰动的编码和两路解码在取样根上的均值分别为 52.0 与 54.0 毫秒，后者未含构造当前观察特征的时间。按原双网实场粗估，四场训练约 0.18 worker 小时，四场开发另约 0.18 worker 小时，加上回放核验。本轮真实成本以每局 `wall_seconds` 为准。[父代历史实测](../hybrid_candidate/results.json)

```bash
dir=reports/sapling_1200k/master6_actor_dev/terminal_return_fit
python -m unittest discover -s "$dir" -p test_trial.py
# 调度者在不同CPU、已冻结地图上安排两臂
python "$dir/trial.py" run plus --cpus 0 1
python "$dir/trial.py" run minus --cpus 2 3
python "$dir/trial.py" fit
# learned_checkpoint.json 确认有更新后验证父子
python "$dir/trial.py" run parent --cpus 0 1
python "$dir/trial.py" run learned --cpus 2 3
python "$dir/trial.py" evaluate
```

两阶段各自保存逐局实录与官方解释器回放。训练更新产物为 `learned_checkpoint.json`，含四个训练终局、输入哈希、四个参数与精确单包哈希。开发验收产物为 `development.json`；训练代码只接口读取 `train_plus/` 和 `train_minus/`，不会使用留图结果更新参数。
