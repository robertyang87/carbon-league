# 原版 Master3s2 的考官出招怎样受墙钟影响

同一个真实局面、同一份公开历史、相同起始成本和随机状态下，给原版考官的核心加一个同优先级计算进程，8 个局面中有 6 个的实际联合命令同时区别于两次空闲重测。空闲条件下重复两次也有 3 个局面的命令不同。原版的 0.58 秒单步预算、0.85 预算占用比例、1.3 成本安全倍数与策略温度 1 均按本尊原码执行。[预注册](protocol.json) · [运行程序](run.py) · [机器可读结果](results.json)

八个根来自两张已用于研究的原版对局地图，涵盖考官的两个物理座位和第 24 到 285 步。每组的 A、B 是两次空闲调用，C 为单个忙进程和考官固定在同一核的调用。三种条件轮换先后，全部走公开 agent 入口；每种条件只执行一次、全数保留。下表列出各条件返回的候选数、最深完成深度，以及中止或提前收轮的次数。根收据保存了每个候选的完成深度、实际联合命令、选择编号、输入状态摘要和完整计时。

平均最深完成深度从 A 的 7.125、B 的 7.375 降至 C 的 3.25。空闲调用合计 16 次，中止 0 次；同核争用调用 8 次，中止 4 次。考官实际消耗的进程 CPU 时间均值依次为 0.469、0.439、0.277 秒，入口墙钟为 0.469、0.445、0.507 秒。C 条件的忙进程每次消耗了 0.214–0.261 秒进程 CPU。第 73 步两次空闲调用本身完成至 4 层和 8 层，竞争调用完成至 6 层，低于整个样本的平均深度并不能预测每个具体局面的行动变化。

每个根先用官方解释器逐步重放母局，并从考官物理席的可见观察与实际命令恢复其信念跟踪器。旧母局没保存各步的四格成本估计，因此先用一份已登记的真实成本记录，调用同一原版处理根前一步，再将得到的四格成本完整复制给三种条件。信念按原局真实出令恢复。本次为诊断预先固定了每个根的随机状态，同时保留温度 1 和默认搜索参数。这里无法复现历史赛事当时的随机流与机器负载。

测量使用 AMD EPYC 9V74 同一逻辑核 3，BLAS 单线程，两种负载最多占这一核。开测前检查同一 cgroup 的实际 CPU 消耗与其他任务在核 3 的占用。第 144 步的一次空闲调用期间，共用 cgroup 的节流计数增加 249,473 微秒，因此“空闲”只表示该条件没有人为加入竞争者。样本覆盖两张图的一档人工竞争，只说明这一负载能改变本机考官的搜索与实际出招。定位历史考试中的影响还需要当时记录的逐局搜索、计时和负载，已有赛果保持其原始含义。
