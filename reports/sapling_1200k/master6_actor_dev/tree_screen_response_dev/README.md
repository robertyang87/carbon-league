# 提前一拍护树能否改变原版 Master3s2 的决策

18 条原版自然对局的回放显示，敌方有钱的种植工已经站在己方树上时，若一格以内有友方采集工，它 190 次全部撤出。测试据此把保树动作提前一拍：敌种植工从远处接近、距离己树只剩一格，本方原令没有采集工覆盖树，且一名距离两格的采集工有唯一安全路线可进入相邻格，才替换这名工人的命令。原动作将兑现载货回款时放弃干预。观察中只有 7/21 次公开触发后对手真的上树。部署包仅用己席行动前历史，不读取敌方当步动作或未来是否上树。[触发机会及失败例](../tactical_exchange_dev/README.md) · [单文件候选](candidate.py)

三张已曝光的开发图，各做一次单步替换和一次原令对照。根步保留对手真实同时命令，从下一拍开始，各臂均让同一 Sapling 父包和完整原版考官按各自新局面自由决策。该设计测单次干预；没有在两臂后续额外重复护树。首根取对方确实上树的首个合格例；另两个对照分别取第一个公开触发、以及相同父包在另一地图席 1 的首个确实上树例。选根不使用其后比分。程序在三个根前全部可见历史上复播实际部署包，五次变更逐个吻合。[同输入部署核验](parity.json)

每个根的两臂共用冻结前缀和初始随机流，分别绑核。考官使用原版公开入口、温度 1、0.58 秒自适应预算；三对每臂分别有 150、52、124 次重新调用。原令/护树的原生截止次数为 7/5、1/2、1/0，全部保留。官方解释器与 FastCarbon 复播全部终分。

开新图的条件在前两个根出分后、第三根仍运行时写定，含两处有敌工上树的根都必须推迟失树。第二处父代也保住了树，所以本版不进整场，预留的开发图 621758329 未使用。该条件限定的是本轮是否值得扩大开场，不能用作正式的统计推断。下一步要区分“敌工能上树”与“若无人去守，敌工会留下”；还要估计调离运货工的损失。[登记与时间口径](protocol.json) · [判定读数](gate.json)

## 行动前预测敌人会不会在两拍内拿走树

以 674 个较早开发图中的敌种植工临近己树时点训练两个逻辑回归头。标签取两次真实联合推进后的树归属，包含敌工虚晃未上树的局面。两个头都使用双方公开工人位置、树龄、可见的上一笔树款、现金和移动历史；第二个头额外读取**己方原计划下令后**有哪些采集工能控制树格。训练和评价按物理地图切分。评价图是本研究中已观察过的两张开发图，不能用作新图强度评估。[特征与训练](threat_fit.py)

在两张留图的 642 个时点中有 118 次失树。用行动前盘面，分图 Brier 误差为 0.1246 和 0.1141；加入己方计划后降低到 0.1226 和 0.1122。用训练失树率当常数为 0.1432 和 0.1591。把范围收窄到部署规则真的可以派人的 15 个时点，真实有 3 次失树，原头预测合计 0.79 次，新头预测合计 2.12 次。新头给真实第 148 步最高风险 19.3%，但次高的第 146 步（18.4%）实际没有失树。仅凭这几个样本还分不清两步是否都值得调走运货工。权重保留作威胁估计，尚未追加考场。[逐根预测与标签](planned_actionable_forecasts.json) · [与原版输入对照](actionable_summary.json) · [模型权重](planned_threat_model.json)
