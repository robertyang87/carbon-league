# Sapling 用自有小网做八步同时行动搜索

**在 4 张预先分开的历史地图上，八步搜索挑出的种植工动作比始终采用原动作平均多 26.08 分，一步搜索少 35.32 分。八步挑出的 16 段真实原版续局仍全部告负。** 这给了一个可以接入现役 Sapling 的搜索选令器。现有数据支持在种植决策上继续检验，尚未显示整局胜率跃升。[冻结判据](protocol.json) · [64 对同根原版终局](root_scores.json.gz) · [按图结果](screen.json)

## 哪些权重可实际使用

冻结搜索设计时，远端 main 为 `d944673f`。随后权重核查推进到 `3d0e0537`。自有 Echo4 it20、PPO it40/45/50 可以实际加载。没有找到与登记大小、身份吻合的 PPO-U it55 制品，两个本机 PPO it4 检查点来自另一条训练。Apex fix3 的两个载荷逐字等同 Master3s2，本仓的历史 abF 也调用考官策略与搜索。它们的比分均不能算作 Sapling 的能力。[权重逐项核验](weights_audit/README.md) · [内容身份记录](weights_audit/identity.json)

原版 `65f268b2` 开启搜索，但文件内未定义可选的 `_ROLL`，中间模拟步仍使用实际大网，并调用价值头。原版的共同随机数和分级筛选值得借鉴。这个实验独立拟合一份便宜的续弈策略，避开考官权重，也留下了要测量的新误差。旧 Sapling D1 完成 1,048 轮 H1 比较，在 1,196 步仅改过 4 次命令。[原版静态与运行路径核验](master_algorithm/README.md) · [旧 D1 和 abF 的实际投入与结果](master_algorithm/prior_arms.md)

## 续弈网与动作比较

- 取 6 张早期 Sapling 开发图换席后的**我方真实动作**监督 1,530 参数 MLP。另 2 张图换席仅检查拟合。比赛回放中的历史联合行动只用于复原局面，敌方当步命令及考官参数都不作为监督。训练混合了几代自有策略，不能当作对 Master3s2 的精确对手模型。
- 每个行动分数取自公共地图、工人状态、目标格及同队已经选定的前缀。新网络与生产前缀共用预算、占位和合法性计算。两张行为留图上，8,242 次采集工决策命中 74.2%，2,595 次种植工决策命中 56.6%，461 次基地决策命中 56.6%。[分组、哈希及输入清单](fit.json) · [真实训练权重](rollout.npz)
- 从我方公开历史估计隐碳，为对手重建其能看见的格子。每一组根动作共享两条扰动流，每个流先在共同的行动前局面抽取一次敌令。两条分支随后按各自变化后的局面重新决策。评分用当前现金，加上携货除以一加到本方最近基地的距离。若抵达规则终局则改用官方结算。该近似叶未给尚存树和未兑现的远期产能加估值。H1 和 H8 在同两条路径上取分，唯一区别是向前看多少步。[训练、模拟与读回程序](bridge.py)
- 64 个根来自既有 16 张图的真身续局，每张图各有 4 个可选根，每个根只有两份完整原版终局。把原令或另一个完整联令交给搜索比较之后，才用对应原版分支的结算评价选令。原版曾首拍采取的行动、未来回复和终局分差均不进入搜索估值。这里的待选联令来自旧父代，且所有干预都只改一个种植工。当前 Sapling 正常入口的检验单列。

八步所选在留图逐图分别为 +238.89、−374.67、+185.74、+54.37。第二张图上 4 次均换令，真实终局全部恶化。4 张图有放回枚举所得均值的 2.5% 至 97.5% 分位为 [−234.57,+212.32]。留图上父代与 H8 所选择分支均为 0 胜，前六批中父代选择 2 段胜局，H8 只选中 1 段。根后真实结局来自一次既有随机续局，且未实际把多个干预串成一局。两个种植窗口以外的拦截、护货和采集都未在这里认证。

## 在现役包上如何使用

入口保留已冻结的开局修正 Sapling 与 75% Echo4＋25% Sapling 实际联合解码。两段时间窗为 t45–125 和 t150–235，每窗至多比较第一组实际付得起、无新增占位冲突、仅一名种植工有差别的两份完整合法联令。用同一双网在真正变动的先前指令上重解码，留地与移开均由模型比较。其余时间直接返回父代。拟启动时已超过 0.45 秒则跳过，完成时已到 0.80 秒则返回父代。同步 NumPy 调用可能耗过内部时限，这两条回退本身不保证平台达标。[入口检查协议](entry_protocol.json) · [单文件重建程序](build.py)

从仓根可以重建该候选。其神经权重由仓内开局模型构建器和本目录的续弈器生成。重建器只在隔离的临时目录写入开局模型的阶段回执。部署不需要 PyTorch。

```bash
python reports/sapling_1200k/master6_actor_dev/own_search_bridge_dev/build.py --out /tmp/sapling-self-rollout.py
```

## 冻结包的实际出令与失败条件

同一份最终包为 **6,117,410 字节**，SHA-256 为 `7cbc89a2c26fc9dac67468765e93bb3fbca0d78cc936f08b91f72e0a5fa71b3e`。从仓内源码与权重在单独目录重新生成，得到逐字相同的文件。公开入口连续处理 3 张旧开发图换席的 6 条完整局史，共 1,794 次正式形状观测，每次都与独立加载的完整无搜父包比较。三图与续弈训练、行为检查、64 个原版干预根以及另线正运行的 8 图，均按物理地形核对没有重叠。这里只重放既有局史，现场没有开新赛。[冻结身份](release.json) · [逐条机会、实际命令与地形清查](qualification.json.gz)

| 检验 | 最终包结果 | 失败如何判读 |
|---|---|---|
| 正常入口能实际换令 | 6 条局史的两个窗口共 12 次比较，11 次在内部时限内完成，实际改变 5 次。6 条局史分别改 1、1、2、0、0、1 次。基准动作在 1,794 次均与独立父代吻合。 | 出现不合法命令、未完成比较仍改令、或在无搜索处偏离父代，均使接线验收失败。归入父代的超时回退仍计入机会分母。 |
| Sapling 确实影响实令 | 保持搜索、PPO 伙伴与公开历史，单独将 Sapling 的合成权重置零，910/1,794 次最终整队命令改变。六场各自第一条证据都在没有搜索机会时出现。 | 消融从未改变执行命令时，不能把成绩归给 Sapling。910 是作用覆盖数，不能解释成 910 次正收益。 |
