# Master3s2 搜索究竟调用了哪些网络

**冻结的原版没有附带单独的 rollout 小网。** 源码含主策略 `_WEIGHTS` 和评论家头 `_VALUE` 两个权重载荷。虽然 `_S_ROLL=True`，但原文件没有任何给 `_ROLL` 赋值的语句。初始化先设 `_RNET=_NET`，随后只有存在 `_ROLL` 才会构建小网。独立提取原 `_net()`、仅替换数值后端的测试只观察到一次带评论家的构建，rollout 和大网是同一对象，状态栏写入 `the same`。本次读取对象为 Git blob `9c46f6fa`、SHA-256 `65f268b2…`。该结论限于以原文件直接加载的对象。[原源码](https://github.com/robertyang87/carbon-league/blob/d944673f8c6487cb4cd9ff10a001cc61735d157c/sources/master3s2/master3s2.py#L1124) · [字段、形状、调度及可复验工件](source_facts.json) · [独立检查](audit.py)

## 一次调用的数据流

1. **先计算受保护的实际根动作。** 物理席维护自己的碳图信念，使用可观测工人、树和上一步实际发送的命令归因。主策略读 54 平面和固定风格，输出每格工人的五个、基地的三个分数。真实根的温度为 1，每局行为 RNG 自然初始化。基地先招，工人按概率和落点冲突仲裁；强制返航优先。最终发出的动作写回信念跟踪器。[信念更新](https://github.com/robertyang87/carbon-league/blob/d944673f8c6487cb4cd9ff10a001cc61735d157c/sources/master3s2/master3s2.py#L205) · [行动入口与落点仲裁](https://github.com/robertyang87/carbon-league/blob/d944673f8c6487cb4cd9ff10a001cc61735d157c/sources/master3s2/master3s2.py#L571)
2. **从策略提案生成互异的完整联合命令。** 第零候选恒为实际根动作，最多 32 个。算法按温度 2.5、1、3.5、单工偏离、5 的顺序限额采样，只有工人分数随温度变，基地也会重新采样。单工偏离只替换一个工人并排除占用目的地。各候选固定原先被强制返航的工人。同一步对手策略在根估计的碳图上先产生动作，按 rollout 编号共享给所有己方候选；它不会看到本次己方候选。[生成菜单与根部共享响应](https://github.com/robertyang87/carbon-league/blob/d944673f8c6487cb4cd9ff10a001cc61735d157c/sources/master3s2/master3s2.py#L1252)
3. **用估计的世界推进双方，在每层评分。** 搜索以根的碳估计作为完整隐状态，内部编码将 known mask 全设为一。后续双方在各候选产生的状态上重新采样，各自的随机流按深度、rollout 编号、物理角色固定。主骨干每个实际求值的未终止深度都参加计算。当前原包将己方和对手的行合批，己方值由大骨干的空间隐层经专用评论家头得出。评论家拼接全局均值、最大值和五个经济标量，再将预测增量加在当前现金差/3000 上。把该头直接挂到 Sapling 的 GRU 隐态，输入的含义和形状都对不上。[价值头](https://github.com/robertyang87/carbon-league/blob/d944673f8c6487cb4cd9ff10a001cc61735d157c/sources/master3s2/master3s2.py#L1003) · [两席批处理与中间层值](https://github.com/robertyang87/carbon-league/blob/d944673f8c6487cb4cd9ff10a001cc61735d157c/sources/master3s2/master3s2.py#L1330)
4. **逐层筛选并控制用时。** 在 H=1 和 H=4 分别保留相对初始候选数 1/2、1/4，至少留两项，并始终保留根原动作。H=8 是所求的环境推进深度。原版 `M=MMAX=1`，每个候选只有一条情景路径。若中途遇到预算门，可以根据最近一次已评分的层在仍存活的候选中择优；替换要求严格超过根原动作，数值差门槛为 0。按源码 `_plan`，K=4 的理想 H8 计划计 32 网络行、14 次后续模拟推进、9 批推理；K=32 为 192 行、80 次、10 批。构造每个候选的首次根转移、提案与根部网络开销另外发生。实际截止从公开入口计 0.58 秒，批处理和剪枝使“每根需要几次大网”不能只由候选数乘深度推算。[时间规划器和常数](https://github.com/robertyang87/carbon-league/blob/d944673f8c6487cb4cd9ff10a001cc61735d157c/sources/master3s2/master3s2.py#L975) · [预算中断与最终择优](https://github.com/robertyang87/carbon-league/blob/d944673f8c6487cb4cd9ff10a001cc61735d157c/sources/master3s2/master3s2.py#L1406)
5. **搜索内部的终局尺度有适用边界。** 内部 `over` 只检查步数超过 298，评分为 `clip(现金差/3000, −2.5, 2.5)+0.5·sign(现金差)`。在内部搜索里没有按平台提前灭绝执行完整结算，也没有把分数转换成仓内的复合 U。因此顶尖玩家的树上排序可以借鉴；我们的真终局标签仍应调用权威计分，灭绝时还需要存活侧的推进前现金。[内部终局实现](https://github.com/robertyang87/carbon-league/blob/d944673f8c6487cb4cd9ff10a001cc61735d157c/sources/master3s2/master3s2.py#L1409) · [我方终局函数](../../../../../code/stage0_teacher.py)

## 自有桥接能做到哪一步

不直接调用原文件的 `_search`。原文件载入时已解析主策略，`_search` 通过全局 `_net` 取得考官主策略与价值，内部 `_sample` 假设两个覆盖整张棋盘的动作张量。我们现役双网按实际前序花费、工位和落点逐槽解码；若只换根原动作或塞进这两个张量，结果仍依赖考官，且新前缀下的动作条件可能失真。可独立实现的部分是完整命令比较、共享敌方响应、同层评分和成本规划；模拟器沿用自有 FastCarbon。分支须各自复制双方可用观察历史与实体编号，模拟隐状态可来自己席信念，策略输入只取各分支可见的公开信息。训练项目已有按镜像轨道抽未知碳以及逐候选共用情景的实现。[先前 D1 及 abF 对照](prior_arms.md) · [已有公开信念与终局工具](../../../../../code/stage0_teacher.py) · [自有联合动作前缀](../../../../../code/cnet2_feat.py)

本次已冻结的最小区分是**相同的两个真实候选、同一批对手响应随机数、同一叶定义，在自有轻量续弈器上比较 H1 和 H8**。蒸馏的标签来自我方实际提交的命令。对手由同一自有模型预测，这是可检验的误差来源。先复算历史同根真实终局，记录在哪些根改变选择、分别使己方多赚多少和对手多赚多少，并对四张保留图单列。将考官未来实际命令用于这一排序会令测量失效。[冻结方案](../protocol.json)

这批 64 根全为种植决策，且训练轻量续弈器的多个我方父代与现行 91e10203 并非同一演员。即使 H8 胜过 H1，能支持的也仅是这类历史种植根的筛选能力。要挂到当前模型，还需在真实晚段采集和护货冲突上，用实际部署包的命令和第二候选，先测新的有效换令、同席响应收益和 1.5 核/512 MiB 逐局资源开销。既有整队评分器在四个留图的 28 对真实动作上所得分差 −39.65，也说明不能用观察到的短期收入替代敌我双方的终局差。[真实动作评分反例](../../joint_response_critic_dev/README.md)
