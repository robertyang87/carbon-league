# 在同一真实进程回到同一个决策点

在已曝光训练图 621758460 的席 0、第 12 步，851c901a 对同一工人的两条合法整队命令分别把它派向下、向上，概率为 0.632826 和 0.367174。先签发第一条推进 3 拍，将裁判与两个真实代理恢复到原处，再签发第二条推进 3 拍。每个分支都消耗学生自然抽签流中的同一个抽数，只干预这一拍实际发出的完整命令。两条动作带随后分别从同一快照通过官方规则重放，6 次转移的双席公开观察、完整棋盘及编号计数全部吻合。最后再次回到原处，三方状态摘要与实验前一致。[事前协议](protocol.json) · [逐拍证据](receipt.json)

裁判快照覆盖官方状态、历史引用、日志、编号生成器和双方时钟余额。原版考官还原隐藏碳跟踪、实际上一拍命令的内部落点、原版 RNG、滑动搜索成本、遥测、配置对象身份及会影响下一拍的缓存。Sapling 还原双网络推理缓存、全部特征历史与掩码、抽样流、路由和计数。真值只在裁判和证据侧。模型静态权重通过字节签名约束。Linux 调度、绝对墙钟、硬件缓存与分配器不会随决策快照倒转。[裁判接口](official_state.py) · [考官审计](original_state.json) · [学生审计](student_state_audit.json)

**本夹具只认证机制。** 完整前缀 12 次及两个分支各 3 次原版公开调用均触发真实 0.58 秒自适应搜索，但每次只有两个根候选，完成深度均为 0。没有终局标签、胜率或对强搜索的收益结论。旧观察器曾意外拒绝合法的零深截止，本夹具保留了该失败，并明确识别零深、多候选正深与单候选三类。[失败记录](observer_failure.json)

可复用的同进程入口为 `fixture.LivePosition(env, original, student, clockbank)` 和 `restore()`。每次恢复返回新的双席时钟余额，随后用 `student_state.act_with_choice` 在真正支持的动作处签发两令。原版从原模块驻留内存的同一实例继续，不能把该接口作为跨机器或跨版本的快照格式。单次实验的代码 SHA 写在收据中。原版模块后续增加了可重算的源码审计入口，核心状态对照见考官审计。[驱动代码](fixture.py)
