# Sapling 原版回报训练留图对照

本轮用两张未用于训练的开发图检验一个问题：在同样的生产采样方式下，更新网络权重后，Sapling 对仓内原版 Master3s2 的官方终局表现有没有改善。原版温度为 1，搜索保留 0.58 秒自适应墙钟。每场从冷启动开始，双方使用自然采样。

| 地图种子 | Sapling 席 0 | Sapling 席 1 |
| --- | --- | --- |
| 621758470 | 父代、候选 | 候选、父代 |
| 621758471 | 候选、父代 | 父代、候选 |

每格在同一台机器、相同物理 CPU 集合上串行执行两场。四格共八场。父代单文件 SHA-256 为 `851c901aa561ce80bf04d03e7c2a8e7876bfa2f24dc6c57ffe22b501979320ee`。候选须通过父目录 `learning.json` 登记的训练，并使用与父代相同的采样及执行代码。独立正式考试另有 100 张图。

## 冻结与开场

1. 在已签收训练结果的工作区运行 `python validation/preflight.py`。它检查训练选择、四个双场作业、重复曝光拦截和零曝光恢复；只使用合成数据。
2. 维护者从 main 读回训练提交、`fit.json` 和实际导出的 `candidate.py`。仅在 `training_mechanism_pass` 时从父目录执行以下命令。它复核训练与主干的提交关系、24 条原版完整对局收据、实际部署权重、四个量化候选步长、跨席行为变化和两图隔离，然后写出本目录的 `release.json`、`protocol.json`、`matrix.sha256`。

   ```sh
   python validation/matrix.py bind --training-commit "$training_commit" --candidate-sha "$package_sha256" --fit-sha "$fit_sha256"
   ```
3. 维护者将实际生成的三项冻结文件入库并从 main 读回，才可手动启动 `sapling-native-return-validation.yml`，传入该次 `protocol.json` 的 SHA-256。工作流只接受 main 的首个 attempt。每次先检查本实验所有历史运行；纯配置或检出故障只有在整批均未进入对局，或逐票回执确认两边启动次数、动作数全为零时才可恢复。一旦有票曝光或无法确认，保留原始收据，停止重发。
4. 工作流在独立容器对每方实际施加 1.5 核与 512 MiB，计入进程冷启、step 0、请求通信、逐步耗时，以及原版搜索的实际深度和回退。所有超时、灭绝、平局和失败均须保留。

## 读回

`merge.py` 从 GitHub 核验独立作业包和提交，重放官方计分，并由 `menu.py` 用父、子两个实际单文件逐拍验证采样动作支持。输出列两席全部胜平负、官方终分、四个同图同席的分差变化，以及两张图各自的双席平均。没有官方分数的超时保留判负并留空分差。每格两臂独立自然采样，两张图只能支持开发判断。它们的结果都不计入正式 200 局目标。
