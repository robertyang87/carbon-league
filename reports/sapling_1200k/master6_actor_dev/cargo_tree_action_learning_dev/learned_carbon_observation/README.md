## 输入与训练

模型只修正本席从未直接观察、当前也没有基地或树的格。采集者可见脚下，种植者可见四邻，零碳的可见格也算已见。第 0 步无工人，母体在基地为零，其余格的初值为 11。座席 1 在编码前把物理位置 `r*15+c` 映到 `r*15+14-c`。模型在当前公开历史上取 44 个量，包括四邻摘要、开局镜像轨道中最近一次直见碳量和时间、树木邻接、工人占位，以及母体从双方公开载货变化中记录的首次原地采集量和时间。镜像位置在开局之后可以有完全不同的地面碳。[推理代码](runtime.py)

单隐层共享权重网络有 32 个 ReLU 单元、1,473 个可训练数值。修正后的碳量按母体的 `uint8(round(clip(carbon/100)*255))` 打包，送入 Sapling 的第 0 平面。其余 32 张空间图、标量、令牌和 75% 权重的自有 it50 编码输入都使用原数据。两个分支仍共用母体的前缀特征。直接可见的 4,343 格和曾经见过的 50,237 个暗格，三个方案的估计逐格相同。[打包实现](package.py)

10 个旧训练地形产生 39,274 个可修正格次。网络和标量对照均使用这批格、同一顺序、相同的 18 次遍历和同一平滑绝对误差目标。每张地图都重放已存的联合动作，按步构造双方各自能获得的观测；模拟器的当前真实地面碳只进入训练标签或评分。所有原始动作带均核了文件摘要、开局物理碳图和终局双边现金。登记后没有按留图选择模型。三个留图针对本次新增估计器独立；原始母体开发曾使用这些地形。13 张实图与 1,553 张已登记天梯地形、母体的原验证/测试组及已列首胜和 343–355 保留图做了物理哈希比对。[预登记](protocol.json) · [训练记录](fit.json) · [地形核验](source_clearance.json)

## 经济目标排序

只比较历史实令前缀之后可选、经济上有意义的目标。采集者以非树非基地的目标格为准，种植者以可负担空地的四邻均值为准。下表要求采集目标当下隐藏，种植目标至少一邻当下隐藏。仅在真值可分的对上计排序正确率，预测并列计半分。估计最高项并列时均匀选取，列中的损失是真实最佳目标与其平均真值之差，单位为碳。[逐机会打分](rank_rows.json.gz)

| 角色 | 真值可分的比较对 | 两项以上的机会 | 母体 / 对照 / 学生正确率 | 母体 / 对照 / 学生选点损失 |
|---|---:|---:|---:|---:|
| 采集 | 7,991 | 2,058 | 99.08% / 99.08% / 99.35% | 0.404 / 0.403 / 0.201 |
| 种植 | 2,436 | 550 | 98.07% / 98.03% / 98.99% | 0.178 / 0.205 / 0.106 |

把范围收窄到至少一个目标会读取可修正格时，采集者的选点损失从 2.857 降至 1.420，种植者从 0.867 降至 0.514。三幅地形中有一处反向结果，621476120 地形种植者的选点损失从 0.009 增至 0.105。全样本采集者对局部可分目标的估计并列率从 0.538% 降至 0.400%，种植者从 0.164% 降至 0.123%。这些目标分数直接衡量地面碳，完整策略还会考虑载货、行动威胁与经济开支。[按图及角色的全部指标](heldout.json)

## 公开入口的实际决策与耗时

三张留图均从第 0 步按固定历史动作带连续重放，对母体和学生分别调用真正的公开入口。双方各 299 步，每个包共 1,794 次决策。19,730 个可控槽中，有 17 条指令发生变化，分布在 16 个回合视角，其中 11 条来自采集者、6 条来自种植者。[首张留图完整入口核验](normal_summary.json) · [另两张留图实令](other_held_actions.json)

| 留出地形 | 比较的回合视角 | 可控槽 | 改令回合 | 变更指令 |
|---|---:|---:|---:|---:|
| 621471120 | 598 | 6,647 | 7 | 8 |
| 621477121 | 598 | 6,492 | 5 | 5 |
| 621476120 | 598 | 6,591 | 4 | 4 |

首张图上，标量仅改变 1 条指令。学生对母体的变化包括物理席 0 第 61 步，采集者从向下改为向右，种植者从向下改为向左。598 个回合视角中，479 个回合视角的学生碳平面发生变化。对三包另开进程做的 1,794 次带检测调用，全部复现各自普通入口实令，伙伴编码输入及输出、共享前缀的起始输入以及其余通道均逐字节比对通过。相同历史上的动作对照能说明模型实际影响决策，比赛得分需要双方根据新动作继续出招才能测出。[逐步动作与不变式](normal_entry.json.gz)

本地 Python 3.12.14、NumPy 1.26.4，独立进程固定一个核心和一个 BLAS 线程。学生外部逐步计时含 JSON 往返，598 次调用中位 42.05 ms、P95 52.16 ms、P99 69.49 ms、最大 290.23 ms，慢于 1 秒的调用数为零，峰值常驻内存 90,140 KiB。与母体按相同输入配对的耗时增量中位数为 0.43 ms。本地宿主 cgroup 配额为 4 核、内存上限 16 GiB；正式天梯 1.5 核、512 MiB 的托管计时需单列。[执行环境与原始分位数](normal_summary.json)

## 复现

在本目录使用项目的 Python 环境，固定为单线程 BLAS，执行 `verify_sources.py`、`fit.py`、`package.py`、`evaluate.py`、`verify_entry.py --cpu <core>`、`verify_more_terrains.py --cpu <core>`。训练可用 CPU PyTorch，两个自包含提交文件在推理时使用 NumPy。学生包为 6,086,621 字节，比母体增加 11,036 字节。[学生包](candidate.py) · [标量对照](constant.py) · [字节数及 SHA-256](packages.json)
