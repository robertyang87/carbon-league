## 怎样核验

1. 两臂各自从对应物理地图、官方配置和同一份完整历史联合动作初始化。官方解释器有进程级实体编号计数器，必须先将一臂独立重放到终局，再初始化另一臂。
2. 对每条注册动作序列先核输入 SHA 和登记身份，再核各步执行指令。窗口实验从替代臂自己的对照计算读取原父代动作，而单步实验从冻结登记表读取两份候选动作。只比较清除显式 NONE 后的实际物理单位及基地命令。
3. 对两席官方观测（含全图真值、各席可见碳、单位及树）、状态和奖励取规范化哈希，直到两臂中较早的终局。这里只做赛后审计。墙钟计数另存，不参与棋盘等价判断。单步 t 指看到步前局面的时刻，动作 t 的效果最早出现在局面 t+1。
4. 标记“同根同敌令”须同时满足此前所有联合动作相等、此前无官方局面分歧、两臂在首次暴露仍存活且当前状态相等、当步敌令相等，以及两臂本方实际不同且实时父代臂的指令等于替代臂的父代对照。连续窗口的后续干预仍然包含在终局差里。无实际改令、当时另一臂已终止和同拍双边异令各自单列。
5. 两条后缀继续独立回放至各自官方终止，逐座比对已归档奖励。分差统一取本席减敌席，再取替代臂减父代臂。所有成绩按登记呈现，零深警示不能筛局或调权。

在仓库虚拟环境运行 `python audit.py --group windows --output windows.json.gz` 得到八行。参数 `--group signed` 复算旧的 signed_roots 合集，`--group all` 合并两组输出。复用于有两条真实分支的新窗口时用 `--manifest MY_PAIRS.json --output audit.json.gz`。清单格式为 `{"cases":[...]}`，每行含 `case, seed, seat, start, last, terrain, source, source_sha256, parent, parent_sha256, alternate, alternate_sha256`。路径相对仓根，注册窗口包含首尾步，terrain 是初始物理图 SHA-256。每臂提供完整 `joint_tape, original_calls, official_scores, statuses, comparisons`；两臂比较项均须有 `t, parent, student`。用完整反事实窗口会逐步核对写入的动作与两臂当时的影子输出。[复算程序](audit.py)

## 已冻结对手根令的历史单步资料

`joint_response_critic_dev/signed_roots.json.gz` 中的 108 个登记根分布在 18 张物理图上，包含地租分析的全部 66 个根。216 条后缀的官方两席终分均与收据完全一致，所有首次改令都满足此前完整联合前缀一致、同一官方根状态且考官根令相同。这些根用的是历史已录得的同一条敌令，原版由下一步开始重新响应。相对于封存的父代动作，108 条替代指令的终局分差有 58 次改善、50 次恶化。各根共用物理图，且每个动作每根只有一条终局后缀；这个计数不能换算为整局胜率。旧格式仅统一核验到原版调用数，本表将逐步零深字段保留为空。包含全部旧胜负与输入文件校验和。[108 根的逐根证据](signed.json.gz)
