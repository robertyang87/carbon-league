# 首胜包的 OpenBLAS 线程继承

地图 621758345 席 1，第 0–31 步，每个版本各用一个新启动的持久进程。父进程都传入 OPENBLAS_NUM_THREADS=4。在 1 个允许的 CPU 上，原包的 OpenBLAS getter 已经读到 1。在 2 个允许的 CPU 上，原包实读 2，新增一行的包装实读 1。四次运行分别 32/32 步与实战出令相同，包括第 0 步的双基地招募。所有调用均低于 1 秒，没有初始化失败或内存失败。

| 2、3 | 强制单线程 | 1 | 45.8 | 54.2 | 185.2 | 90.6 | 1.81 |

**处置。** 保留强制单线程包作为可复现的包装备选，已测首胜包和四席完整计时证据继续绑定原 SHA。双核条件下备选的 P95 和最大耗时较低，但逐根配对仅 15/32 步更快，且两臂各只有一次进程运行、顺序固定。现有读数不足以认定稳定加速或要求替换已赢一局的版本。32 步一致也不能外推全部局面或实战胜率。

新增的一行在首次导入 NumPy 前覆盖 OPENBLAS_NUM_THREADS；build.py 断言父包 SHA，重建包为 6,075,626 字节，权重字节与全部决策逻辑原样保留。检测发生在干净 Python 3.12.16 进程中，未预载 NumPy。原包 8da4b465…，备选 934e277e…；预加载数值库的其他宿主不能凭这行保证改变既有线程池。端到端计时包含序列化、Docker IPC 和返回值解析，主控在 CPU3。两臂进程均设 512 MiB RLIMIT_AS，本机实际 cgroup 限制与天梯不同。
