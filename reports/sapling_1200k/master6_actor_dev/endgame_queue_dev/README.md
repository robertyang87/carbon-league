以 621475120 为例，父代原令让三名工人同时送入 357.78。新令让携带 59.95 的工人多留一拍，另两人先入 297.83。该工脚下当时可见碳 48.90，最近敌工距它 4 格；多停一拍后，它下拍携 74.62 回库。四局中 7 名留守工在行动前距离最近敌工为 4–7 格。621476120 有一名脚下碳为零的工人随同改变，25.87 是联合动作的增量，不能把它平均归功于两名工人的采集。四处都没有库外拦截，修改也没有新增同步进仓；其中三个局面调整的是本来就会合流的工人。[逐局各席分项](root_audit.json.gz)

用完整父包在改后的最后局面重新解码，四处的己方期初现金加上末拍由己方载货工明确送往己库的货，较相应参照分别多 30.6147、14.6702、25.8720、12.6914。默认移动费和熔炼费都是零；在己库同格碰撞，唯一最轻采集工获货后入库，平手则双方都死、货直接计入库主现金。两种路径都只记一次，敌方也可能通过自己的新决策改变自己的得分。三种代理在原令分支上分别有 5、3、5 局的绝对终分偏离原局。另有 8 项官方/快速引擎构局覆盖敌工进入、基地招工、两步树税、最后一工死亡和灭绝奖励。[真实父网重新出令](v1_last_reply.py) · [结算测试](home_settlement_test.py)

## 与前次试验的关系

已有末手分析在父代错过一条清晰回库路时独立改一名工人，并统计真实同队同库碰撞。旧近赢分支另外检验过 H5–12 的单工早回和单格截运，但拒绝新增友军目的格冲突。本项事前联合生成两拍路线，并把双方的终局现金都计入选择；结果把“基地合流已会”和“安全相邻时尚可多采一拍”分开。原版 Master3s2 自身也在末段解码时显式允许采集工同库，它并不把每种同格都当作应避免的碰撞。[旧末手和同库统计](../../../master_family/tactical_rules/detail/endgame.py) · [旧近赢续弈](../../planter_routes_dev/endgame_responses/README.md) · [旧跨图单工分支](../../late_response_training/README.md)

## 完整原版在改后局面怎样出招

对评价组所有四个改令根做了有限配对。第 297 拍使用双方同时提交的原版考官指令，本方分别执行原令与已冻改令。第 298 拍分别在两条真实后继公开盘面运行完整原版 Master3s2，重建 0 至 297 拍的观察、工人路线与其已执行指令。每根用一份事前从系统熵生成并封存的原版温度 1 随机状态，两臂共用，搜索成本从同一实测历史校准值起步。旧场没有保存末拍随机/计时缓存，因而新配对测的是本次明确记录的响应流。八次调用都完成搜索，各自比较 2 个候选、深度 1、1 次 rollout，零中止；在 08 整批签收后使用同一核，共耗墙钟 6.95 秒。[原版协议](native_protocol.json) · [配对结果与八条原始命令的哈希](native_result.json)

在 621474120/席0 和 621475120/席1，考官看见不同后继后改变了末拍实令。四对中考官的最终现金均相同，本方增加的 83.85 全由自身现金实收。计入其余 12 个原令相同的位置，两席分别为平均分差 +3.83 和 +6.66，所有 8 图 16 席 ΔU 为 +0.0004703。该批四对两臂各自 0 胜，最接近的一对从输 371.79 变成输 357.12。四次干预每根只有一个共同随机流，对新图/其他对手的结论仍须独立样本。末两拍的敌库外截击在 56 个公开根中没有一次满足几何条件，未产生任何拒付收益。[逐席时点](study_results.json) · [原版真实末拍](native_result.json)
