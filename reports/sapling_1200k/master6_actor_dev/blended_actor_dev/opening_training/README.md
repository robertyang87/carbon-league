# Sapling 的首轮招工修复

**保留上一版融合候选的采集策略，把首轮的双采集工修回 Master6 示范的一采一种。** 共享的 291 个 FP32 参数只对第 0 步的基地命令生效。10 张验证图、18 张留图和另列的 18 张已曝光败图均逐基地还原了示范；对同一给定历史的另外 506 个实际局面，完整团队命令逐项等于原融合候选。该修复尚无对仓内原版 Master3s2 的终局收益实测。[公开入口核验](normal_entry.json.gz) · [冻结判据](protocol.json)

## 从首轮的实令学到了什么

原融合训练的 2,048 个样本里只有 8 个首拍，对训练外 Master6 的 28 张图均招出了两个采集工。我们重新从缓存核验了 218 张训练图的第 0 步，含 128 局席 0、90 局席 1，覆盖 51 个报名对手、213 胜、4 负、1 平。每席保留当时合法的三个基地命令、下一个基地见到的剩余预算和位序、物理格与规范化格、实际提交的工种及次帧确认的出生格与工种。输入仅取行动前可见状态，次帧出生用于核账。[逐地图逐基地档](panel.json.gz) · [可重建的公开张量](roots.npz) · [原训练抽样](../../blended_actor_arena/opening_coverage.json)

218 张训练图全都在规范化第一基地招采集工、第二基地招种植工。28 张独立于训练的地图以及另列 18 张旧败图，也都使用同一顺序。开局可见碳格为零，两基地几何对称；合规规范化网络输入只有一种。这里有 264 个不同真实地形、528 个核实的基地命令，但只有一种网络可区分的首轮状态。训练集的常见顺序单独作基准，命中率同样是 100%。这些示范能确定 Master6 在此规则下的首轮习惯，对于改变开局信息或价格后应招什么还没有标签。[可见特征、不同整队命令与机会分母](panel.json.gz)

## 神经更新和同图关停对照

从刚测完的 75% Echo4 it20＋25% Sapling 包 `85c47d5d` 出发，冻结两网全部已有参数。给 Sapling 基地解码的 96 维隐藏状态添加一个共享的三动作线性残差，总共 96×3＋3 个数。两个基地共用一组参数，按实际已选的前序命令、余钱和合法动作逐个解码。模型没有基地 ID、座位、种子或写死工种的条件分支。按图、基地槽和真实示范工种加权训练，218 张训练图全量进入每批，18 次优化后达到预先登记的训练内停止条件；验证图和留图未参与选步。[训练器](train_opening.py) · [完整训练轨迹](fit.json) · [增量权重](opening_weights.npz)

## 哪些原版比赛可以用于回答收益

现有开发场确有四对同图同席首令。各自从真实初盘推进一拍，可见两种招工都真实扣款 60，首轮后本方工种构成不同。该资料把第一拍的命令和扣款固定住了；之后用的是两个不同模型，考官后续自然墙钟搜索和采样也各自演进。原融合候选的四局 0 胜、平均官方分差 −1,761.56，较早双网为 0 胜、−2,192.34。这组差异无法归给首轮招工。审阅以 `85c47d5d` 身份登记的对局、首次分叉的官方复演及旧招工对照后，没有找到已经把两种首令分开，随后双方使用同一个 `85c47d5d` 对原版打到终局的配对。旧招工试验只检查第 8–170 步且未产生真实改令。[原开发赛](../../blended_actor_arena/RESULTS.md) · [首令固定敌方的一拍复演](../../blended_actor_arena/first_split.json.gz) · [先前招工残差](../../workforce_policy/README.md)

## 重建可运行比赛包

本目录保存 1,670 字节的增量权重和构包器。由已入仓的 6 MB 双网包重建出的完整单文件为 **6,082,576 字节**，SHA-256 为 `91e10203615a40f368119883a0d9dcf1d42b1962ba4f43bb9534d5eb2e01bdab`。目录中执行以下命令即可得到能直接运行的比赛包。[构包代码](build.py) · [身份凭证](release.json)

```sh
python build.py --out candidate.py
```

训练和机制复现分别使用 `train_opening.py` 与 `evaluate.py`。开发环境下使用仓内所需的 Torch/NumPy，固定单线程；训练入口约束 `nice -n 19 taskset -c 2`。冻结判据通过仅说明模型在这些实际状态上恢复了示范开局。
