# 招工残差已经训练，六条原版轨迹上实际改令为零

冻结的 Sapling v1 与完整原版 Master3s2 在三张开发图换席。v1 共付费招了 205 个采集工、132 个种植工，对手分别为 204、122。值得检查的差别出现在已有至少两名种植工时：第 220 步前 v1 仍增招种植工 64 次，其中 24 人可归属直接净收入为正，合计 **+799.55**；对手增招 39 次，22 人净正，合计 **+2,823.42**。这批人的总收益在两边都为正，训练尝试针对的是继续加招的时机。另两条已归档的 v1 父分支与主样本共享开局，独有后段单列。[逐局招工、工资和树息](baseline.md) · [付费工与持有树逐笔证据](baseline_games.json.gz) · [核正的试验条件](observational_gate.json)

每笔树吸收收益从种树或夺树时起跟随树 ID 和本方持有期；付款种植工阵亡后仍收的钱继续归给原付款者。换主或到龄结束该段记录。八条完整或接续的路径均核至官方终分，未归属树收入为零。对手后来少收的钱、封路和防守价值无法据此归给某个新工人。

## 训练与留出

冻结 v1 双网和工人决策。对三个基地命令学习一个以原版基地 logits 为起点的小分类头。模型包含 37 个可见状态/已发前缀特征、两个可学习的动作列，共 74 个系数，NONE 为参照。输入含现金、工位、现存工种、待扣种树费、基地占位、附近敌工、自己的带货工和将到龄的树。训练保留有工位、付得起时的全部 NONE 标签；地图等权，每三步取一个公开局面。所有 62 张图地形唯一，40 张训练图的 Top5 行动席包括 37 个胜席和 8 个负席；高手互打的同图两席合计占一张图的训练权重。没有使用 Master3s2 的动作、权重或未来收入作为训练标签。[训练程序](train.py) · [权重](weights.json) · [特征定义](features.py)

评价以高手自己此前已选的工人/基地动作作为前缀，测的是给定这个前缀时的招工分布。陌生对手组的六个高手席均为胜席，熟悉对手池的测试含三个负席。V4 历史上把 454 个高手选择中的种植工从实际 81 次过预测到 346 次；本次如实列出三类，陌生对手组出现少预测种工 11 次。[完整留出结果](evaluation.json) · [V4 历史对照](../../TREE_V4_TRAINING.md)

## 部署包实际做了什么

包 SHA-256 为 `8018c516364f488e80ff57c574f57598332e69af2204b9bc8a1832166374fe3a`。候选只在 t8–170、本来打算继续招种工且已有至少两名存活种工时检查。最多修改一座基地一次，须依然负担得起其他已发命令、留得出一次补招费，并在完整重新解码后保留全部其他已选动作。[可运行提交包](agent.py) · [完整构包](build.py) · [原决策与动作保护](runtime.py)

沿实际 v1 历史逐步调用候选包，3 图双席共 1,794 步。六条轨迹在规定窗口内有 57 个合格回合、58 个可检查的原招种工基地决定。安全限制生效前，训练头仍选种工 52 次、改选采工 5 次、改选等待 1 次。以程序的首个拒绝原因为准，51 次继续种工，1 次危险/占位，2 次概率或相对优势不够，4 次现金预留不足。**实际出令与原版 v1 相同 1,794/1,794 步。** [六条逐局覆盖](screen.json) · [58 个准确局面与预测](funnel.json)

例如图 621461220 席 1 第 18 步，模型对改招采集工给出 0.843，此时仅有 35.45 现金。工资 30，剩下 5.45，触发了预先冻结的 30 元备招聘用条件。该例中两种工人的即期工资一样，现金条件限制的是本实验愿意测试的状态。另一个可延期端点出现在同席第 135 步，现金 3,006.34，等待与继续招种工的概率分别为 0.508 和 0.474，相差 0.034，低于冻结的 0.10。

本次保留模型权重和可重建的提交包。按赛前条件至少须有两张不同地图、相反席位的真实首次改令，实际为零，因此发起 **0 场**原版响应试验。本次公开动作拟合的改善尚未产生可测的对战收益，现役 v1 保持原样。[空选根清单](roots.json) · [冻结条件](protocol.json) · [原版响应入口](response.py)
