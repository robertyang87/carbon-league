# Sapling 对 Master3s2 的整局胜率验收

开发场使用地图 620106811 和 620106812，各交换一次席位，每个候选共 4 局。同图同席依次测已发布的 V3 和冻结候选。考官取仓内原版 Master3s2，源码 MD5 为 `57f9a594cce4f2ec9e3573d8d9d26ca1`。考试器将动作提交给模拟器直至权威终局结算，计正式胜平负。若候选提前灭绝，尚未到达的中途快照留空。研究场可以淘汰候选，其中 4 胜也只足以支持继续验证。

## 正式目标和成本

冻结候选 NPZ 和逐字相同的 int8 单文件包；汇总所有训练、调参、曾经考试的已知地图种子。再从保留区间抽 100 个新地图种子，每张图两席，单次完整读数。出场前保存计划、排除清单、抽样 nonce、运行目录名、考官及判分程序摘要。必须登记之后的正式复测，用新的封存图。看过的图永久降为开发图。原版考官具有温度采样和墙钟搜索，同图换席和同一地图上的复跑均可能产生不同轨迹。

- **达成这次考试的 90% 目标**要求至少 180 胜/200 局；和局计入分母。另报席 0/席 1 各自胜局、两席是否分别达到 90/100、分席校正区间、总胜平负、官方终分差和运行错误。例如席 0 全胜、席 1 胜 80 局能达到总体目标，席 1 距单席目标仍差 10 胜。错误或缺失先排查，须保留原始记录及重新运行原因。
- 不确定性按地图聚类。一个地图的两席胜局数可拆为“至少一胜”和“获两胜”两个指示量之和。对这两个地图级概率各作精确 97.5% Clopper–Pearson 双侧区间，再平均两个下界与两个上界；经 Bonferroni 校正得到保守的总体胜率 95% 区间，允许同一地图两席完全相关。这个解释要求不同地图的抽样与对局独立，且运行环境代表目标场景。
- 另报“总体胜率 95% 区间下界达到 90%”这个更强说法。比如一组构造数据中，90 张图双胜、10 张图双败，可达到本场目标，区间约 [81.2%, 95.6%]。
- 在当前双工位上，先用开发场实测每张图的墙钟 `T`，200 局的墙钟估算为 `100 × T`，另计初始化和异常恢复。若每图 150 秒，为约 4.2 小时，占用两个固定 CPU 工位。该估算依赖候选存活时长、真身搜索和并行环境。
- 开发场持续零胜时保留封存区，继续改模型。不要把密集投考零胜模型当成提升胜率的手段。

## 复跑

从仓库根目录运行，使用能够加载本仓 NumPy、PyTorch、fastsim 的 Python 与至少两个可用 CPU。用 `--cpus` 指定本机的两个不同核心。默认选 0 与 1。每个完成的席位立即原子落盘；重新调用同一命令会校验身份并只补缺局。

```sh
python reports/sapling_1200k/tree_v4_exam.py \
  --weights data/weights/sapling_1200k/tree_v4.npz \
  --pack data/weights/sapling_1200k/tree_v4_agent.py \
  --run reports/sapling_1200k/tree_exam_v4
```

正式开场时先将 `known_seeds.json` 整理为已知整数地图种子的 JSON 数组。必须使用已冻结且在开发场验证过的包。以下两个命令是正式考试流程示例，仓内开发场没有消耗这 100 个地图号。

```sh
python reports/sapling_1200k/tree_win_gate.py \
  --weights candidate.npz --pack candidate_agent.py --exclusions known_seeds.json \
  --run final_exam_1 --out final_plan_1.json
python reports/sapling_1200k/tree_win_gate.py run \
  --weights candidate.npz --pack candidate_agent.py --plan final_plan_1.json \
  --run final_exam_1
```

开发场和正式场的 JSON 都绑定实际权重、单文件包和原版对手源码。每局记录终止原因、双方调用和错误、官方比分，以及两个席位在第 60/100/200 步和终局的存款、存活工人、种树、树收入和滞留载货。单步受墙钟约束，运行环境和线程设置须随结果保存。该研究考试在 fastsim 上使用官方终局判分，以相同地图和双方席位作对照。胜率的解释范围为本机配置、这个原版考官和封存地图分布；登记考场或天梯成绩须在那里另测。

正式执行日志逐次追加。候选报错、考官报错或对局数据异常会使整次正式验收失效，保留诊断日志并退役这组地图。外部信号中断可按原命令恢复已持久化的席位。

## 原版搜索与终分留证

V3/V4 开发四局沿用共享旧考试器。它只接受 `searched + single = 已调用步数`；本次两组全部满足。后续 V4r、basecal 与正式验收均按原版每次进入 `_search` 的计数差核账。完整比较、单候选返回、预算耗尽且实际深度为零后回基础动作分列。完整比较中被迫提前截断的步仍计一次完整比较。新考场要求至少有一次真实完成的比较，所有搜索返回均可解释，搜索设置和两方行为同时留证。

每席的 gzip 原件含权重/包身份、动作指令、每步搜索返回、最后一次转移前后现金和灭绝状态、官方终分与错误。先持久化这份原件再验收。无法分类的步或无法证明的调用会使命中该局的正式结果失效；分数和错误仍可读回。当进程恰在写完原件、汇总前中断时，程序保住原件并报告需从该记录恢复，防止重走一次抽样后覆盖已有对局。

V4r 的两个源权重与构建件记录在开发场的 [build_manifest.json](tree_exam_v4r/build_manifest.json)。复核该组合包的开发首图可执行以下命令。应使用新目录，原版考官每场会重新采样。

```sh
python reports/sapling_1200k/tree_pack_arena.py \
  --weights reports/sapling_1200k/tree_exam_v4r/build_manifest.json \
  --pack data/weights/sapling_1200k/tree_v4r_agent.py \
  --pack-sha256 12aeeb3718b62b1271fadea63debb71a9c22454cd61dd97b91aeab59590870e0 \
  --maps 620106811 --run v4r_dev_repeat
```
