# 正式考试的原版 Master3s2 墙钟记录

新冻结的 100 张图、200 个席位沿用原版 0.58 秒预算、温度 1、自然搜索和官方计分。两核按冻结图清单的序号换席。第 0 张图席 0 用第一个核，席 1 用第二个核，第 1 张交换，之后交替。每席在每核各打 50 局，断点只补一个席位时沿用该图原分配。抽图规则与胜率、分差判据见 [正式入口](tree_win_gate.py)。

每局的 `results.json` 行绑定 `native_clock_<seed>_<candidate_seat>.json.gz` 的 SHA-256。收据反向绑定实际动作带、考生包、权重、考官和物理席。单网和复合包均读原考官的公开入口。采样器在原函数返回后读取 `_S_STATS` 的计数与 `last`，记录各步候选数、最深完成层、每番已分配的 rollout 数、是否改令、返回类别、原生日志耗时、公开入口墙钟和进程 CPU 秒。仅一个候选时原码不更新 `last`，该步按一个候选、零层、零 rollout 和空的原生耗时入账。零层回退的 rollout 数沿用考官所报的初始分配数。逐候选记录器 `_S_REC` 保持关闭。

收据汇总分开计算原生 `aborted`、有多个候选而未达到该步可达层数的次数、原生耗时超过 0.58 秒的次数，以及公开入口超过该时长的次数。原码按预测成本决定是否开始下一轮，达到第 4 层后仍可能提前结束并不增加 `aborted`。可达层数取配置最大层数与距终局剩余步数中的较小值。聚合深度是该根完成的最深层，逐个候选的深度不可由该账还原。

考官载入后及本局结束时各采一次主机、CPU 型号、进程与线程亲和性、实际 Torch 并行度、原生线程池及相关环境、cgroup 限额和节流计数。可选的线程池枚举不可用时保留异常原因。进程 CPU 秒属于该 worker，cgroup 计数则包含与它共用配额的其余进程。计时与聚合均不更改原码搜索、出令、种子和奖励。

运行与复核均由 `tree_win_gate.py run` 接入。正式运行根据冻结源码清单强制要求收据；丢文件、换席、换核、逐步和考官累计不符都不能签收。历史冻结按其登记的源码 revision 回放，原有 `verify_raw` 与 `validate_game` 仍可校验旧动作带；旧赛事缺少的计时字段保持未知。回归使用模拟考官与已归档的历史比赛，运行时不抽正式图。
