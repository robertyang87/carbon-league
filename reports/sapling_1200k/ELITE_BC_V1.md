# Sapling 120 万对 Master3s2 · 完整示范训练与生存诊断

## 训练改了什么

从已发布的 1,206,476 参数 sqrt64 权重继续训练。原版只从 4 局规则示范中学习前 120 步。新版输入、网络宽度、推理入口和守卫配置相同。在真实天梯上取 Master5s 与 Master6 的完整比赛，各席均衡，按比赛和地图种子隔离。训练用 12 局、3,588 个局面、39,378 个动作。另留 4 局、1,196 个局面、13,293 个动作，固定最后一次更新作为考生。

每次以行动前该席可见的棋盘、工人历史和本方已下达的动作作为输入，监督目标为下一帧记录的该单位实际指令。训练棋盘编码器和策略解码器，按工种和动作在训练集上的频率作平方根平衡，基地没有招募选项时不给该槽策略梯度。AdamW 更新 320 次，批大小 24，学习率 0.0005。在本次两核 CPU 上从读入数据到训练及留出评估共约 112 秒。价值与辅助头未获终局监督，骨干已随策略改变。详见[样本清单](elite_bc_data.json)、[训练回执](elite_bc_v1_training.json)和[可直接运行的 int8 考生包](../../data/weights/sapling_1200k/elite_bc_v1_agent.py)。

## 独立动作核验

在 4 局留出的 Master5s/Master6 对局上，动作交叉熵从 1.239 降到 0.945。基地有招募选项的 412 次机会里，专家实际招工 246 次，旧版预测招 9 次，新版预测招 292 次。新人更愿意招工，招得是否合算要看比赛中的现金与产出。[训练回执](elite_bc_v1_training.json)

另从仓库取 4 局有 Master3s2 真身参与的公开比赛，两个席位各 2 局，与上述 16 局无比赛或地图种子交集。每局均匀取 20 个行动前局面，只算专家至少有两个合法指令的 751 次选择。给定专家在该步已经下达的动作前缀，旧版命中 307 次，新版命中 453 次。交叉熵由 1.428 降至 1.009。采集工命中 247→368（共 580），种树工 30→53（共 122），基地 30→32（共 49）。这些读数衡量模仿指令，自主对局时前缀由模型自己产生。[逐局、逐工种校验](elite_3s2_agreement.json)

## 为什么另外测灭绝

规则的 300 个状态从 t0 到 t299，走满对应 299 次联合推进。若一方无工、无树，且没有基地或现金低于最便宜的招工价，即触发灭绝。72 的 55 万 sqrt 千局归档可还原 851 局正常结束、149 局提前灭绝。旧 120 万版此前的两图双席小场是 4 局均正常结束，4 局全负。55 万的一例在 t100 仍有 113.67 在途货物，但现金为零，最终在 t202 无工无树、现金 17.74，已经付不起 30 的招工价。[规则实现](../../code/eval_v53.py) · [生存复算](survival_audit_v1.json) · [旧版小场](external_3s2.md)

本次训练的 3,588 个专家局面中，“只剩一名工人、无树、现金低于 30”计数为零。正常经营示范可以教网络少走进这样的局势，最后一工如何自救仍需要学生自己走出的局面和相应监督。

## 救场样本的实际情况

用独立的 4 张训练地图让旧版对内置规则对手走完全局，记录“只剩一工、零树、现金不足 30”的所有局面。4 局里仅 1 局贡献了 143 个这样的根。固定当步其余单位和敌方已实行动作，把最后一工的 5 个合法选择都跑过一次，715 个后继都活过了当步。143 个根在单步生死上没有区分度，故未用它们训练本版权重。

但这个训练对局说明了为什么“活满”容易误导。在第 156–269 步，唯一的空载采集工在基地连续 114 步选择不动，本方现金一直是 14.52，零树。因此下一次若做这类局面的重标，应比较待命、安全出发采收、带货交付在后续多步带来的现金与灭绝风险。只给“存活一回合”奖励，五个动作在这里得分相同。[逐局回执](survival_labels/survival_report.json) · [分支程序](survival_branch_probe.py)

## 复跑

从仓库根目录执行，数据目录、训练产物和评估结果使用新路径。需要 NumPy、PyTorch 和 threadpoolctl。

```bash
python code/build_sapling_elite_bc.py /tmp/sapling-elite-data
python code/sapling_elite_bc.py --manifest /tmp/sapling-elite-data/manifest.json \
  --init data/weights/sapling_1200k/sqrt64.npz --out /tmp/sapling-elite.npz \
  --receipt /tmp/sapling-elite-train.json --device cpu
python reports/sapling_1200k/elite_3s2_agreement.py --out /tmp/sapling-elite-agreement.json
python reports/sapling_1200k/elite_exam.py --arm sqrt64 --out /tmp/sapling-sqrt64-games.json
python reports/sapling_1200k/elite_exam.py --arm elite_bc_v1 --out /tmp/sapling-elite-games.json
```

最后三条默认读取仓内冻结权重。复现实战计时须对两次调用指定同一组可用 CPU，例如附加 `--cpus 0 1`。
