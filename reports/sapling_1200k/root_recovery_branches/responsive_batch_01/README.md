## 如何运行和恢复

批运行器通过计划指定源对局目录、地图、席位、根类型，也可直接指定合法动作。采用 `family: explicit_worker` 时，在该任务条目填写 `preferred_seat`、`root_t`、`worker`、`alternative`，并确保决策步在计划窗口内；`alternative` 可取 `UP/RIGHT/DOWN/LEFT/NONE`。代码检查工人当步归属、行动有效、与其余本方命令不撞格、目标不在敌基地。若需要归因到某一特定树，再提供可追踪的 `tree` ID。[批次执行器](../batch.py)

```sh
export OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 CARBON_DEBUG=1
d=reports/sapling_1200k/root_recovery_branches
python "$d/batch.py" "$d/responsive_batch_01" run-all --cpus 1 2
```

可只给一个可用 CPU，让两臂依次运行。每 25 个根后动作原子保存一次双方动作、根后的原考官随机数与搜索耗时状态、局面现金和进度；中断后重复相同命令，先用截至检查点的真实指令带恢复两方历史，再继续推演。已完成的臂先核身份和指令带哈希，整对完成后用官方解释器独立重放核分。在第一图亲本臂第六次后续搜索后刻意退出并重启，保留其恢复次数用于核查。重新生成新随机起点时应使用新的输出目录和计划文件。[原版续弈与断点实现](../live.py) · [独立官方复验](../live_verify.py)

每根使用一个两臂共享的、从原版配置新抽的 RNG 起点与暖启计时估计；母局原始无种子采样状态和实测耗时没有归档。地图与回放选根先冻结，后续搜索会随分支局面和机器耗时分化。每种动作只有一张开发图，结果用于具体取舍，无法给出胜率或跨地图分布。
