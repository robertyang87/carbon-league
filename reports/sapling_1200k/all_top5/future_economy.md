# 从当时的局面学习未来十步、三十步的经营结果

同一对局、同一决策步、同一行动席位，现在可以分别取出双方随后 10 或 30 个联合步的**实际交付、树收入、采集工生存与重建**。输入继续使用原有的 `Game.decision(t, seat)`。未来结果由独立的 `FutureEconomy(game).labels(t, seat)` 生成。按对局复用一个读取器即可共享内存中的逐步流水。仓内归档的整局、百步、波动段报告保留原用途，任意起点的目标从对应原回放和同一套已逐帧核对的经济记账器重算。[决策输入](context.md) · [离线目标代码](future_economy.py) · [原经济账定义](economy_extract.py)

截至 4bfdabf5 的前三批天梯数据含 1,347 局，802,770 个有真实下一步的席位决策。两方结果在每个决策里分别命名为 `own` 和 `opponent`。同一帧换席时，两组数据精确交换。

| 预测窗 | 有完整目标的席位决策 | 距实际终止不足 H 步 |
|---|---:|---:|
| 10 个联合步 | 778,524 | 24,246 |
| 30 个联合步 | 724,668 | 78,102 |

**555c0c56 补编**增加 10 局、5,582 个席决策。其中一局在第 100 步终止，其余九局打到第 299 步。补编的 10 步完整目标有 5,402 条、截断 180 条；30 步完整目标 5,002 条、截断 580 条。四批累计有 1,357 局、808,352 个席决策。累计 10 步完整／截断为 783,926／24,426，30 步为 729,670／78,682。[补编逐框收据](context_appendix_555c0c56_receipt.json) · [四批累计、逐批分母及标签复核](appendix_555c0c56/future_economy_check.json)

读取器按 `context_*_receipt.json` 查找已登记的补编索引并校验索引 SHA-256。新增补编一经完成背景核验即可识别，未发收据的中间文件不进入训练样本。可用 `--expect-games` 钉住预期总局数。`--out` 用于另存本次收据，默认仅输出到终端。

**窗口从 t 帧落子之前开始**，累计 t→t+1 至 t+H−1→t+H 的现金。若对局恰在 t+H 结算，仍算完整；不足 H 步时 `target=null`，单列 `observed_to_terminal`、实际观察步数和终止类型。最后一帧可见的实际金额为零时原样保留。研究完整窗口应按 `full_horizon` 取样；训练“到步限为止”的任务可以显式消费截断窗口。提前结束可能与局势有关，两组应分别核对。

## 可以学习哪些结果

| 标签 | 逐席含义 |
|---|---|
| `own_collector_delivery` | 由该方自己的采集工成功交入自家基地的净现金，含已经夺来并实际交付的货。直接撞击现金、敌人主动交入、仅留在身上的货各有独立结算。 |
| `tree_absorption` | 该方当时拥有的树实际结算的吸收收入，包含地面碳及对敌方采集工收取的部分。整份沿途抢货不会自动算作树收入。 |
| `collectors_end`、`original_collectors_surviving`、`sole_starting_collector_survived` | 窗口末编制、根上原班采集工中仍活的人数、唯一原采集工是否仍活。根上有零名或多名时，第三项留空。 |
| `first_loss_of_last_collector_offset`、`first_collector_present_again_offset` | 从根起算，第几个结算帧首次从有人变为零人；已经曾有采集工后出现断档，第几个结算帧第一次重新有人。开场从无到有的第一名工人另行区分；若窗口内又断档，以期末编制和最低编制补充观察。 |
| `first_fundable_rehire_after_having_collector_offset` | 已经曾有采集工，后来断档，窗口中首次在仍可行动的帧里有基地、未达工人数上限且能付一名采集工的价格。偏移 0 表示根上就可付。命令是否下达、新工是否熬过同格碰撞，分别以真实后续帧判定。 |
| `cash_end`、`living_trees_end`、`hire_price_end`、`cash_meets_hire_price_end` | 期末能支付的资源和未失去的树。招工价格含全场当帧采集工数带来的涨价。终局仍记录现金和理论价格，实际可再下招工令的字段留空。 |

以 `6fe4eb3c` 第 84 步的席 0 为例。十步开始和结束都只有一个采集工，按原工号追踪，原工在下一步已死，之后一度零人。第五步才有钱补，第六步新工存活。这十步内回库为 **0**，树息为 **38.279175**。只监督期末工人数会漏掉整个停产和恢复过程。另一局 `76a7c94f` 席 1 在第 104 步要求预测 30 步，第 115 步已经终局。可见的 11 步里回库和树息均为 **0**，30 步目标为缺失。[逐值原始证据](future_economy_check.json)

## 取样与复核

```python
from future_economy import FutureEconomy, open_game

game = open_game("6fe4eb3c61132e6736b0ff785d2d2878-1")
reader = FutureEconomy(game)
policy_input = game.decision(84, 0)
targets = reader.labels(84, 0)
```

从该目录也可直接运行下列命令。`--replay-cache` 可指向已经解包的回放目录，每个文件仍按原目录的 SHA-256 和步数核对。默认从 Git 仓内归档读取。

```sh
python future_economy.py 6fe4eb3c61132e6736b0ff785d2d2878-1 84 0 --horizons 10 30 --with-decision
python future_economy_check.py
```

4bfdabf5 版复核在三批里预先列出五局，包含正常终局、提前终局、开局、停产与真实复工。现金以逐步模拟器的结算事件提取，再用相邻公开帧、动作和轻重碰撞规则独立核回库，用树主与逐树收入核树息；工号生死、资金与终止条件由原回放逐帧重数。共逐值检查 108 个“窗口×实际一方”的结果，并检查每个决策换席时双方结果互换。全库覆盖数来自已验证索引。五局抽查覆盖数值正确性，所有局均可按需重算，未重复发布数十万份训练标签。监督目标描述实际双方走法下的结果；将某个候选动作归因为收益仍需分支续局。[复核脚本](future_economy_check.py) · [覆盖与校验收据](future_economy_check.json)

555c0c56 的累计检查保留这五局，并在每个尚无抽检的补编自动选取最短实战作为附加样本。新批选中 `5620f376`（100 步终结），核验开局、第 50／70／90／99 步、两席的 10 与 30 步目标。六局共 128 个窗口×一方逐值通过。
