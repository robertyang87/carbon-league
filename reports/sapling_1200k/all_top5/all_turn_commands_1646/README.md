本目录补齐固定清单中 1,502 场对局的双方完整队令。其余 144 场已有同类窗口，保留在原补编中；两组合并覆盖截至 `e0916a448` 的全部 **1,646 场有双方官方终分的前五比赛**。每局使用相同的回放 SHA 和原经济复盘选定的时刻，机器清单列出已有 144 场对应的文件和新增分片的校验值。另有 1 场只有一方官方终分的执行故障，已单列至正常前缀的最后一拍。[覆盖清单](coverage.json) · [历史故障](../appendix_97de1ebc/unscored/README.md)

16 个新增分片共 19,484,385 字节，覆盖 **3,002 个原始经济窗口、57,220 个去重联合行动、1,235,377 个当时在场的基地或工人指令槽**。其中 439,435 个在场槽在原回放省略发令，另有 24,113 条上一拍存在、本拍已离场的实体记录。两场原账没有持续领先窗口，均保留其最大现金差窗口。[全量独立核验](validation.json) · [独立复核程序](audit.py)

## 按比赛 ID 查阅

以 ID 的第一个十六进制字符定位 `shards/<首字符>.jsonl.gz`。每行是一场对局。先从 `windows` 找窗口的 `start` 和 `end`，再按 `lookback["3"]`、`lookback["5"]`、`lookback["10"]` 找到对应的行动前记录。两段窗口互相覆盖时，同一步只保存一条。若开局不足五步或十步，两种回看分别到真实第 0 步为止。[分片目录](shards/) · [复算程序](extract.py)

- `swing` 取原逐局经济账中绝对现金差变化最大的十步窗口。`decisive` 取最终胜方开始持续保持现金领先附近的既有窗口。原账没有适用的持续领先时段时，该场只列 `swing`。
- `transitions` 每条记录的 `public_before.players` 对两个席位分别给出现金、基地 UID 和位置、工人 UID 与位置/载货/工种、树 UID 与位置/年龄。`public_before.trees` 是当拍规则指定对双方共享的树表。这里的 `t` 指记录里的游戏步号，窗口序列可能有中断。
- `orders_as_recorded` 保留原始联合动作；`orders_all_present` 逐席列出当时每个基地、工人的实际指令。一个在场单位省略发令时记为 `NONE`。`departed_since_previous_by_seat` 单列上一帧存在、本帧已经离场的 UID；第 0 步该列表为空。
- 动作 `t` 的输入来自回放第 `t` 帧，实际发令来自第 `t+1` 帧。`labels_after.cash_by_seat` 是这些指令结算后的双边现金。各个窗口由赛后轨迹挑出，单凭窗口里的动作与现金变化无法判断换一个动作后的终局走向。逐席只可见碳图和更长的当时历史仍可通过原回放的 `(ID, t, seat)` 获取。[按席位还原行动前观测](../context.md)
