# 只改母包实发令中的一名种植工

这次修复了训练标签的归属。给定母包对该局面**实际发出的完整队令**和事前指定的工号，构造器只允许改这名仍存活的己方种植工。母包原来给所有其他工人和基地的命令都排进同一拍。目标工的四个不同备选分别列出，通过或拒绝都有原因。整个过程独立于搜索菜单、模拟深度和预算。[构造器](order.py) · [逐例收据](evidence.json)

## 接入方式

用 `Anchor(public_observation, issued_parent_order, focal_planter, configuration)` 建立一次行动前记录。调用 `candidates()` 得到四个完整备选与拒绝原因，调用 `audit(externally_proposed_order)` 可检查外部搜索命令是否只改指定的一人。所有基地招工指令保持不动，友方落点按环形棋盘计算；空指令和显式 NONE 统一为同一个动作，拒绝越席或未知实体、未知动词。对手同时动作仍有不确定性，能提交的完整备选可能在推进后碰撞、未成树或被夺。

保存正常完整续弈后，再用 `bind_terminal_returns` 绑定训练标签。当前适配仓内 `tree_value_labels` 的收据格式和正常 DONE 或规则内灭绝终止；异常或硬超时需要专门的裁决记录再纳入。核查脚本会重放上表的来源关系与真实冲突证据，全程不开新局。[复核入口](verify.py)
