# 六步回款网络的原版搜索接入检验

本包从 ds-pro-v1 的原始单文件构建。在两张曝光图的 12 个提议根，以及单列的哈基米失货根上，没有一次能把实际改令归因给新网络。独立登记的 24 个旧图根也没有通过。**模型已经接入，当前单文件未显示可重复的实战决策改进。**

## 发布字节与实际工作方式

候选 SHA-256 为 `1cb68dec03649eff89d3ba6656b999d7f6850963f07ca095505aa2e1dbedc35f`，2,922,068 字节，绑定父包 7cf5c6c9、修订后的模型 c756d487 和权重 8afb999b。构建器核对源权重、模型源码与训练登记的散列、数值和张量形状，再把两件嵌进父包。运行不读外部权重，也不加载回放。[候选](candidate.py) · [身份清单](manifest.json)

搜索沿用父策略生成的联合动作及原候选。距己库 1–5 格、持货至少 100、距终局至少 6 拍，且不受原版强制返航保护的自家采集工，按载货降序、同载货按 ID 升序选一名。新网络只用该方行动前可见的当前格碳与公共工人、基地、树和现金估计五种动作的相对六步回款分数。

提出的落点须与当前及父动作相比都不增加到最近己库的距离，也不能与队友最终落点或本方招募冲突。敌基地、有更轻或等重敌采集工能一步到达的格子排除。分数须比父动作高至少 0.05。原始公开请求已用时达到 0.50 秒时放弃新提议。原搜索菜单至少有两个动作、提议确实是新联合动作时，它只替换末尾的非默认项，**实际候选数不增加**。已有相同项时顺序不动。父搜索按相同墙钟和原价值函数选出最终动作。[事前协议](protocol.json) · [物理占位实现](offer.py)

## 三类实证

- **已曝光局面。** 安生 N33 与 Fable v8 两图沿注册步序各查 90 根，基于当拍真实公开输入和固定私有随机得到 16、10 个可提议的根。每图依次取前六个，按协议运行父版、关闭开关的修正版和两份开启调用。共 24 次开启调用，其中 20 次向菜单放入了新联合动作，4 次原菜单已有。新插入项最后被选 **0 次**。当父版与关闭版重复结果相同、两份开启结果也相同，且四臂完成宽度、深度与重复数均一致时，共有 8 个根，均未产生可归因改令。其余根保留墙钟差异，不从中挑一个不同结果充作新头贡献。[公开调用逐根收据](probe.json.gz)
- **哈基米 t174。** 新包覆盖工人 15 所在的距库 5 格。历史真实发令为向下，这次给定私有随机下生成的父网络根动作却已向左；新头也给向左最高分，其他落点未通过几何筛选。这一根没有新提议，不能声称模型已修复那次 423.34 失货。[历史动作](../../ladder/losses_nov20/hajimi_baseline/DIAGNOSIS.md)
- **独立旧图。** 独立登记的 24 个根、96 次真实公开调用中，首次开启时 15 根受几何筛选、7 根分数增量不足、1 根原菜单已有，仅 1 根真正新增。该根四臂均选择已有的第 6 项。没有得到可以归因并送入续弈的改令，未消耗新图开发赛。[独立逐根验收](../development/root_results.json.gz)

## 开销与可用环境

本地 Python 3.12.14、NumPy 1.26.4、单 CPU 亲和。181 次独立提议检查中，新增计算 P95 为 0.38 ms，最大 1.05 ms。包含搜索和动作序列化／反序列化的 26 次开启公开调用，P95 为 0.547 秒、P99 为 0.630 秒、最大 0.658 秒。一次全新进程有 Torch 的候选冷启 2.48 秒，第一步 0.209 秒，整进程峰值 RSS 305,300 KiB。父包与候选在模拟无 Torch 的进程中均可输出动作，但父包的完整搜索自动关闭；本次接入位于该搜索内部，此种运行环境没有新头贡献。以上是开发机探针，不能替代逐局 1.5 核与 512 MiB 平台认证。[冷启与首步](cold_receipt.json)

复算请运行 `build.py --verify`、`contract.py`、`probe.py --cpu <空闲核>`、`cold_probe.py --cpu <空闲核>`。前两项可独立重复。后两项需要仓内三个已曝光的官方回放，实时墙钟下菜单完成深度与原收据可能有差异。旧权重阶段的收据见 [修正前诊断](early_diagnostic/README.md)。
