# 树首次持有期的现金回报能否改善种植工决策

**在 8 张留出图上，用树收益加权使种植工动作预测小幅改善；在 16 个事先选定的实战局面上，它与普通行为克隆生成了相同的搜索菜单，发令完全相同。** 两个学习头各在 1 个局面改变了线上 v2 的最终队令。现有证据能将这次改令归于两个头共有的学习成分。收益加权的独立实战增益仍未测出。此实验没有运行新整局。[留图结果](held.json) · [原生搜索逐次记录](native.json.gz)

从线上 v2（`8b4c4baf`）冻结的 96 维格点特征出发，只在己方根上有种植工的格子叠加五向动作残差。新增 485 个可训练参数，任何方向的原始 logit 改变量限于 ±1.25。采集工、基地、对手和推演中的网络保持原有输出。种植工一旦影响联合菜单和搜索名次，最终也可能连带改变采集工指令。这个实验补充了此前按公开特征估算树回报并向菜单提案的研究。[策略头构建器](package.py) · [收益加权权重](head.npz) · [以前的树价值预测研究](../tree_control_response/README.md)

## 实际经济标签和留图结果

只给真实新种和成功夺树计算标签。首段从扣款开始，到树易主、凋谢或对局结束为止；将实际到账的地租、敌方过路货税及直接记入树主的钱相加，扣掉真实种植或夺树成本。后来夺回同一棵树另起一笔。给同一个种植工的前一、两拍衰减归因，同时每九拍留取一批普通动作作锚点。未选择的位置没有反事实回报，没种成的尝试仅可能落入普通抽样。部署输入由原策略读取同席可见碳、公共信息与该席过去实发令重建，收益与未来命令只用于监督。[地图和训练判据](protocol.json) · [逐树计账](labels.py) · [训练程序](study.py)

训练采用 20 张已结束的天梯图、20 个对手注册 ID，得到 3,335 行真实种植工行动，含 699 次新种和 176 次易主。留出的 8 张图来自另外四个对手家族，各有 v1/v2、席 0/1 数据。所有地形分别归入单一分组。留出共 1,374 行，含 283 次新种、85 次易主、692 行与其后两拍成树或易主关联的实际移动、309 行中性抽样。两头使用相同样本、容量、训练预算与按图等权的目标。在收益加权的对照中，按净额与距离实际扣款的拍数确定权重。先冻结权重 SHA-256 `845e8f23c8c69ca310b9a41cfb42fecf72663a9480b98ed1b0dcaff3ff09421b`，后计算留出标签和比较结果。[训练收据](fit.json) · [每条留出动作及其回报](held_rows.json.gz)

收益加权相对普通克隆的 NLL 差为 −0.00116，8 张图中 5 张改善。按整张图重采样的描述性 95% 区间为 [−0.00364, +0.00099]。赚钱动作的真实指令 log 概率逐图平均增加 0.00307，亏钱动作减少 0.01026。根据这项概率变化对两类实际结算做区分，图内 AUC 的等权均值为 0.630。这个分母只覆盖已经成功新种或易主的位置。[各图、各注册对手与分母](held.json) · [分新种、夺树和行动前两拍](diagnostics.json)

**对赚钱动作的误伤真实存在。** 278 个盈利动作中，较普通克隆有 64 个概率上升、53 个下降、161 个在 10⁻¹⁰ 对数概率容差内不变，首选方向没有一个因这项加权而翻转。90 个亏损动作里仍有 25 个的概率上升。对留出的天梯 Master3s2 那一张图，赚钱动作的平均 log 概率降低 0.00635，亏钱动作上升 0.01692。例如，对 Fable v7 席 1 的 t137，28 号在格 38 原地种树，首段赚 24.09；普通克隆给原地的概率为 0.00521%，收益加权降到 0.00441%，三版的网络首选都是向左。历史完整策略的搜索最终仍然发出了原地动作。[逐例比较及反例](diagnostics.json)

## 是否真正改令

八张图各用身份哈希选出两个当时有己方种植工的决策，选取时不读命令、比分和树收入。冻结同一个动作随机流，每个模型对每根运行两次自然 0.58 秒搜索，再比对相同对手应手、完成深度和工作量。收益加权与普通克隆在 **16/16** 根上菜单和实发队令都相同。两者对 v2 都在 **6/16** 根改变菜单，在 **1/16** 根改变实发。该根是对安生N33，席 0、t235。53 号种植工从右改为下；55 号空载采集工从右改为上，后一变化通过整队搜索发生。v2 与两个头在搜索前的 A0 相同，v2 最终选第 0 个候选，两头都选第 3 个。按父包实际完成的 4 候选、深度 8、1 个情景重复后，父包和两头都逐令复现其自然时钟输出。对这两个新令没有实际终局回报。[自然工作量和缩小菜单的对照](native.json.gz) · [精确匹配父包工作量的复演](native_matched.json.gz)

先按 `register.py` 中固定的仓库快照复算地图清单。使用 Python 3.12、NumPy、SciPy 和 CPU PyTorch，依次执行 `study.py fit`、`study.py held`、`diagnostics.py`、`package.py`。原始回放相对仓库根目录的路径和 SHA-256 在清单中。重运行自然搜索会随实际 CPU 耗时波动；整队结果、原始先验、每臂深度及对手应手以已归档收据为准。[单文件收益加权策略](weighted.py) · [同容量 BC 对照](bc.py) · [机制复算入口](native_probe.py)
