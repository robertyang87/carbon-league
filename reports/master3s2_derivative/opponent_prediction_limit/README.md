# 首拍敌令预测误差能改变多少实发决策

将历史原版 Master3s2 的真实首拍队令代入 v2 的同拍搜索后，**16 根中有 11 根改变我方实发动作**。第 117 拍为 5/8，第 247 拍为 6/8。16 根均匹配候选菜单、搜索前原始动作、完成深度分布和响应次数。v2 当初记录的完整对手指令与本次固定随机流的自然预测仅在 1/16 根吻合。第一拍对手响应足以影响搜索选择，变化能否兑现成收益要用独立对手应手检验。[逐根候选菜单、实发命令与重复运行](roots.json.gz)

## 对照做法

复用先前冻结的四张历史开发图（621758610–613），每图换席，分别检查第 117、247 拍。按原始公开观察与该席位此前真正发出的动作重建信念。每根先按正常 0.58 秒测定 v2 完成的候选数和深度，再固定工作量，轮换自然预测和历史真实首拍响应，两臂各重复两次。自然预测复演逐项恢复原结果，真实命令只代入对手的第一个模拟联合动作。此后对手仍使用同一原版采样流程。所有历史动作从已归档逐拍收据提取，强制工作量的分数及耗时仅用于机制对照。[四图登记和历史收据](../modal_root_opponent/protocol.json) · [复算脚本](probe.py)

## 独立重新应手

固定取第 247 拍发生改令的前两张不同地图。同一局面中，两条续弈共用一次原版考官重新自然采样的根指令，分别执行 v2 先选的指令和离线代入历史敌令后选出的指令。其后双方走各自完整公开入口直至官方终局，考官始终沿用原版 0.58 秒搜索与温度 1。每一组只有一次新根响应和一对续弈，各组的胜负及分差只覆盖原定的开发根。本地用固定逻辑 CPU 和现有共享资源，平台计时资格需以拟部署包另行实测。[筛根规则与哈希](responses_protocol.json) · [续弈入口](response.py)
