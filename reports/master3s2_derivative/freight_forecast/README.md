# 带货采集工下一格预测

**旧留出命中 440 → 442 / 495，另七场已公开开发局 350 → 351 / 399。两组都通过预定的动作方向门。回仓、与轻工同格这两项预测均无增益，本件仅归档研究结果。**

研究对象是完整原版 Master3s2 实际提交的敌方工人命令。在自研敌方预测器 `245b5814` 的根策略上拟合 25 个线性残差参数，仅对符合条件的采集工输出 5 个行动修正量。输入使用己席行动前可见的货量、基地、双方位置、离家距离、剩余步数。同行提交的命令只在预测完成后用于计算实际同格。预测解码沿用模型原有的共享占位、招工预算、根随机数。

旧留出多猜对的两步均为停留。开发图 582 席 0 第 263 步，对方采集工带 88.96 货、离家 3 格，附近有较轻对手。修正后预测方向与实发一致。开发图 583 席 0 第 287 步也改变预测，仍猜错。改善集中在少数行动。两组中其余工人（1,890 和 1,564 条）以及基地（494 和 406 条）的队令预测均未改变。回仓栏按实际发出的下一目标格计，要验证实收金额还须结合碰撞结算与入账。此实验没有针对新预测器的真实对局，无法据此估计胜率、回款或分差增幅。

## 样本与复现

- 研究开始先锁定 [protocol.json](protocol.json)。取 24 张旧训练图的 48 场、2,802 个合格工人决策拟合，各图等权。限定 t=163 起每 4 步至 295，加 296–298，共 37 个时点。带货至少 50、离家至少 1 格，且离家至多 4 格或到截止的富余在 0–4 步。
- 训练、旧留出、另一批开发局三组的物理地图无交叉。旧留出取登记的两席八场。开发集合共登记八场，582 席 1 双方冷启超时，0 步，其余七场全部纳入。两组赛果在研究前已经产生；图上正例没有独立实战收益的含义。[旧局及地图清单](../opponent_policy/protocol.json) · [八场结算](../dev1/hosted/settlement.json)
- [head.npy](head.npy) 保存 25 个 float32 参数。[result.json](result.json) 有逐图结果、全部五个预测改变事件、原/新/实发命令 ID 及冻结协议哈希。[secondary.json](secondary.json) 对应完整队令和非目标工人的核验。`eligible_as_next_experiment` 严格指两个预测方向门，判定条件为各自总命中严格增加且至少 3/4 地图持平或改善。回仓和争货证据见上表。
- 完整仓检出后，从仓根执行下方命令。复现脚本从已签名公开轨迹重新生成特征、训练并验证三个输出与归档字节一致。实测 NumPy 1.26.4、SciPy 1.17.0、PyTorch 2.5.1 CPU，裁判使用本仓含的 `zerosum_env`。[训练与评分](learn_return.py) · [开发真实请求/响应读取器](dev_tapes.py)

OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 \
