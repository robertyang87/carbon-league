# 将模拟中的敌方策略截到第 2 块，实际能省多少时间

**有计算收益，动作质量未过关。** 12 个旧训练根上，保持相同模拟工作和动作，完整公开调用累计从原来的 4.508 秒降至 4.184 秒（共享前两块，少 7.2%），或 3.789 秒（将敌方行单独浅算，少 16.0%）。本批测量按根取三次墙钟中位数再求和。训练出的 776 参数动作头在另四张留图上只复现 1/128 条完整敌方命令，到此停止。两种节省都不能折算为对原版的胜率或分差。[完整入口逐根三臂数据](full_request.json) · [独立质量验证](../fit.json)

两项测试使用相同的两张老训练图、双方席位及第 20、85、215 步。第一项冻结了全部 125 个原版自然搜索批次、848 行网络输入，同一张量依次重复六种臂顺序。第二项另按原来的 0.58 秒时钟生成各根的参考调用（共 116 批、790 行），随后给三种实现相同的根菜单上限、逐次预算判定和参考敌方 logits。每种实现都实际计算其神经输出，随后用参考敌方输出继续模拟，以防未训练头改变行动、进而测到不同的盘面。复核每次调用的送网张量、候选、深度和最终指令均相同。完整调用包含进入 agent 后的双方视角编码、神经前向、动作抽样、物理推进、候选选择及测量适配开销。两个测试面板的基准时数不能相减；不含容器初启、通信或天梯资源认证。[冻结选根与线程](protocol.json) · [原始张量及工作顺序](panel.json) · [完整调用方法](fixed_work.py)

两个新实现均原样保留己方根策略、对手根预测、所有己方价值以及已算出的己方深层推演策略。仅在 `look(both=True)` 的敌方行、以及筛选阶段 `other` 的敌方续弈缩短骨干。原源代码的 `_RNET` 旁路还会把已做过大网前向的己方行再算一遍小网；这里的分开计算直接使用已有己方结果。计时用相同形状的两个占位读出，训练工件有独立权重和单独验收。所有运行绑定一个本地 CPU，PyTorch 实际单线程，位于共享 cgroup。批次大小、缓存和宿主调度都能影响结果；共享版有 2 根比原版慢。[三臂前向](forward.py) · [六次平衡计时及数值误差](measurements.json)

**数值核验。** 对原深网和共享实现，返回的己方价值最大绝对差为 0.0000003875，工人及基地 logits 分别不超过 0.000233 和 0.000185；109,125 个己方棋盘格中 2 个工人类别 argmax 改变。棋盘格包括空格，因此这两处只作为数值读数。共享与分开两种浅算的模拟敌方工人 logits 最大绝对差 0.0000821，敌方 81,675 个格子的两类动作头 argmax 均相同。训练可调用 `forward.frozen_targets(net,X,sid)` 同时取出第二块后逐格的 96 维特征与第六块后冻结教师的 5/3 类 logits；教师动作的读取仍须使用该模拟行当时的单位位置、合法性、资源与同队解码顺序。[冻结特征与教师函数](forward.py)

冻结张量通过 uint8 百分位无损保存，每行采集时校验还原后的 float32 数值逐项相同。库内 `capture.py`、`measure.py`、`fixed_work.py` 顺序分别对应张量采集、固定批次前向和完整入口验证；已落盘的收据防覆盖。[输入张量](panel.npz) · [采集程序](capture.py) · [计时程序](measure.py)
