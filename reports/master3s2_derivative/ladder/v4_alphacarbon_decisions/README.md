## 两个不应优化错的动作

- **在敌基地撞上重货，账面反而亏。** 第 279 拍己 68 在 139 携带 30.13，历史向左。改向下进入敌基地 154，恰好碰上实际向右返库的敌 56，成功夺到 **189.11**。同拍我方工人在对方基地把连同自己原货在内的 **219.24** 全部存给对面。敌人的“己工交库”被切断，实际钱包却比原局多 30.13。训练应追踪货最终落入哪方钱包。[双引擎现金事件](branches.json.gz)
- **提前到账有时只牺牲采集。** 第 274 拍己 40 在 63，改原地为向右回到己库 64，立即交付 **144.54**。原局在安全位置又采两拍，第 276 拍行动后交付 **195.54**。固定其后历史命令复算三拍，提前回库的分差反而比原令低 **51.00**。[候选清单](scan.json)

**覆盖和边界。** 先对两边实发命令复原完整 299 拍，逐拍交叉核对仓内官方解释器与 FastCarbon 的玩家、完整棋盘、树、两席局部观测和最终得分。13 个根中共检验 383 条合法单采集工改令，固定己方其余单位且排除友军落点冲突。按同拍实发敌令，只有三条出现新增截货、增加己方交库或减少敌方己工交库。两步布位的例子是此后回顾性选择的另一种动作，不包括在单拍 383 条之内。短期分支中，双方其他单位沿用历史命令；因改线消失的工人跳过，新增工人没有历史令时采用默认动作，二者都有逐拍记录。真实天梯对手的策略包身份无法从该战注册复原，因此表中走法是敏感性诊断，未开展该玩家对改线的自然应答试验。可将这组三类根用作训练/验证的对照：库外截获并运回可赚，敌库相撞可能捐款，安全晚交也可能比抢先回库更值钱。[扫描程序](scan.py) · [逐拍分支](branches.json.gz)
