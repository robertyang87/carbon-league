## 第 286 拍的路线

当时己 68 位于格 54、空载。对手 56 在距敌库 70 两步的格 72 载有 **132.97**，敌方另一名空载 68 在库外 71。两个敌工的当前位置和载量均可见。己工直冲 70 容易把截来的货存给对面；先经 55、56 绕到库外 71，才可能把货带走。此路在历史结果揭晓后选出。那一刻无法知道敌 68 是否会原地采集、变成有货者，也无法知道敌 56 会在哪一拍返库。[复赛原回放](../../v4_observations/increment_0926/replays/5906206b61c94c29d8ea2f99d2b4d62d-1.json.gz)

己方只接管 68 号，其余单位使用存档命令。每拍均核验其它己方单位和招工的实际落点。改线导致生死与招工改变，新工只有出生回合、出生基地和角色都与存档对上才承接原命令；匹配不上就缺省等待。这里确实出现新生敌工 id 69 对应历史 id 70 的情况。另以纯数字 ID 绑定重放原敌方应手，得到相同终分。每一臂均用官方引擎至判终局，并逐拍用 FastCarbon 核对两席公开碳、完整图、玩家现金、单位和树。上述其他单位的历史动作只是一个受控续策，双方没有就变化后的局面重新调用原策略。[逐拍共同与差异动作、出生匹配、现金账](paths.json.gz) · [复现代码](response.py)

## 两个关于提前回库的检验

- **复赛 t289。** 己 66 在 49、携货 46.97，如果立即向下回库，下一状态钱包的确会从历史的 **−24.69** 变成 **+22.28**。原局多等一拍，携 55.02 回库。对后续命令和对手保持相同口径，抢先回款的官方终局是 **−270.77**，比原局少 **23.18**。瞬时反超并不等于终局变好。[两臂账](paths.json.gz)
- **初场 t297。** 旧胜局当时落后 32.19，己 51 回 154 交 107.20，下一状态领先 76.04。只把这一拍改为原地，在相同敌令下，t298 仍落后 31.16；但最后一拍实际可把 111.14 交回己库，最终 **+136.23**，也赢。这说明实际那次交付确实反超，当时严格提前一步并非该场获胜的必要条件。[初场回放](../../v4_observations/replays/2cba12ae1302e3e6392cf0bc74476b12-1.json.gz) · [两局改令终局](terminal.json)
