# 在 ds-pro-v1 原搜索之后比较一次终局货物交接

哈基米 v3pro 的败局中，新增包两次从公开 `agent()` 发出 **工 37 向左，向队友 9 交货**。其中一次开、关新功能的原搜索有相同的 19 项菜单、相同各臂深度、相同胜出动作，差异只来自交接比较。另一次的原搜索完成深度受墙钟影响；按事前要求，两次均可归因才算稳定，故严格验收为 **0 个稳定改令根**。重演两次实际送入比较器的完整父令与新令，在固定历史对手指令下均使终局多收 130.58，仍然落败。其余 32 张定位图和保留的 6 张原版交手图上没有实际发出新令。现有证据支持这一处策略缺口，尚不足以更新天梯版本。[逐次开关结果](public_entries.json.gz) · [现金和官方终局](mechanics.json.gz)

## 可运行的改动

单文件从 ds-pro-v1 的冻结包 `7cf5c6c9` 生成，原包全部 2,902,805 字节保留，在末尾追加比较器。候选长 2,910,057 字节，SHA-256 为 `65918bf9389b78ad21d8ea0554edd06439f00a9381864f0789960bd04547bf36`。代码沿用原策略网、轻量续弈网和规则模拟，新增训练参数为零。原包在缺少其搜索所需运行时时仍走原有策略路径。这个派生包的天梯资源资格尚未测定。[单文件](candidate.py) · [追加源码](runtime.py) · [构建和身份](manifest.json)

1. 原生搜索照常从 A0 与所有原候选中选出完整命令。新比较器接收这一次实际选中的整队令，在剩余 2–5 拍时至多提出一条替代。原搜索没有删项或为接力预留时间。
2. 原路线使携带至少 30 的采集工下一步离库距离超过剩余时间，己方另一名更轻的采集工已按其原令朝基地移动、且能按几何距离及时回库。改捐货工一人的命令到两人相约的非基地格。排除目标格存在第三位己方到达者、双方同重，以及敌方同重或更轻工可在该拍进入。非基地且保持所有招工原令，使本次改动没有新增招工和抢占基地的问题。若多个选择过筛，只比较载量最大者，距离、单位和方向顺序固定。
3. 在本席信念碳图上预测一条同时敌令，父令和交接令使用相同敌令推进。其余拍由原包的轻量续弈策略按新局面重新出招，双方两分支根随机数一致。分支可导致后续动作改变。跟踪这批货的队友接手和到库，直至步限。只有看到己方采集工在己库活下来并清掉载货、整队官方现金差的估计也高于原令，才发交接令。模拟灭绝、跟丢运输者、没有到账、预算不足、异常均返回原搜索结果。估计用本席信念和模拟对手，不读取对方当拍真实行动。到库检查确认携货路线，实际入库数另由双引擎查账。

## 墙钟与处置

在唯一有效根，两次额外比较耗时 73.7 和 61.9 毫秒；两次完整公开调用用时 480 和 455 毫秒。26 个定位机会中，关闭、开启的公开调用 P95 分别为 584、531 毫秒，最大 697、555 毫秒；15 个原版机会中分别为 724、499 毫秒，最大 875、593 毫秒。两组独立占时的差异包含共享宿主调度与父搜索的自适应深度。父包的 0.58 秒内部截止并非平台端到端计时。实验固定一颗逻辑 CPU 和一个 Torch 线程，未施加天梯独立 1.5 核 / 512 MiB 限额。[汇总及资源环境](results.json)

跨图没有自然触发，继续用同一哈基米地图调阈值只会重复选择已知答案。保留该候选与单元正反例；若后续有新的真实终局交接机会，可以用不同地图自然响应和父包对照判断是否值得集成。此版本没有新天梯战绩。
