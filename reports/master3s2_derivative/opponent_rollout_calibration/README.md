# 原版 Master3s2 模拟对手的动作概率校准

原版搜索要预测对手接下来做什么。ds-pro-v1 用估计对手看到的棋面生成队令，后续每层直接使用网络 logits。本次给采集工、种植工、基地各训练一个系数，分别乘以该角色的动作 logits，再走原生整队解码。三系数分别为 **0.209、0.168、0.355**，都把概率从最看好的动作上分给了其他动作。源包在本机 PyTorch 2.5.1 CPU 下实际报告 rollout 和主干共用同一网络。首拍对手根模型、我方策略、价值输出和 0.58 秒预算沿用 ds-pro-v1。候选单文件 SHA-256 为 `2cf0c9ac5066b19d8375e82140a991ecc85d0a660d1e5a361ed2a184993cea58`，大小 2,903,428 字节。[代码与一键重建](build.py) · [冻结权重](weights.json)

## 监督究竟对应哪一拍

全部数据来自自己已经归档的 ds-pro-v1 `7cf5c6c9` 对完整原版 `65f268b2` 的自然 0.58 秒实战。每五拍取一根，先从我席当时可见的碳和真实观测历史重建信念，代入双方这一次已经发出的命令，让原版模拟器推进一拍。在这个后继上预测对方**下一次**发出的命令。已有 2 张训练图双席、236 个后继；另外 4 张历史开发图双席、472 个后继。双方工种、位置和基地的物理身份全部对齐，新出生工人按席位、工种、位置连接。冻结系数后才为这个模型计算四张留图结果。全部留图属于旧开发赛的已曝光地图。[冻结样本清单](protocol.json)

实际输入量化与原版 NumPy 入口逐值相等，另对 8 个训练根核对 NumPy/torch 原 logits，最大绝对偏差为 0.000206（工人）、0.000137（基地）。把实际标签故意错移一拍，采集工实际 NLL 从 0.91 升为 17.31（前拍）或 15.07（后拍），种植工从 1.75 升为 16.61 或 17.16。在只作诊断的原版对手自身私有观测上，采集工原输出 NLL 0.82、校准后 0.34，种植工 1.29→0.48。可观测信息差异能解释一部分误差；即便给了对手本来看到的信息，原先验对对手实际搜索后动作仍相对过度集中。模拟后继与实际后继的单工载货平均绝对差为 0.0036、最大 7.66，整席现金平均绝对差 0.0277、最大 3.20。未真的走出的其他分支缺少对手实发标签。[时间与特征复核](alignment.json)

## 真搜索能否改变我方决策

两张旧训练图、双席分别取 t42、t177，通过完整公开入口共运行 32 次。组内交替运行母包、系数置一的候选、训练候选，并复跑首臂。八根重跑结果均一致，系数置一时八根均返回母包命令。有 7 根四次搜索工作量、根菜单、对手第一步一致，其中 **4 根我方最终实发命令改变**。这七根中，21 次可匹配的首层分支保持我方模拟动作，12 次改变对手模拟动作。另 1 根的计算工作量不同，原样留证。计时为本地单核真实墙钟；线上执行器还须核验同一 SHA 的整局资源与真实对手结果。[逐根搜索与命令](probe.json)

复算时用仓库环境中的 NumPy、SciPy 与 CPU PyTorch，从本目录执行 `python study.py train`，再执行 `python study.py held --weights-sha 84a50f0f6d6c4cd3651877680ef7240463b752daa5bdde598185fd8cec0fc0a7`。输入复核、打包、真搜索分别执行 `python alignment.py`、`python build.py`、`python probe.py`。真实墙钟会使重跑达到的深度或候选数变化。[拟合与原生联合动作评分](study.py)
