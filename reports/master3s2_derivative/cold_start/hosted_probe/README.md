# 原版派生网络的宿主冷启动与第 0 步

在同一台 GitHub Ubuntu 24.04 执行器上，V1 和 V2 各在四张旧训练图冷启动一次，与原版 Master3s2 同时加载。V1 冷启动平均 **7.388 秒**，V2 为 **2.850 秒**，四组配对都缩短，平均节省 **4.537 秒（61.4%）**。八对都在 20 秒内完成双方初始化，第 0 步双方均在 1 秒内返回合法命令。历史开发场那次双方约 20 秒超时继续计入原场，此次四图没有重现该事件。[冻结协议](protocol.json) · [原始执行](https://github.com/robertyang87/carbon-league/actions/runs/44671315099) · [逐场核验](results.json)

每一行使用两个新容器和新策略解释器。两席的 `cpu.max` 均为 `150000 100000`，`memory.max` 均为 `536870912`，交换空间额外额度为零，网络隔离。每个角色独占自己的 cgroup，两席在同一组两个逻辑核上并发冷启。候选就绪后，环境依既有考场时序先向席 0、再向席 1 请求第 0 步。冷启动用时从公开 load 请求发出到 READY 解析完成，首步从观察发出到整队命令解析完成。ZIP 包含每侧程序、镜像身份、通信墙钟、进程 CPU、宿主 cgroup CPU 及峰值内存。ZIP 按 GitHub 的 16,237 字节和 SHA-256 `fa2e89fd825dc7f00f9fc6710cda8018a5d5e707985580f576beb5af873b941c` 读回核验。[原始工件](14600446559.zip) · [执行与复核代码](probe.py)

原版与 V1 同时加载时平均耗时 7.379 秒，与 V2 同时加载时平均 4.223 秒。两个角色共享宿主调度，这组数适用于实测的成对并发配置。V2 第 0 步最大 65.39 毫秒；完整对局会遇到不同局面和批量，本组收据只有第 0 步。另一次训练图测量的 244,936 项网络输出逐字节一致；V2 未显式预热的批量中，N=31 首次调用 252.82 毫秒，比其后两次测量的中位数多 15.58 毫秒。两项证据分别覆盖宿主初始化和部分批量首次前向。整局慢步、累计超额、稳定胜率仍待相应整场数据。[本地批量逐项对照](../shapes/README.md) · [原开发场结算](../../dev1/hosted/settlement.json)
