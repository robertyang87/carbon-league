# 缩短原版派生网络的启动热身

冻结候选 V1 在开发图 621758582 席 1 与未修改的原版都在约 20.019 秒触发冷启截止，该场计 0 步。现有宿主收据无法指出这次双超时具体耗在哪个阶段。这里单独检验可直接改变的耗时，在已冻结的 V1 上只修改启动热身批次。V2 未参加原先八场，其成绩不能用 V1 的对局代替。

原循环依次预热 1 到 32 行的所有批量（528 行），V2 预热 1、2、4、8、16、32（63 行）。随后的 32 行实测成本标定在两个版本里均照常执行。生成器恢复那一行即可还原 V1 的全部原始字节，包括 CRLF、权重、载入逻辑和搜索的 0.58 秒截止。候选 SHA-256 为 `7cf5c6c91fc59b46b2a38924c4c5ab56143fb1242d082f9426303af7336ac3ed`，大小 2,902,805 字节。[新包](candidate.py) · [逐字节差异与哈希](release.json) · [单行修改的生成器](build.py)

随后用同一 SHA 在两张新开发图上对原版打满四场，获得 3 胜 1 负，平均官方分差 +260.81。实测完整比赛的最慢冷启 10.86 秒，最慢一步 0.589 秒。[四场完整比赛](development/README.md)

## 同 CPU 的独立进程冷启动

每个版本分别启动四个新解释器，按 V1→V2、V2→V1 交替次序。由父进程从创建子进程开始计时，收到并解析 READY 才结束。随后提交实际使用过的两张训练图的公开观察，测试首步、开场连续回合和从真实历史恢复的中后局。每个版本累计 30 次完整公开请求；父进程在序列化之前起表，收到并解析动作后停表。中后局测试恢复历史的时间单独结算。两个版本的搜索都用真实墙钟。

| 本地测量 | V1 | V2 |
|---|---:|---:|
| 4 次冷启到 READY，中位数 | 5.582 s | 2.229 s |
| 冷启范围 | 5.120–5.888 s | 2.118–2.303 s |
| 四个首步请求的最慢值 | 0.183 s | 0.196 s |
| 全部 30 次请求的最慢值 | 0.530 s | 0.476 s |
| 观测到的峰值 RSS | 293.9 MiB | 293.8 MiB |

另用每版两个独立进程给初始化加阶段计时。热身形状遍历由 3.434 秒降至 0.649 秒（中位数），NumPy 导入为 0.053/0.062 秒、策略参数解码 0.024/0.024 秒、Torch 导入并设置线程 1.054/1.253 秒、搜索网络建立及等价自检 0.083/0.241 秒、原始 32 行成本估计 0.270/0.316 秒。插桩进程与未插桩进程分别统计。当地结果表明删减热身能节省初始化，并在这些公开请求中守住了一秒。[按进程、按步的原始读数](startup.json.gz) · [父进程](measure.py) · [子进程与计时位置](worker.py) · [训练图观察的生成和校验](fixtures.py)

环境为 Python 3.12、NumPy 1.26.4、PyTorch 2.5.1 CPU，两个版本绑定同一逻辑核。每个子进程读回上级 cgroup 为 4 核、16 GiB；文件系统页缓存可能已热。独立解释器能验证导入和初始化路径，平台在 1.5 核/512 MiB 下的完整资源认证仍开放。

另取四张旧训练图的 32 个真实公开局面，在 18 个新进程中逐项测量批量 3、5、7、9、11、15、23、31、32。244,936 个策略及价值输出逐字节相同。V2 未显式预热的批量中，首次调用相对自身两次复测的最大额外耗时是批量 31 的 15.58 毫秒（首次共 252.82 毫秒）。宿主负载造成的尾部波动明显，各形状原始读数一并保留。[不同输入批量的首调用测量](shapes/README.md)
