## 如何复查

配置提前固定候选 `7cf5c6c9`、考官 `65f268b2`、两个图的物理哈希、两侧 RNG、CPU 及先后次序。两图首拍两侧的 225 格公开碳均为零，逐席请求哈希相同。策略首拍看不到图号，也无法靠动作前可见碳在这两张图之间选择不同开局。两臂都固定原版首拍双采、己方基地 0 招采集工。仅干预己方基地 1；双方分开保存私有观察、信念、模型搜索状态、RNG 和超时银行。[预登记](protocol.json)

第一拍用历史实发令建干预，现场原生根调用留下时钟与私态。第一拍之后每一拍的双方队令均在当前分支公开观察上由完整原生策略重新作出，维持温度 1 和 0.58 秒自适应搜索。每场进入分支时恢复同一裁判和独立私态快照，以预登记的独立己、敌 RNG 从首拍后开始；后来队伍组成和采样次数可以分化。单机原生墙钟和原天梯采样轨迹均可能不同。

该机计时从每次调用公开 `agent` 开始，是同机进程内诊断。冷启和进程间通信未包含，双臂共用首调用条件；天梯部署资格单独认证。各臂保留全部输赢、深度、逐步耗时及两个独立账本。

在仓根安装原有 Python、NumPy、Torch 和官方环境依赖后，以 `python reports/master3s2_derivative/opening_recruitment/settle.py` 从四份逐步回执独立复算，逐一检查原始 SHA、同图同席的公开请求、两臂共享私态、首拍仅有一条命令不同及官方判读。完整对局脚本为 [paired.py](paired.py)，它需要按预登记 `taskset` 绑核。
