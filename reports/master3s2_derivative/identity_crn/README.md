# 在搜索比较中，让同一工人使用同一次抽样

当种植工在方案 A 生存、在方案 B 死亡时，原版依次遍历幸存单位抽动作。相同随机种子下，排在它后面的工人会改用另一组随机数，掩盖首令本身造成的差异。两边有理由在不同棋面发出不同动作；这个改动让同一单位从相同分位数抽样，各分支仍使用各自棋面的策略分布。出场考官使用仓内完整原版。[原始分支实测](../search_response_audit/README.md)

候选从我们以原版权重制作的 ds-pro-v1 构建。根上已有工人与基地按原顺序分配分位数，之后招募的单位按身份与模拟种子取数。在名单不变的 512 组测试中与父包逐次一致；删除前序单位后，父包有 397 组让后序单位换了抽样位置，新版为 0。16 个事前选定的实战根逐一从公开入口运行。两次调用都能保持相同菜单、候选数、深度和推演数的有 7 根，其中 1 根稳定改变最终发令。[可重建的候选](build.py) · [逐次检查](checks.json.gz) · [冻结单文件](candidate.py)
