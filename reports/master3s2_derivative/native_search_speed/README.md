# 用同一套权重腾出搜索预算

以线上 V2 为母包。在现有 Winograd 前向里复用数组，沿用此前逐批核对过的张量运算替换。另将推演里的小规模类别抽样改成同样的双精度累积分布查找。候选沿用策略与价值权重、0.58 秒截止、温度 1、同一模型与候选生成顺序。在 NumPy 1.26.4 和 2.3.5 上分别复算 16,128 次，全部抽样值和结束随机状态一致。[候选包](candidate.py) · [构建程序](probe.py) · [平台 NumPy 抽样检查](rng_check_1.26.4.json)

以四张旧开发图双方的公开实战前缀为输入，每席取第 117、247 步。16 个局面在固定同一实际工作后，菜单、对手根令、每个候选的深度与叶值、最终联合动作全部一致。父包与候选各两次调用，平均 CPU 从 0.4442 降至 0.3970 秒，减少约 10.6%。两臂从父包同一成本起点进入原生墙钟时，16 个根的首次自然发令均一致。[协议](protocol.json) · [所有同工作量读数](results.json.gz)

让两包各自用该局面前的三次真实公开请求暖机和估价后，再在自然预算下交替调用。每包 32 次目标调用，平均完整候选从 11.59 到 12.88，平均深度从 7.88 到 7.81，H8 完成 30 次和 29 次。两侧重复发令稳定且两包不同的有 4 个局面。能评更多完整队令是可观察的变化，胜率收益由另行登记的新开发图整局检验。[独立估价与逐根读数](self_calibrated.json.gz) · [复算程序](self_calibrated.py)
