# 真实双边续弈检验了回款预测，却没有改善终局选令

在 4 张不同的旧开发地图上，两条候选的**新续弈结果**在盲判签出前均未知。对每个根，冻结网络都能分辨同一名采集工当前携货的两种处置，4 次猜对了 3 次哪种选择能在未来 12 拍交入更多当前货。但叠加网络后，4 个根均仍选择原生首令 A；原生及校正后的终局排序各对 2/4，改变的胜负为零。[此前签出的预测](model_blind.json) · [揭盲结算](model_grade.json)

预登记池是 8 张地图，两侧的 t279、285；用当时的公开现金差、在途可达性和同层 H8 首次两项筛出 4 张合格地图，两席各 2 张。动作选择方未使用网络分数。后续运行器在启动双方真实续弈前校验菜单 SHA `3b737e03…` 和盲判 SHA `8d90d61a…`。每根两臂共用未改原版的当拍实发，不同首令之后双方根据自己的新观察重新行动到官方终局。每个分支只有一次自然应答采样。[根登记](protocol.json) · [完整候选和全部筛选过程](menus.json) · [双臂运行器](branches.py)

600 和 592 的 B 确实各多交了一笔现有货，但 A 的终局反而分别少输 142.42 和 132.84。602 的 A 把当前货多交 219.42，全队交仓却少 9.72，最终少赢 59.38。四根上的同工回款差平均绝对误差为 75.59，所有动作都报相同回款的基线为 81.41；将网络分数加入原生价值后，终局价值差的均方误差由 0.002392 升至 0.002834。四根全队的两种结算各在同一胜负侧，未出现首令把输赢翻转的样本。这组前瞻新标签可用来检查资产能否入库及其与终局的分歧，但独立地图只有四张，不能估算整场胜率或支持扩大部署。

`model_predict.py` 只读权重、公开根信息和两项完整命令，并以追加保护写入盲件。`model_grade.py` 等所有根结束后，按工号重算原载货的首笔入库，验证分支绑定的盲件、菜单和预登记哈希。全体数据附带每臂官方分、所有实际交仓、终局 WDL 和自然搜索时钟。[盲判程序](model_predict.py) · [结算程序](model_grade.py) · [四组逐局收据](cases/)
