## 1. 谱系依据

本改造是 **v53 作者本人机制的推广**（lineage_diff_report.md 确认）：base 的
run_mode=3 用 run_b 按携带三档贝叶斯学习蹲守者出击率、以期望损失 (2c+30) 定价，
但只用于 run_cells 的冲门决策。本案复用同一统计形态（Beta 型先验＋后验回填）与
同一损失函数，推广到 DP soft 层、minreach 层、动作层致命/等重三处。
一处有意更严：作者的伪计数先验（强度约 2–2.5）即时混合后验；本案按
avoid_tax_report §7 的准红线，**桶 n≥30 才允许后验接管，之前纯先验价**。
这是与作者机制冲突风险最低的推广路径——但验收表明：推广到全局移动层不成立（§6 诊断）。

## 2. 改造点与公式（as built，回滚前配置 soft=1/lethal=1/minreach=1）

统计管道照 probe (b) 口径产品化（与 run_b 同构）：每步在最终目的地定稿后登记
watch，下一步（H1）/ 两步内（H2）结算；敌员消失不计样本。

- 桶定义：携带档照 probe——0 / 1–80 / 81–150 / 151–250 / 251+。
  H1 =（敌携带档 × 我携带档），供 lethal/minreach；H2 =（n2 档 × 敌最轻携带档 × 我携带档），供 soft。
- 后验接管：桶 n≥30 用 (strikes + 30·prior)/(n + 30)（先验强度 30）；
  否则边际桶（H1 按我携带档、H2 按 n2 档）同规则；再否则纯先验。
- 先验：soft = f(n2)（0.06/0.25/1.0）；minreach C1 = avoid1 0.5、Cr = avoid2 0.15
  （同桶后验、两个先验，Cr 不吃 pred 顶格）；lethal = 0.5；tie = 1.0。
- **soft 层**（原 L1759–1767）：固定 f 罚 → P̂(H2 桶) × (c+30) 期望损失。
- **致命层**（原 L1925 一带）：−1e6 只保留红线区（我携带 ≥150 且 P̂ ≥0.5）；
  其余 P̂·(2c+30)（与作者 run_ev 同一损失式）；原地动作另加 P̂·500；
  等重扣减 = max(30 + 0.2c, P̂_tie·(40 + c))——单位价值下限 30+0.2c 为有意设计
  （c 小时高于 base 的 12+c，把「工人本身值钱」计入）；终局 R≤6 缩放分支与 run 分支未动。
- **minreach 层**（原 L1753–1757）：C1/Cr 的 avoid1/avoid2 常数 → P̂(H1)·(c+30)。
- **pred_next 强特征**：预测落点命中的格，该格 P̂ 下限 0.9（lethal/minreach-C1 要求
  敌携带 < 我携带；soft 要求 ≤）。
- 独立开关：PARAMS 中 price_soft / price_lethal / price_minreach（+price_min_n=30 等）。

存档配置：fork_c_all.py（全开）、fork_c_soft.py（soft 单开）、fork_c_lethal.py
（lethal 单开，minreach 关）、fork_c_nosoft.py（soft 关、lethal+minreach 开＝回滚验证配置）、
fork_c_off.py（全关）。

## 6. 诊断与下一步建议

1. 「规避税」的成立范围是对手碰撞威胁近零的 matchup。对位强手时最坏情形层是
   承重结构。任何放松都必须**以对手原型为条件**——与 S2/案 A 的原型识别合流：
   识别为弱威胁原型时才允许定价化接管，且接管幅度受 dc 红线在线监控。
2. 先验必须用实测桶率重标定（pb2 已有 n≥500 的可靠桶率），不能沿用作者常数；
   但重标定后的 soft 罚在主要桶上将**高于**现行固定罚——「税」在大桶上不存在，
   存在的是低携带桶上的常数错位（可作独立小案：按携带分档缩放固定 f）。
3. run_b 式定价的安全推广面应限于**有明确对价的局部决策**（冲门、抢树、猎杀接近——
   作者本人正是在这些地方用的），全局移动 DP 不是合适载体。
4. 本案的耐久资产：fork_c_pricing.py 内的统计管道与桶率表（§4）、五份配置存档、
   40 局全留痕（§7）。机制本身待原型识别就位后可按 1. 的条件化形式重启。
