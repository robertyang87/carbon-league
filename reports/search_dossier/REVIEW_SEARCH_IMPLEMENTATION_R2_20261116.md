## 2. 两项 P1

### R2-01：两席 guard 对象独立，但对手历史复制自己方

定位：[`real_env.py:558–566`](https://github.com/robertyang87/carbon-league/blob/b15b475d/code/search_proto/real_env.py#L558)，关键代码 `guards = (inx.guard.copy(), inx.guard.copy())`；`:588–595`把第二份用于对手席。

`inx.guard`属于当前agent己方，含自己的 lostw/prevw。BankruptcyGuard 用 `lostw += len(prevw-cur)` 累计死亡；对手UID与己方UID不同，首次续弈就把复制来的己方存活单位当成对手死亡。分配两个不共享的对象不能修正状态归属。

实包探针：双方各1个存活collector、各cash10、此前无死亡。H2首次守卫调用后，己方lostw=0，对手凭空lostw=1，me0/me1均复现。

行为控制例使用真实生产guard和FastCarbon，只固定候选续弈标签以隔离变量：错误历史触发GUARD_NARROW，对手从113逃到98，叶值−117；正确的对手历史不触发该保护，对手碰撞灭绝，叶值+209。其余根、动作标签、网络、模拟器与评分不变。**这是可能改变搜索评价的反例，不是自然发生率或整局收益估计。**

现有修复测试只检查更新后的prevw不相交；apply本身已经把prevw覆盖成本席集合，因而漏掉仍残留的虚构lostw。

修复：按各席自身历史维护guard快照。离线有真实对手状态时取其快照；部署预测器则维护明确的对手历史估计，不能拿己方历史顶替。回归至少覆盖无死亡、只己方死亡、只对手死亡、不同既有lostw和换席，并核原快照不被分支改写。

证据：`real_env/probe_r2.py`、`results.json`、`findings.md`。

### R2-12（P2）：根级IPW＋入样局等权，尚不足以恢复声明的局等权总体
