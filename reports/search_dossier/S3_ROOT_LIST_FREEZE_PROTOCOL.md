## §1 枚举方法

### 1.1 对局形态

- 诊断种子块 **986200–986499**，共 300 局，基线包（Echo4 包 md5 819250bf，
  SEARCH=False）自对弈，双席。局号 `game` 为块内序数 0–299，种子 `seed = 986200 + game`
  （与 verify3「局 0／种子 986400」的记法一致）。
- 每局打满至权威终局（时限 step 299 或灭绝），agent 局内持久、跨局重建；
  部署口径见 §10.2。**枚举期间不做任何比较器决策、不算任何 ΔU、不咨询任何测试结果**
  （测试尚未发生）；枚举只产出根身份＋触发元数据。

### 1.2 触发筛查（类一，逐字口径）

根枚举的触发面就是 `key_units(obs, cfg)`（code/cnet2_search.py:386–478，源码 md5 94f7fb64；
生产调用点 `_search` 保留段 :1506）。枚举对每步 obs 以生产 cfg 原样复算 key_units 的
分类结果（A3 §0）。生产 cfg ＝ DEFAULTS ⊕ Echo4 包 CONF（cnet2_search.py:621–623；
包 CONF 逐字见 A3 §0）。

类一判据（A3 §1，L30–44；基础段 key_units:389–405，无步数门，全步带 0–298 均可触发）：

- 对本席每个工人 `w=(pos, cargo, kind)`，当且仅当 `kind == "COLLECTOR"` 且存在敌方
  COLLECTOR `e` 满足下列任一方向时，该工人成为关键根（stake 取两方向最大值，>0 才入选）：
  - **1a 受威胁／逃逸向**（key_units:399–400）：`DIST[pos, e.pos] <= KEY_R(=2)` 且
    `e.cargo <= cargo` 且 `cargo >= MINC(=10.0)` → stake ＝ `cargo × PRIO_THREAT`
    （`cfg.get("PRIO_THREAT", 1.0)`，CONF／DEFAULTS 均未设 → 1.0）。
  - **1b 猎杀向**（key_units:401–402）：`DIST[pos, e.pos] <= KEY_R(=2)` 且
    `e.cargo > cargo` 且 `e.cargo >= MINC(=10.0)` → stake ＝ `e.cargo`。
    此向多一道门 `cfg["HUNT"]`：DEFAULTS 为 True、CONF 未覆盖 → **门开**。
- 入选后按 stake 降序（:404），最终截断 `keys[:MAX_KEY]`，MAX_KEY＝3（:452、:463）。
  同一步可产出多根（每席 ≤3）。
- 变体子情形 1c THREAT_FIRST（:407–419）与 1d SPLIT（:420–435）的门
  `cfg.get("THREAT_FIRST")`／`cfg.get("SPLIT")` 在生产 cfg 下均缺省为假 → **关**，
  类一按基础段排序（A3 §1）。

### 1.3 子方向判定（枚举脚本必须做的复核）

`key_units` 只返回工人 uid 列表，不带段标签。枚举脚本对每个返回的 key，必须用 obs
现值重算 1a／1b 两谓词（DIST 矩阵 cnet2_feat.py:54、双方 cargo）并登记子方向；
**两谓词均不成立的返回 key＝判据实现与触发清单不符**，按 §1.4 处置。

### 1.4 类二／类三出现即停

- 本趟裁定级触发范围先行声明收窄为**类一**一类（A3 §5）；类二（返航交付）、类三
  （近步限现金清算）在生产 CONF 下触发不成立，记「不覆盖（触发不成立）」，不以变体
  CONF 的根充数（A1 §7、A3 §2／§3／§5）。
- 枚举中出现任何自称类二／类三的根（或 §1.3 复核不成立的 key），即判据实现与本清单
  不符：**停下上报核查**，按附则 §3「触发判据误报」记无效；不许跳过继续枚举、不许
  事后把该根改记类一（A3 §5 末段）。
- 类二／类三不成立的决定性证据（备查，不复算）：类二唯一路径 key_units:437 门
  `cfg.get("KEY_LATE_HOME")` 键不在包 CONF 亦不在 DEFAULTS；类三主段 key_units:455
  双门皆关（KEY_LATE_CARGO 键缺省、KEY_LATE_STEP 缺省默认 999 超出步数域 0–299）。
  CONF 中的 `"LATE_STEP": 240` 是对手教师相位切换（:843–857），不是 KEY_LATE_STEP，
  不得据此认为晚期触发已开（A3 §3）。

### 1.5 步域与根步

- 根步域 0–298（最后可行动根步为 298；终局步 299 为权威口径，见修订版 §1.1）。
- **枚举不设 verify3 式的 step≥240 硬线**：verify3 的 step≥240 是其延续腿的扫描线
  （A4 附件协议），不是 S3 根总体的筛线。附则 §1 明文「在每步以注册触发条件筛根」，
  枚举覆盖全步带。

### 2.2 去重键（写死）

`root_id = "<seed>-<game>-<step>-<seat>-<key_uid>"`。**去重键必须含种子＋局号**
（R2 §5 小项；A4 附件的根去重口径同源）。同一去重键出现两次＝枚举实现错误，
停下核查、不许静默去重后继续。

### 2.3 枚举期不做判读

根单定稿前不做任何判读：不算 ΔU、不比候选、不排根的优劣。stake 只作审计字段，
不作抽样或排序依据（抽样分带只用根数，见 §4）。

## §3 局总体册

### 3.1 总体定义（先行、固定）

**局总体 ＝ 枚举中产生 ≥1 个类一根的局**，连同每局的根数在开测前落盘钉版
（修订版 §2.1，L38–41）。估计量的总体就是这个局总体，报告中明示。
不产生类一根的局**不在总体内**——这是总体定义、不是抽样排除，须在报告中写清
（同上）。

### 3.2 局总体册 schema（每局一条 JSON 对象）

| 字段 | 类型 | 说明 |
|---|---|---|
| `game`／`seed` | int | 同 §2.1 |
| `root_count` | int | 该局类一根总数 |
| `root_count_by_seat` | {0: int, 1: int} | 分席根数 |
| `pi_g` | float | §4 第一阶段局纳入概率（普查时 1.0） |
| `sampled` | bool | 该局是否入样 |
| `zero_valid_roots` | bool | 测试后填（§8）；冻结时为 null |

### 3.3 零根局的报告义务

枚举报告必须写明：共打 300 局，其中产根局 N 局、零根局 M 局（N＋M＝300）。
零根局不在局总体内，但其**计数必须在枚举报告中出现**，不许沉默消失。

## §4 两阶段抽样设计

### 4.1 设计原则（先行声明，冻结时落实数字）

- 两段纳入概率 **π_g 与 π_{r|g} 须在开测前登记钉版**（与根单同批入档），测试执行方
  开跑前验根单 md5 时一并验 π 表。
- 分带只用**枚举元数据（根数）**，不用任何测试结果（测试尚未发生）；抽样不按结果
  挑根、不按 stake 挑根。
- **普查优先**：局总体能全查时 π_g＝1；入样局内根能全测时 π_{r|g}＝1。抽样是
  预算不足时的例外，须在冻结记录中写明触发它的预算数（见 §4.4）。

### 4.2 第一阶段（局先行）

- **先抽局**：局总体若超执行预算，先抽局；按局根数分带分层随机抽局，每层局纳入
  概率 π_g 开测前登记钉版；局总体可全查时 π_g＝1（普查）。**局的入样由本阶段决定，
  与其根是否被抽中无关**——原附则 §1「按根分层抽样」对主尺废止（修订版 §2.2，L43–47）。
- 分带规则（先行声明，冻结时按枚举总体算出具体界）：按局根数三分位分带
  （低／中／高三带，带界＝枚举总体的三分位点，四舍五入取整，带界值随冻结记录入档）；
  预算按带大小比例分配，即各带 π_g 相等（自加权设计），各带抽局数向上取整，
  **每局的精确 π_g 值逐局登记入册**。
- 未被抽中的局由 π_g 的设计权重在估计式中计入（§7.2），不许沉默消失（同上）。

### 4.3 第二阶段（局内根）

- 入样局内按登记的条件概率 π_{r|g}（层＝席位带：席 0／席 1）抽根；根层逆概率加权
  **只修正局内机制**，不冒充局纳入概率的修正（修订版 §2.2，L43–47）。
- 默认普查：入样局内根全测，π_{r|g}＝1（分席各记）。仅当某局根数超过局内根上限 C
  （C 由策略组在冻结时定数入档；未定数时 C＝∞，即普查）时，按席带等比抽根，
  每席带精确 π_{r|g} 值逐根登记（§2.1 字段）。
- 未被抽中的根由 π_{r|g} 计入（§7.2）。

### 4.4 冻结时必须定数的参数

下列参数在冻结时由策略组定数、随根单入档，**本协议不预填数字**（枚举总体规模未知，
现填即编造）：

| 参数 | 含义 | 默认值（未定数时） |
|---|---|---|
| B | S3 测试可执行的局数预算 | 未定数时＝局总体规模（即普查） |
| C | 单局可测试的根数上限 | 未定数时＝∞（即局内普查） |

### 4.5 冻结记录中的抽样声明

冻结记录（§5.2）必须含：B、C 的定数值与定数人；分带界与各带 π_g 表；每局 π_g；
每根 π_{r|g}；以及声明「分带仅用根数元数据，枚举期间未做任何比较器决策、未算
任何 ΔU」。

## §6 结算可辨性下限（附则 §4 的冻结落点）

- 定义沿附则 §4（L24–30）：对**结算可判定根**（H=1 且全部合法候选的一步结局可精确
  计算的根），准入集**必须包含一步结算 argmax 候选**（与 A0 的结算差最大者；并列时取
  先验序靠前者）；其余名额仍按先验序截断至 K≤4（含 A0）。非结算可判定根不适用
  本规则。
- 冻结落点：`settlement_decidable` 与 `settlement_argmax`（§2.1）**在枚举时算出并
  随根单冻结**。计算方法：以冻结原型叶的权威结算（cnet2_search.py 叶内结算，
  verify3 所用 `make_terminal_score_fn` 同源，F01／F04 口径）对该根全部合法候选逐一
  算一步结局；全部可精确算 → 可判，argmax 为结算差最大者。枚举脚本必须在冻结记录
  中写明所用结算函数的**文件＋行号**（执行时核对，见 §10.4）。
- 测试时规则：可判根的准入集缺 argmax 候选＝准入违规，该根记**无效**（附则 §3），
  不许静默重截断后继续。不可判根不受此限。

## §7 主估计量与证据记录

### 7.1 主尺：逐根逐臂 ΔU（修订版 §1.1，L7–18，逐字钉死）

对每个入样根、每个臂（A0 臂／改子臂），取该臂续弈（附则 §5 口径）到达**权威终局**时
的逐席终局分数：

- 时限终局（step 299）：双席终局分数＝终局现金（F04 口径）。
- 灭绝终局：**先按 F01 逐席得分**，公式写死（权威源 code/cnet2_search.py:666–673）：
  **灭绝席分数 ＝ step_count − episodeSteps − 1；存活席分数 ＝ 带入灭绝步的现金**。
  先逐席得分、再进入下式——不许整组取带入现金，不许直接拿灭绝时点现金或原始分差算 U。
- 记根席位为本席：**M_臂 ＝ 本席终局分数 − 对手终局分数**（该臂的分差，带符号）。
- **WDL_臂**：沿项目归一胜负口径（code/bigeval.py:38、code/stage0_teacher.py:29）：
  M_臂 > 0 → 1；M_臂 ＝ 0 → 0.5；M_臂 < 0 → 0。
- **U_臂 ＝ 0.5·WDL_臂 ＋ 0.5·sigmoid(M_臂/1000)**。
- **ΔU_根 ＝ U_改子臂 − U_A0臂**。主尺对 ΔU_根 做加权与聚合（§7.2），
  **不在聚合后做任何非线性补算**。
- H=0 的根：两臂执行同一 A0 动作、终局分数相同，ΔU ＝ 0 是定义下的必然结果
  （不再是「记 0」的约定，但数值口径与原附则一致，照旧入主尺）。
- **原始现金差（终局分差之差）降为副尺**：随主尺同报、不混入主尺，不许以副尺的
  正负支撑面向 U 的结论。

### 7.2 聚合（修订版 §2.3，L49–53）

- 局内：入样根 ΔU 以 1/π_{r|g} 加权（Hájek 形式）得局均值。
- 跨局：以 1/π_g 为局权重（Hájek 形式）估计局总体的**局等权平均 ΔU**；
  π_g ＝ 1 时退化为原附则的跨局等权。CI 仍按局级聚类口径。
- 主尺、副尺（H≥1 条件 ΔU、类一内分层、席位敏感性、原始分差差）分开报，沿原
  附则 §2 框架，仅估计量按 §7.1 与本节替换。

### 7.3 镜像根的计数（S1 裁决的落点）

- 同一步的双席两根（如 verify3 的 267 双席镜像对）是**两个根**，分别入样、分别算 ΔU；
  其相关性由**局内先聚合＋局级聚类 CI**吸收，不删其一。S1 裁决把 267 镜像对按
  「1 个独立正例步」计，是附件 n＝2 的个案表述，不作 S3 的删根规则（A4 判读节）。
- 跨局等权平均的单位是局，不是根；根数多的局不因根多而权重更大（除 π 设计权重外）。

### 7.4 证据记录要求（修订版 §1.3，L25–27）

续弈机械须逐根逐臂记录**双席终局分数对**（而非仅分差），并记录终局类型
（时限／灭绝）与灭绝时的 F01 结清值；ΔU 在分析层由分数对算出，可复算。
**只报分差的证据包不合规。**

### 7.5 分析代码自检（本协议新增，草案条，待策略组验收）

分析管线在触碰真实数据前，必须在修订版两则自检算例上逐位复现：

1. R2-11 合成反例（修订版 §1.4，L29–34）：A0 臂分差 [10, −1000]、改子臂分差
   [−10, −900] → 平均 ΔU 必须算出 **−0.24622272**（根 1 −0.50249998、根 2 +0.01005454）。
2. R2-12 合成反例（修订版 §2.5，L65–69）：局 A（100 根、ΔU 全 +0.01、全有效）
   与局 B（1 根、ΔU −0.20、验证失败记无效）→ 点估计 +0.01 且最坏界必须算出
   **[−0.495, +0.505]**，并触发「缺失敏感、不可裁定」。
   
   两则有一则不合，分析管线停用、先修代码。真实数据的 ΔU 与界由同一管线算出，
   自检记录随证据包入档。

## §8 无效与缺失（修订版 §2.4，L55–63，§3 整节改写）

- 无效定义沿原附则 §3（L18–22）：执行失败（异常／超时未达终局）、状态泄漏或快照
  恢复复现检不过、根在冻结后被证伪（如触发判据误报）、双臂任一未到权威终局——
  **记无效、绝不填 0** 不变。
- **删除原「单局无效 >50% 整局剔除」规则**——预先声明的删除不消除结果相关缺失的
  偏差，不再以任何形式整局删除。
- 逐局缺失报告（强制）：每入样局报有效根数／冻结根数／无效根数与原因码分布，
  随证据包入仓。
- 局内有 ≥1 有效根：该局以有效根局内加权均值入估计；局内无效占比 >50% 的局在报告中
  **点名标记**（标记、不是删除）。
- **零有效根的局**：不删除、不沉默。点估计照常以有数据局计算，但报告必须同时给出：
  ① 该类局的清单（局号＋无效原因）；② **最坏界分析**——对每个零有效根局分别赋
  ΔU ＝ −1 与 +1（ΔU 的理论值域，因 U∈[0,1]），代入跨局估计式得主尺的下界与上界，
  随点估计同报。
- **预注册失效规则**：若最坏界区间跨过裁定线（主尺符号判定即跨 0），本趟主尺结论
  降为敏感性级、记「缺失敏感、不可裁定」，不许只报点估计下裁定；若零有效根局占
  入样局 >10%，本趟对裁定目的作废（与根级阈值无关、独立触发）。
- **5%／15% 阈值定性更正**：原附则 §3 的根级无效占比阈值（>5% 降级、>15% 作废）保留，
  但明确定性为**运维控制**（执行质量的停查线），**不是推断有效性的充分条件**——
  低于阈值不自动意味着主尺无偏，缺失处置一律按本节执行。
