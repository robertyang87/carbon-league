## 0. 结论先行

**判定：条件可行，建议按已注册主线推进，前沿增量分轨排队。**

1. **主线（方案 A）可行性最高、且已注册**：少候选（K≤4）、可提前结束的浅层战术比较器，启发式叶对照＋同检查点完整 PPO critic 候选叶，S0→S4 逐闸验收。它直接针对历史上两次失败的真实死因（搜索从未真正评估过叶、叶量纲/身份从未对齐），且每一步都有先证闸与停止条件，最坏结果是「在 S0/S1/S3 以可承受成本拿到否定结论」，不是再烧一轮大场。
2. **最大的单点未知不是算法，是成本与身份**：完整 vnet 工件尚未取得；H=1 一轮完整 critic 比较能否塞进 1 秒单步线内的剩余预算，无任何实测。S0（工件存亡盘点＋身份核验＋分阶段成本表）是全线第一闸，其结果决定后面所有路线的取舍——在 S0 出表之前，任何深度分布、改子率、ΔU 的数字都是假设，本方案不给。
3. **业界前沿与 Codex 方案同向、且能补强三处**：Gumbel AlphaZero/MuZero 的「少模拟亦可改进」给 K≤4 提供了候选抽样与预算分配的成型机制（§4.1，列为 B 臂消融）；Student of Games / ReBeL 一系提醒本游戏是**不完全信息＋同时行动**，J 个对手情景本质是信念采样，长期须按信念一致性加权、且叶应逼近反事实价值（§4.2，列为 C 臂与研究轨）；DeepNash 证明无搜索路线在同类游戏可达顶级——搜索线必须保留「转投网络本体」的回退（§4.4，方案 F），不把全部筹码押在搜索上。
4. **明确不可行的部分先划掉**：在 1.5 核／512 MiB／单文件 ≤10 MB／单步 1 秒的部署盒子里做全量 GT-CFR、深层 PUCT 树、跨步树复用、外部推理运行时（ONNX/CUDA 等未经平台证明的依赖）——本方案一律列为不做或研究轨，不进部署路线。

## 1. 历史复盘：四次尝试、四类死因

搜索这条线不是没试过，是试过四种死法。可行性判断必须建立在死因上，否则会第五次死在同一处。

### 1.1 模板内置搜索：从未在生产形态开启

agent 模板本就内置 PUCT 式搜索（C_PUCT=1.5、MAX_BR=16、ROOT_S=12 等）与 sweep 比较两条分支，出厂默认 SEARCH=True；Echo 打包时主动关掉（Echo3/Echo4 的 CONF 均为 SEARCH=False / MODE=sweep / ROLL=self / GUARD=True）。即：**现役强度 = 纯网络策略＋规则守卫，临场零搜索**。任何「现有强度里已含搜索贡献」的说法都不成立。

### 1.2 K4 探针（2026-11-12 前后）：上报死链，结论作废重核

替身包开 SEARCH 后曾报 search_games=0，一度被读成「搜索没跑」。逐行核代码后定案：搜索一直在跑，是统计字典从未发布到 agent.last_stats，上报链是死的。教训已入册：**机制类结论必须有现象计数（如每局搜索步数、叶调用数）从独立通道读回，不认自报字段**。此教训直接变成新预注册 S1 的现象计数硬要求。

### 1.3 KataGo 价值叶嫁接（2026-11-14 关账）：三腿全负，死因四条

- 从未有任何一版搜索在「部署形态、叶身份对齐、量纲校准、预算够完成至少一轮比较」四条件同时满足下被测过。**搜索在本线的真实战绩是「未测」，不是「已败」。**

## 4. 业界前沿映射：五条线、各自补什么

选线标准：与本问题的结构同构（少预算／同时行动／不完全信息／学习型叶／部署盒子约束），且有公开可核的强结果。不凑数。

### 4.1 Gumbel AlphaZero / Gumbel MuZero（Danihelka et al., ICLR 2022）——少模拟的成型机制

- 核心：根部用 Gumbel-top-k **无放回抽样**选少数候选，再以 **Sequential Halving（逐半淘汰）** 在候选间分配模拟预算，最后用 completed-Q 形成改进策略；其策略改进保证在「并非所有根动作都被访问」时依然成立，且在极少模拟（量级 ~2 次/步）下即有强表现。
- 与本线同构点：我们的约束正是「叶太贵、每步只能完整比较极少数候选」。Codex 的「整轮完成才更新」是均匀加深；Sequential Halving 是它的**自适应版**——先全员 H=1，再把预算集中给幸存者加深。Gumbel 抽样则给「K≤4 怎么选」一个有依据的答案（按先验 logits＋噪声无放回采样），替代纯 top-k 的确定性截断。
- **采纳边界（重要）**：其改进保证假设动作值被正确评估；我们的叶是近似值、且是同时行动＋不完全信息博弈，教科书假设不全成立。因此 B 臂只借**机制**（抽样＋逐半分配），不借**保证**——收益仍以 S3/S4 实测 ΔU 为唯一判据。另注意 completed-Q 中未访问动作的补全方式在小 K 下影响有限，首版可不做。
- 落点：方案 B（§7），在 S1 通过后、S3 中以消融臂形态出现（与均匀加深同根同叶对照），不改主线合同。

### 4.2 Student of Games / GT-CFR＋CVPN（Schmid et al., Science Advances 2023）与 ReBeL 一系——不完全信息的「正统」搜索

- 核心：SoG 用 growing-tree CFR 在**信息集**上做 anytime 局部搜索，价值/策略网络（CVPN）预测的是**反事实价值**；作者证明其 soundness（算力与逼近容量增大时收敛到完美博弈），并在围棋、国际象棋、 heads-up 无限德州与 Scotland Yard 上取得强结果。ReBeL（Brown et al., NeurIPS 2020）则把搜索建立在**公共信念状态**上，是同一思想的另一形态。
- 对本线的三条硬提醒：
1. 本游戏的隐藏量（对手未知碳量等）使「单个真实状态上的价值」在原理上不存在——叶严格来说应是**给定公共历史与信念的期望价值**。我们现在的 J=1 对手情景＋冻结对手模型，是信念的单点采样近似；J=2 与信念加权是沿这个方向的第一步（方案 C）。
2. 搜索输入必须与信念隔离：回放 full_carbon 等真值只能用于离线评估，绝不能漏进候选生成或叶（现行合同已钉死，S1 设隔离用例）。
3. 全量 GT-CFR 在 1 秒/1.5 核下不可行，**只取其价值定义与信念纪律，不取其算法本体**（研究轨 §8 Phase 6，仅在主线已证正信号后评估一个「根部微型子博弈重解」的裁剪版）。
- 落点：方案 C 的理论依据＋全线信息隔离纪律。

### 4.3 同时行动 MCTS 文献——序列化伪影与解耦选择

- 同时行动博弈里，把联合行动序列化（先我后敌）会系统性造出偏守或偏攻的伪影，因为对手被假定能看见我方动作再响应；正统做法是双方动作**独立、同时**选取再联合推进（如 SM-MCTS 的 decoupled UCB：各方独立维护动作值、联合行动为独立选择的组合，避免联合 UCB 退化为可被利用的纯策略）。
- 对本线：Codex 合同「同一步对手动作来自共同的推进前信息、不得按己方候选偷看后再生成」正是此纪律。S1 须加一条可证伪的**窥视测试**：交换候选呈现顺序/屏蔽候选信息后，对手情景动作分布应不变；变了即实现漏了，机制关作废。
- 落点：§5.4 情景管理器合同＋S1 测试项。

### 4.4 DeepNash / R-NaD（Perolat et al., Science 2022）——无搜索回退路线的存在性证明

- DeepNash 以纯自博弈 model-free RL（R-NaD：正则化 Nash 动力学，迭代把正则策略更新为上一轮固定点，收敛向近似 Nash）**不用搜索**在 Stratego（不完全信息）达到人类专家级、Gravon 全时段前三；其收尾还有一条可借的小工程：用阈值化＋离散化投影消除长局里累积的低概率失误动作。
- 对本线的意义是**组合管理**：搜索不是唯一变强路径。若 S3 判负，正确动作不是加预算硬撑，而是把资源转回网络本体（PPO 续训的正则化/参考策略口径、终局段阈值化清理），搜索组应主动给出这个转投建议（方案 F）。反之，若搜索为正，其根级数据又能反哺训练（Phase 5 专家迭代）。
- 落点：方案 F（回退）＋Phase 5（正信号后的蒸馏闭环）。

### 4.5 KataGo 工程学＋MuZero/EfficientZero 的价值等价——叶与预算的工艺

- KataGo（Wu 2019）的可迁移工艺：**playout cap randomization**（多数步用小预算、少数步用满预算作策略目标）在训练期制造预算多样性；辅助稠密监督头（ownership/score）大幅提高样本效率；forced playouts＋policy target pruning 防止网络学搜索已否决的动作。对本线的用处在 Phase 5：若把搜索改进蒸馏回网络，训练须混入多档搜索预算，否则网络会过拟合单一预算、换个预算就退化。
- MuZero/EfficientZero 的**价值等价原则**：模型/叶只需对「做决策所需的量」准，不需要重构世界。EfficientZero 以自监督一致性、价值前缀端到端学习、离线价值修正三招在极少数据下达到高性能。对方案 D（小型叶）的直接指导：小叶的训练目标应是**在生产续弈策略下的后继排序与终局 U 校准**（真实 Monte Carlo 终局 U 为锚、critic 软标签为辅），而不是拟合 critic 本身的输出——只蒸馏 critic 的误差不会更准（Codex §7 同口径）。
- 落点：方案 D 的训练配方＋Phase 5 的预算随机化。

## 5. 目标架构（主线 A 的实现蓝图）

比较器作为 Echo4 派生包存在：actor 权重逐字不变，与 Echo4 的 CONF diff 逐项列明后才许开测。模块按「运行时／搜索／叶／测量」四线拆分（承 Codex §11），单推进者（搜索组）内部分工，不设第二个推进者。

### 5.1 入口计时与初始化迁移

- 公开 agent 入口第一行取 `perf_counter()` 为整次调用 t0；加载、观察、根网络、守卫、搜索、输出全计入。
- 静态权重解码、weight transforms、纯推理暖机迁入顶层初始化（20 秒预算内）；step=0 局状态初始化仍走正常路径。暖机不得伪造真实历史，结束清模拟/缓存状态。
- 内部截止 0.75–0.80 秒（待 S0 标定），外留通信/调度余量；**总预算不重复分配，快步不积攒额度**。

### 5.2 准入控制器（成本表驱动）

- 维护 C_hi 表：按 (K, J, H, 单位数区间, 叶后端, 冷/热) 记录完整一轮比较成本的高分位与最坏样本（S0 生成、S2 复核）。
- 每轮启动前算 R = 内部截止 − 已用 − 返回预留；仅当 C_hi < R 才启动该轮。NumPy 原生运算中途不可取消，因此准入必须保守、工作单元必须先切小——「算完再看超时」不提供任何保障。
- 基线动作 A0 先就绪且先计时：若 A0 本身已逼近时限，搜索准入直接为零，先修基线推理（停止条件已注册）。

### 5.3 候选生成（K≤4）

- A0（原 actor＋守卫最终动作）恒占一位。
- 其余候选从**一个**最值得干预的单位生成 2–3 个不同联合动作，经真实 Prefix 重解码（后续单位对前缀改变作出反应），不做「替换单动作复用原合法性/预算特征」的拼接。
- 准入三筛（在 key_units 风险筛选之上）：替代动作与 A0 实际不同；预期风险/收益值得一比；剩余预算够一轮完整比较。三筛不过 → H=0 返回 A0，并记触发未准入原因。
- 首版干预范围只限三类战术（见覆盖表）；长期种树与全图多单位协调不生成候选，留给网络。
- B 臂变体：候选抽样改 Gumbel-top-k 无放回（先验 logits＋Gumbel 噪声），与 top-k 确定性截断同根对照（§7）。

### 5.4 情景管理与轮次提交（anytime 合同）

- J=1 首版：对手模型冻结登记（＝Echo4 包现行对手预测口径；不得因我方 TEACHER=2 默认对手亦为 2）。同一根内所有候选共享同一组对手情景与随机种子；对手动作只由推进前共同信息生成（反窥视，§4.3）。
- 轮次语义：H 指真实环境联合推进次数（根推进 = H=1）。在相同 H、相同情景、相同叶定义下评完全部 K×J 候选 → 形成不可变完整结果 → 过预注册阈值/风险规则才替换 A0；预算允许才整体加深到 H=2、H=3 并以新完整结果替换旧结果；中断/失败回上一轮完整结果，首轮未完成回 A0。**不许部分情景、缺叶填零、浅候选占便宜。**
- 计数分开记账：K、J、H、神经状态编码次数各自成列，不再用一个含混的 SIMS 数代替（成本公式承 Codex §5：T_call = T_base + T_candidates(K) + T_opp(J) + T_sim_feat + ΣT_roll_batch(2KJ) + Σ_d T_leaf(KJ,d) + T_return + T_unfinished，其中 T_unfinished 是中断轮的已耗工作，必须入账）。
- 每候选独立模拟器/Feat/守卫快照，树编号、现金、历史、终局状态、规则参数完整复制；未知碳等隐藏量与策略可见输入隔离，真值只在离线评估侧。

### 5.5 叶接口（统一 U 尺度）

- 所有叶实现同一接口：输入后继状态（合法 belief 侧信息），输出 U 尺度标量＋成本计数；精确终局直接取权威规则 U，不再推进后评分。
- 叶 A（对照）：现行启发式叶。注意其在 H=1/2 是**新估计器**，不继承旧 MIN_DEPTH≥3 下的任何信任；若含 margin 量纲，转换器须冻结并单独验校准，不得与 U 混排。
- 叶 B（学习型候选）：同检查点完整 vnet 整件（骨干＋头），U 代理 = (tanh(Z_vnet)+1)/2（reward=2U−1、GAE 目标的对应映射）；只移线性头到 actor ctx 上**不等价**，禁止。身份以 S0 核验为准：对应 it=20 检查点、键完整、与 actor 同源 state，三项缺一即不上场。
- 叶 C（后备）：小型蒸馏叶（方案 D），仅在 B 成本判负时启动，按 §4.5 价值等价配方训练。
- 阈值纪律：替换 A0 的收益阈值须与叶量纲对应、由独立标定集决定；校准集／阈值选择集／收益验证集三者分开，argmax 用的估计不得再当自身验证标签。

### 5.6 守卫一致性与回退

- rollout 续弈若定义为生产策略续弈，必须执行相同守卫，不得静默换成无守卫裸网。
- 搜索选出的动作经守卫重写后，须重新验证「被评动作＝执行动作」；不一致或有安全后处理未重评 → 回 A0。
- 任何异常（模拟器错误、叶 NaN、成本表未命中 shape）一律回 A0 并记原因码，不许带病提交部分结果。

### 5.7 遥测（先于优化存在）

- 每调用记录：分阶段 wall（加载/根网络/候选解码/对手推断/模拟/叶/返回）、触发与准入漏斗（trigger/all、admit/trigger、complete/admit、changed/all、changed/complete）、H 分布（含 H=0）、编码计数、慢步标记、回退原因码。
- 遥测走独立通道读回（吸取 K4 上报死链教训）：统计发布点在 S1 首日即用构造例验活，不等跑完大场才发现字段是死的。

## 6. 可行性分维评估

评级口径：高＝已有证据或成型路径、剩余风险可控；中＝路径明确但关键未知须靠在册闸门回答；低＝未知占主导或依赖未证明条件。每维给出「未知是什么、由哪一闸回答」。

| 维度 | 评级 | 依据 | 关键未知 → 回答闸 |
|---|---|---|---|
| 机制可行性 | **高** | 比较器合同不依赖任何未发明算法；旧代码已有 fastsim/batch/trunk 复用/模拟器池；Codex 已逐行核过 sweep 分支与门的位置 | 整轮提交、Prefix 重解码、守卫隔离的正确性 → S1 构造正反例＋窥视测试 |
| 叶身份可行性 | **中** | 训练/导出合同已核（sep-value、NPZ 只导出 actor、vnet 存 trainer state）；工件位置明确（L20 主臂 it=20 state） | 工件是否还在、键是否完整、与 actor 是否同源 → S0 存亡盘点（作战室排期令第一步） |
| 叶质量可行性 | **中偏低** | 启发式叶浅层质量未测；critic 与 guard-on 行为/对手分布的匹配度未测；历史上叶从未被有效评估过（既是风险也是机会：没有负证据，只有无证据） | 排序质量（同候选同信息集同续弈的独立真实续弈）→ S3；S1 只答「能调用、有非退化输出」 |
| 计时/平台可行性 | **中** | 内部截止与准入制在工程上成立；但基线分阶段成本、K={2,4}×H={1,2,3} 可完成区间**零实测**；旧形态曾有 85–236 慢步/局的失败读数（口径含影子争用，不可直接外推、但足以警示） | 全部 → S0 成本表＋S2 部署形态逐局判读。**这是全案最硬的一维，S0 出表前不承诺任何深度分布** |
| 统计可行性 | **高** | 判据链已按 SOP 注册：S3 按局聚类、全根报、跨零关门；S4 主尺钉死、N 由 S3 散布联合功效锁、超可行量停回策略组 | S4 所需 N 是否在产能内 → S3 散布出后锁 N 时回答；不够就降主张或停，不硬跑 |
| 数据可行性 | **高** | 诊断种子块已留（986200–986499）；S3 根有现役对局来源；小叶（若触发）监督可用真实终局 U＋critic 软标签，语料在册 | 小叶训练量是否够 → 仅 D 臂触发时评估，不提前占资源 |
| 工程量可行性 | **中** | 主线是「新比较器＋叶接入＋遥测」，非新引擎；难点集中在 Prefix 重解码与状态隔离的正确性，这类 bug 隐蔽（见风险册 R6） | 工作量单价未校准——S0 完成前所有工期只给量级（§8），不给日期承诺 |
| 组织/排期可行性 | **高** | 单推进者已定（搜索组）、验收/排期/工件/考位四方接口已逐一落字；工程组交接干净（零在飞工作） | 排期时点归作战室（C1/C2 考位与 L20 工件请求在其令内）→ 等排期令 |
| 部署合规可行性 | **中** | 派生包须满足单文件 ≤10 MB：Echo4 本体已 4.6 MB，**再塞一个完整 vnet 骨干可能顶破上限**——这是叶 B 的隐藏约束，S0 须同时核「工件大小＋打包后总尺寸」；若顶破，叶 B 只能走小叶（D）或包外不可行即判负 | 打包尺寸 → S0 身份核验时一并量 |

**总评**：九维无一票否决项；两维（叶质量、计时）是真未知，但都各自有在册的、成本递增的闸门去回答，且每道闸都允许「拿到否定结论并停」——这正是与前四次尝试的区别。可行性成立的形式是**分阶段可证伪**，不是「大概率能成」。

## 11. 成本账（公式先行，数字待实测填）

- 整局机器成本：`机器小时 ≈ 对局数 × [每局联合步数 × (μ_A + μ_B) + 环境/启动开销] / 3600`，μ 为双方每次外部调用平均耗时、须求和不取平均；多机外推另注有效吞吐。生产 1.5 核时间与研究吞吐（DGX/Studio）分开报。
- 根级诊断另记：根数、来源局数、每根候选/续弈次数、双席、机器/配额、并行度。神经编码数只估工作量，不等于墙钟线性缩放。
- S4 预算在 N 锁定时按上式出账并经策略组确认后才开场；预算达不到所需 N → 降主张或停（已注册）。
