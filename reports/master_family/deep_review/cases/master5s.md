# Master5s：154份指定目录样本与机制案例

冻结：`37965ea578851b5f3ff88ffc42d7119ff716b5cc`。本稿是手选机制案例及指定目录样本的补充读数，不等于全仓联合检索后的最终总体；不同稿件的目录样本量不得相加。统一按比赛表 `order` 映射真实席位，差值取关注模型减对手。格号为原始15×15数组索引，`row=cell//15, col=cell%15`；这是行列视角，不按网页旋转方向重映射。
下列阶段均值与案例只覆盖该提交的 `data/master5s_corpus/`；按实体ID消失识别的候选事件包含友军合并和基地结算，不能直接当净损失。本文损益案例已另核前后状态。

## 1. 样本与读法

- 冻结仓内 `data/master5s_corpus/` 可读 **154** 份 gzip 回放；[data/master5s_matches.json](https://github.com/robertyang87/carbon-league/blob/37965ea578851b5f3ff88ffc42d7119ff716b5cc/data/master5s_matches.json) 有 **187** 条记录，因此这里只能称“该目录的全部可用回放”，不能称全仓联合样本或全部天梯对局。
- 154 份均按 `(match id, game)` 匹配元数据，再由 `order` 转换 Master5s 的真实席位，逐份核最终回放分数与元数据分数，无不一致。共 **45,851** 次环境转移，席位分布 0/1 = **69/85**。
- 观察性战绩 **148 胜、6 负**，平均分差 **+2,180.92**、中位数 **+1,818.87**。对手不均衡，版本和采样时点不同；这不是固定考官、双席配对、等权对手池的正式强度估计。153 局含 300 个状态；1 局在 state 104 结束（对 ClaudeFable5.2-BC-v2，2175.55 对 −197），不得补成 299 步。
- **步数约定**：下文“决策 t”使用 `steps[t]` 的状态与 `steps[t+1][seat].action`，该动作产生 state t+1。不能把 state t 中附带的上一手动作当作当前决策。
- **位置约定**：位置为 observation 的 0-based flat index，`row=pos//15, col=pos%15`；坐标是行/列，不是界面笛卡尔坐标。15×15 环面。
- 树所有权由 `players[seat][3]` 判定，不能看树 ID 的 `player-0/1` 前缀：夺树保留旧 ID。隐藏 `full_carbon` 仅是回放评估字段，以下不得据此推断 Master5s 的实际输入。

可复核的阶段形态：

1. **前 50 步投入扩张，优势还未现金化**：现金差几乎为零，state 50 已多约 2.31 棵树。0–49 步每份回放平均新种 4.43 棵、夺树 2.90 次；这不是单纯“疯狂种树”，其中相当部分来自所有权竞争。
2. **50–249 步形成持续经济差**：总体维持约 7.5–7.9 collector、1.9–2.2 planter。现金差从 +8.77 扩至 +1,796.15，不能把全部优势归于最后十步搜索。state 100 双方树数几乎相同而现金差已有 +605.88，也说明“活树数”不能代替收入、交付、税收和抢夺质量。
3. **250 后明显收缩种植编制、强化交付**：state 275 collector 升至 8.61，planter 降至 1.13，终局剩 0.51 planter；未交付载货由 528.39 降到 87.18。直接识别到的“存活 collector 回己方基地且载货归零”事件，250–298 步合计 2,972 次，对比 200–249 的 1,714 次。这只是确定性交付事件子集，不包括友军合并、碰撞后结算等，不能拿它做完整财务账。

## 3. 案例一：早期 planter 连夺两树，随后持续收款

回放：[data/master5s_corpus/00f7e221872bf7bc75a3847676e17b56-1.json.gz](https://github.com/robertyang87/carbon-league/blob/37965ea578851b5f3ff88ffc42d7119ff716b5cc/data/master5s_corpus/00f7e221872bf7bc75a3847676e17b56-1.json.gz)。Master5s 为席位 1，对哈基米 v3；终局 **8,889.90 : 6,231.27**，差 **+2,658.63**。

同一 `player-1-worker-5`（PLANTER）的真实前缀：

| 决策 t | 决策前位置 | 动作 | 后继 |
|---:|---:|---|---|
| 18 | 71 (4,11) | RIGHT | 72 |
| 19 | 72 (4,12) | RIGHT | 73 |
| 20 | 73 (4,13) | DOWN | 88 |
| 21 | 88 (5,13) | NONE / 无动作项 | `player-0-tree-1` 所有权由敌变我，树龄 7→8 |
| 22 | 88 | DOWN | 103 |
| 23 | 103 | DOWN | 118 |
| 24 | 118 (7,13) | NONE / 无动作项 | `player-0-tree-0` 所有权由敌变我，树龄 14→15 |

两次夺树均付规则 `seizeCost=20`。第一棵在 state 22–64 连续归 Master5s，实际累计吸收 **84.426375**；第二棵在 state 25–60 连续归 Master5s，实际累计吸收 **34.309575**。扣各自 20 的夺取费，直接收入减夺取费分别 **+64.43/+14.31**，还没有扣招募、旅行及机会成本，也没有算对方被剥夺收入的反事实。

**可学的约束**：行动目标需要树龄/剩余寿命、当前位置到目标路径、支付能力与控制保持时间；“站住”对 planter 是夺取/种植操作，不能统一当作无效等待。**不能泛化为“见树就抢”**：第二棵的毛收入很低，树龄、路线和未来被抢回都会改变是否值得。

## 4. 案例二：终局前补采三次，再按真实路径交付 611.32

回放：[data/master5s_corpus/afb1c0a51bddc547bbd00df00564aed1-1.json.gz](https://github.com/robertyang87/carbon-league/blob/37965ea578851b5f3ff88ffc42d7119ff716b5cc/data/master5s_corpus/afb1c0a51bddc547bbd00df00564aed1-1.json.gz)。Master5s 席位 1，对哈基米基准；终局 **8,216.98 : 6,736.94**，差 **+1,480.04**。

`player-1-worker-52`（COLLECTOR）在 state 275 位于 58，载货 545.62215；沿 LEFT、LEFT、UP 到 state 278 的 **41 (2,11)**，随后：

- 决策 278、279、280 连续 NONE，载货 **545.62215 → 575.62215 → 596.62215 → 611.32215**。
- 决策 281 DOWN：41→56；282 DOWN：56→71；283 LEFT：71→己方基地 **70 (4,10)**。
- state 284 collector 存活且载货归零，确定交付 **611.32215**。同次团队现金 **6,679.60→7,296.72**，增 **617.12**；多出的约 5.80 是其他同一步现金流，不能全归这名 worker。

**可学的约束**：剩余步数、可回基地的实际路径、载货、局部安全及补采的边际收益需要联合表示。它不是“250 后一律直接返航”：这里 278–280 仍补采，283 才交付，而且交付后又出门。此行为是成功样本，未做替代路径试验，不能声称那三次补采一定优于提前交付。

## 5. 案例三：低载抢高载成功，但抢来的碳没有变成己方分数

回放：[data/master5s_corpus/2da59e846e326c701cabcd15fa6439bd-1.json.gz](https://github.com/robertyang87/carbon-league/blob/37965ea578851b5f3ff88ffc42d7119ff716b5cc/data/master5s_corpus/2da59e846e326c701cabcd15fa6439bd-1.json.gz)。Master5s 席位 1，对 ClaudeFable5.2-BC-v2；终局 **9,514.43 : 5,750.89**，差 **+3,763.54**。

- 决策 **296**，己方 `player-1-worker-74` 在 **176 (11,11)**，载货 **28.9542**，动作 **UP→161 (10,11)**。
- 敌 `player-0-worker-49` 在 **162 (10,12)**，载货 **346.3776**，动作 **LEFT→161**。
- 同步推进后敌 worker 消失，己方存活，state 297 载货恰为 **375.3318 = 28.9542 + 346.3776**。
- 决策 297 己方 RIGHT→162，决策 298 NONE；state 299 仍在 162，载货仍 **375.3318**，**没有交到己方基地**。

**确定事实**是截获及阻断对手这名 collector；**不是己方银行 +346.38**。对手若不被截能否交付，需要独立反事实续弈，不能从当前位置和终局总差直接宣布“该手贡献 692.76”。

**可学的约束**：目标应区分己方交付收益、敌方交付阻断、未变现载货；仅将“赢碰撞/抢到多少”作为奖励，会高估末局远离己方基地的战利品。动作生成须按双方同时行动，不能让敌方候选偷看己方选项再响应。

## 6. 案例四：Master5s 自身也会丢大载货，而且这次对手真的交付了

回放：[data/master5s_corpus/ad630693c26ae17b724092518d883ae1-1.json.gz](https://github.com/robertyang87/carbon-league/blob/37965ea578851b5f3ff88ffc42d7119ff716b5cc/data/master5s_corpus/ad630693c26ae17b724092518d883ae1-1.json.gz)。Master5s 席位 1，对 RyanX-AIPowercore-M9XJ-630；终局 **6,716.02 : 7,326.38**，差 **−610.36**。

- state 104，己方 `player-1-worker-9` 在 204，载货 604.7958；UP、UP 到 174，决策 106 NONE 后载货 **624.5511**；随后 LEFT→173、UP→158、UP→143。
- 决策 **110**，己方从 **143 (9,8)** 载 **624.5511**，**LEFT→142 (9,7)**。
- 对手 `player-0-worker-24` 从 **157 (10,7)** 载 **44.0268**，**UP→142**。
- state 111 己方 collector 消失，对手存活且载货 **668.5779**，恰等于两者之和。
- 对手随后 RIGHT→143→144→145，再 DOWN→己方基地 160，于 **state 115 载货归零**。这次 668.5779 真实交付，包含抢得的 624.5511。

这是一个明确的高载风险错误/失配样本，不是只挑成功录像。**不能**从 −610.36 的终局分差推出“避开这次碰撞一定反胜”，因为换动作会改变后续全部轨迹。但足以证明 Master5s 不是低载碰撞无漏洞的神谕，蒸馏其硬动作必须保留坏样本与结果监督；更重要的是长回程的高载安全，不能只学最后 20 步。

## 7. 额外防误读案例：在敌基地击杀，抢到的货会立刻付给敌基地

回放：[data/master5s_corpus/3199ea6fa6700a1cd596c1ffd96b34ec-1.json.gz](https://github.com/robertyang87/carbon-league/blob/37965ea578851b5f3ff88ffc42d7119ff716b5cc/data/master5s_corpus/3199ea6fa6700a1cd596c1ffd96b34ec-1.json.gz)。Master5s 席位 1，对 ClaudeFable5.2-v8；终局差 **+2,120.93**。

决策 **288**：己方 `player-1-worker-80`，65 (4,5)、载 0，LEFT→**敌基地 64 (4,4)**；敌 `player-0-worker-51`，63 (4,3)、载 **383.2686**，RIGHT→64。碰撞后敌死、己方活，但己方 state 289 载货已归零。规则顺序是先碰撞、再基地结算，**敌基地所有者收到 383.2686**，并非己方得到这笔银行收益。对手团队现金同次 5075.73→5418.39（净 +342.66，其他支出收入并存）。

因此“高载敌人被杀且己方生存”这个事件筛选仍不足以确认抢夺收益；本分析刻意没有把此手列入纯正向案例。训练奖励、辅助头或搜索启发式必须显式区分基地归属与结算顺序。

规则对应冻结 [code/fastsim.py](https://github.com/robertyang87/carbon-league/blob/37965ea578851b5f3ff88ffc42d7119ff716b5cc/code/fastsim.py)：碰撞/低载唯一胜者 L593 起，基地结算（包含敌基地）L633 起，夺树 L683 起，树吸收 L714 起。这里的实例结论同时有真实回放前后状态支撑，不只依赖模拟器注释。

## 8. 对当前学生/搜索设计能支持什么，不能支持什么

**可以直接落到表示和样本设计的要求**：

- 阶段感知不能只是最后几步阈值：前期扩张、50–250 步重复经济循环、末期兑现均有量化证据。监督分桶至少保留开局、中局、终局以及 worker 类型。
- 保留每实体载货、到双方基地的距离/安全路径、基地归属、碰撞相对载货、树龄/归属、剩余步数和 shared cash；Prefix 改动作后必须重算后续实体合法性/预算。
- 策略监督与价值/结果监督分离：观察到的成功动作可供模仿，但不可把整局赢家每步都当“优解”；高载惨败与“抢到却没交”的样本适合作为价值与辅助标签的负例。
- 辅助头若要做，优先考虑“能否兑现、兑现时限/风险、己敌载货结算归属、树剩余收益”这类可由合法视角加真实结果定义的量。不要把所有即时转移都当最终 U，也不要用完整隐藏图喂推理输入。
- 局部搜索优先测可结算、可解释的临界动作：临近基地交付/阻断、高载逃逸、末局兑现。案例支持这些是有经济量级的决策，**不证明现有搜索能稳定改善它们**；仍须冻结信息集、同续弈、配对终局收益闸。

**这批公开回放不回答**：Master5s 使用多大网络、何种 critic、是否/如何搜索、训练数据与损失、哪个模块因果地产生优势。也不证明换 Transformer 或增大网络能复制它。96.1% 的样本胜率与选择出的五个例子都不能替代正式消融。当前最可迁移的是决策结构和错误约束，而不是假想的私有实现。
